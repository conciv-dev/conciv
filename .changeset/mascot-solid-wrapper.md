Add the Solid wrapper as `@conciv/mascot/solid`: `<Mascot>` renders the whole robot on its own — head, antenna and eyes layers on a 44px default stage plus the binary effect — and `<Mascot.Head>`, `<Mascot.Eyes>`, `<Mascot.Antenna>` and `<Mascot.Binary>` replace the default they name, restoring it when they unmount. Parts register through context, so fragments, `<Show>` and any child order work. The default stage size applies only when the consumer sizes nothing, so a consumer `class` or `style` still wins. Consumer `style` merges over the core one except for the geometry the rig depends on (`position`, `inset` and the `background` shorthand parts), which a layer keeps. Root props (`state`, `working`, `follow`, `activity`, `curve`) drive the framework-free core service; `<Mascot.Eyes follow={false}>` and `<Mascot.Antenna follow={false}>` opt one gaze channel out, and `<Mascot.Binary curve="arc">` overrides the curve for that emitter alone. `initialSkin` is read once, when the service is created; swapping skins after mount is not supported yet and the name says so.

`solid-js` is an optional peer dependency and `./solid` is the only entry that reaches it, so the core and effect subpaths stay framework-free. The subpath ships both the compiled DOM build (`import`) and the JSX-preserved source (`solid` condition) the way `@ark-ui/solid` does, and every element renders through `Dynamic`, so the entry also imports and server-renders under plain node.

The core gains the pieces the wrappers need: layers carry their own stacking depth (head, antenna, eyes, effect host) so a replaced part is never painted over by a default; each part's props carry a `release(element)` that clears the slot only if that element is still the bound one; a slot holds its candidate elements, so during a keyed swap or a double claim the survivor takes over instead of leaving the rig dead; and re-mounting an effect on the same id (a curve change) drains the flying particles the way any other stop does instead of dropping them. A part swap still tears the rig down and sets it up again on the new element — one frame of re-registration, by design, not a leak.
