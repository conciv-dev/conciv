# conciv.dev landing redesign — design spec (v5, Zed-measured rebuild)

Date: 2026-08-16 (v5, third pass). Owner: Omri. Status: approved direction ("terminal-first / Zed-structured", palette "dark product windows on paper"). v2 folds in the 36 findings of the Codex spec review (`gpt-5.6-sol`, read-only, this worktree). v3 dropped the `Reveal` whileInView primitive (SSR bakes `opacity:0` into the HTML, invisible until JS/IntersectionObserver runs — bad for crawlers, no-JS, LCP; static page instead). v4 requires every UI element to come from a component registry (21st.dev, smoothui.dev, kokonutui.com, shadcn) adapted to `--od-*` tokens, hand-written code reserved for page layout containers and copy. v5 (2026-08-16) rebuilds the page on Zed's measured grid (1120px ruled column, 112px gutter columns, node markers, six type sizes, 8px spacing) after the owner's first-paint review, fixes the four P0 defects (empty product frame on SSR, two gutters, hero too tall, action row off-axis), lifts the component-level motion ban (registry components keep their own motion; page-level backgrounds/entrance reveals stay banned, with one owner-approved exception: a hero-only backdrop shader slot), and replaces the v4 adopted/rejected list with a per-element provenance table — see Components. The third v5 pass (2026-08-16, after two Codex reviews) re-cut the copy, removed the Card wrappers from the figure and principle cells, made the poster wait for the demo's own `onReady`, added the accent-ink contrast tokens, and rewrote the provenance table against the files as they now stand. Rows below describe the code in the worktree, not the intent.

## Goal

Replace the current landing page (`apps/site/src/components/landing/*`) with a page that reads like a serious developer-tool site (reference: zed.dev structure, Bun/Warp confidence), not a template. Product screenshots and the live demo carry the page; type and rules carry the hierarchy. Primary conversion: copy the install command and follow Quick start. Audience: frontend developers already using Claude Code / Codex.

Non-goals: docs pages, widget changes, new product features, dark-mode redesign of the widget. The site keeps its stack (React 19, TanStack Start, Tailwind v4, shadcn radix-nova, Cloudflare Workers).

## Truth rules for copy (every claim must hold today)

- Claude Code is the default harness; Codex is supported. Say "Connect Claude Code or Codex", never "mounts Claude Code or Codex".
- Bundlers: say only what `apps/site/src/components/landing/framework-snippets.ts` has real code for. Rollup/esbuild are `soon` there; iOS is alpha. Do not list six bundlers as shipped. Use "one integration", not "one plugin line", except for the Vite-specific screenshot caption.
- Privacy: "Your code and prompts never pass through conciv servers. The local engine binds to localhost." Never "prompts never leave localhost" (the agent provider receives them) and never "0 servers" (a local Hono engine runs).
- Keys: "No conciv account or API key — bring your own authenticated Claude Code or Codex CLI." Never "no keys to paste".
- Tests: "Run Vitest or Playwright locally; results render as cards in the thread." Not "Vitest runs in-app".
- Diffs: "Source edits render as readable diff cards in the thread." No "before it lands" (there is no staging workflow).
- Banned words: supercharge, seamlessly, 10x, revolutionize, unlock, effortless, "it just works". Sentence case titles, no exclamation marks. Product is Beta — keep the word somewhere near the top.

## Visual system

- Palette unchanged: `--od-paper` / `--od-ink` / `--od-muted` / `--od-line` / `--od-accent` (red) with the existing dark-mode values. Red is reserved for: eyebrow labels, the spark mark, one primary button, link hover, step numerals, and the existing focus/selection/status affordances (`primary`, `ring`, caret) that already map to it in `app.css`. No new red surfaces.
- Product imagery is always a dark window. On the light page it sits directly on paper; in dark mode every screenshot gets a 1px `--od-line` keyline plus a 4px matte in `--od-panel` so the window still reads as an object. Never recolor screenshots; never place a light-widget capture.
- Type:
  - Display (h1, h2, h3): serif — `@fontsource-variable/newsreader`. Six-size scale (DESIGN.md): h1 italic 400 `clamp(34px, 3.4vw, 48px)`/1.2 tracking -0.02em; h2 upright 26/32; h3 upright 17/24; body 16/24; ui 14/20 (nav links, buttons, tabs); caption/mono/eyebrow 13/20. Registry components keep their own shipped sizes where they differ (shadcn Badge `text-xs`).
  - Body/UI: `Geist Variable` (installed).
  - Mono: `@fontsource-variable/jetbrains-mono` self-hosted; remove the Google Fonts `@import` in `app.css`, the Bricolage `@import`, `public/fonts/BricolageGrotesque-*.ttf`, and `public/fonts/LICENSE-Bricolage-Grotesque.txt`.
- Grid (v5, `apps/site/DESIGN.md` Layout): `.od-page` = 1120px column + 112px gutter columns (1344px, x=48..1392 at 1440) with 1px `--od-line` rules on both page edges and both column edges (`.od-col`), running from the nav through the footer; text sits 48px inside the column (`.od-inset`), product frame and figure grids run flush to the column rules. Sections are separated by viewport-wide 1px rules (`.od-ruled`) carrying 7px rotated-square node markers at every intersection with a vertical rule. Grids inside sections use cell rules (`divide-x/y`), never empty gaps. Spacing on the 8px scale only. Section eyebrows are mono, uppercase, `tracking-[0.16em]`, 13px, red — but sections do NOT share one heading anatomy (see structure): capabilities is image-led, how-it-works is a numbered technical document, open source is a compact ledger. No generic `section.tsx` wrapper.
- Radius: 10px for code/terminal panels and buttons' registry defaults; the product frame and capability figures are square-cornered and flush to the ruled grid (Zed). No shadow anywhere on the page; figures are border-and-caption objects (1px `--od-line`).
- Motion (v5): page-level bans only — no gradient/glow page backgrounds, no ambient shaders, no scroll-driven entrance reveals that leave SSR content invisible (`whileInView`/`initial={{opacity:0}}` on page sections is out; smoothui's block entrances are stripped when a block is adopted). Component motion shipped by an adopted registry component is kept as designed (copy-button icon swap, star-count spring, sheet slide); the theme switch lost its spin and gradient after the second Codex review. The demo keeps its gsap ghost cursor. Durations and curves are tokenised: `--od-ease-out cubic-bezier(0.23, 1, 0.32, 1)` for everything on the page, `--od-ease-in-out cubic-bezier(0.77, 0, 0.175, 1)` for the one looping pulse; 160ms hover and colour, 200ms tab indicator, 250ms magic-move, 500ms poster crossfade, star 280ms in and 150ms out. Hero-only exception approved by the owner: `HeroBackdrop`, a WebGL julia isoline field behind the hero copy, absolutely positioned inside the hero band, clipped to it, `pointer-events:none`, `aria-hidden`, nothing on SSR, rendered through `--od-accent` at `--od-hero-line-alpha` (0.10 light, 0.16 dark) with multiply blend (screen in dark), a quiet ellipse behind the headline, static single frame under reduced motion, hidden below 768px. See DESIGN.md "Hallmark exceptions" for the measured footprint and the runtime budget.
- Delete after `fallow dead-code --trace` confirms landing-only: `ClickSpark`, `SplitText`, `VariableProximity`, `Magnet`, `AnimatedContent`, `LogoLoop`, `smooth-scroll.tsx` + `lenis` dep, `robot-fab.tsx` (if unused), `features-section.tsx`, `install-chip.tsx`, `bundler-band.tsx`, and any `ui/*-icon.tsx` animated icons only they used.
- No gradients, no glass, no glow, no icon grid, no bento, no marquee, no typewriter, no bundler logo row.

## Page structure (top → bottom)

### 0. Nav (`site-nav.tsx` on `ui/site-header.tsx`)

Inside the same ruled column as everything else (`.od-col`), 56px tall, viewport-wide rule below with node markers. The nav uses a 12px inset (`px-3`), not the 48px section inset: measured against Zed, that puts the brand at x=174 and the right edge of the nav content at x=1266 on a 1440 viewport, which is the inset that matches their nav optically. Brand link (`BrandMark`: spark + "conciv" in Geist 16/700) left, then "How it works" / "Docs" 24px to its right (14px, 32px tall, 12px padding, Zed's nav link box); right: GitHub outline button with the star count, theme switch, and a Sheet menu button under `md`. Under `sm` the GitHub button moves into the sheet. The docs link is a TanStack `Link` with `activeProps`/`inactiveProps`/`activeOptions`, so the router supplies both `aria-current` and the active colour.

### 1. Hero = two siblings

**HeroCopy** (`hero.tsx`): `.od-ruled` band; `HeroBackdrop` slot absolutely behind the copy; centred column with symmetric 88px padding top and bottom (`py-16 md:py-22`), which puts the band at 500px tall against Zed's 502px; h1 max 720px, sub 60ch (`.od-lede`, balanced).

- Eyebrow (mono, red, two items): `Beta · Open source`
- H1 (serif italic): **"Your coding agent, inside the app it's building."** — one exported constant `HERO_HEADLINE` so the swap to "Claude Code, in the page." is one line.
- Sub (16/24 muted, 60ch, balanced, 17 words): "Claude Code or Codex, inside your running app: it sees the page, edits live, writes to source."
- Action row (v5, one group centred on the page axis, 8px gaps): `InstallCommand` composes `ui/package-installer-tabs.tsx` (21st Script Copy Button 1095 layout: package tabs `npm | pnpm | bun | yarn` with icons on `ui/animated-tabs.tsx` above; command box `$ npm i -D @conciv/it` 36px tall + copy button outside it) and takes the "Try it live" button (shadcn Button outline, lg) as an `action` slot on the command row. The command text is `@shikijs/magic-move`'s `ShikiMagicMovePrecompiled` over precompiled steps, so switching package manager morphs the shared characters in 250ms with no stagger. The choice lives in `lib/package-installer-store.ts` (`useSyncExternalStore`, server snapshot `npm`, `localStorage` key `conciv.pm`) so the hero and step 01 share it and hydrate without mismatch. Copy: `ui/copy-button.tsx` (smoothui button-copy) — `await navigator.clipboard.writeText`, failure state "Copy failed — select the text", `aria-live="polite"` "Copied", icon swap animation, focus stays on the button. Under `md` the tabs and "Try it live" are hidden; the command box + copy button stay.
  **ProductFrame** (`product-frame.tsx`, v5): its own `.od-ruled` band, flush to the column rules (1120 wide, square corners, no shadow — Zed), frame top at y≈543 of a 900px viewport. `ui/browser-frame.tsx` (21st Safari 4117 chrome: neutral dots, centred `localhost:3000` field) in the `dark` token scope. Inside: an `aspect-[8/5]` box that ALWAYS paints `hero-demo.webp` (2240×1400 capture of the demo body, `fetchpriority=high`) on the server and on mobile; on desktop, after hydration, the lazy `Demo` mounts on top of the poster inside a `ClientOnly`/`Suspense` wrapper. The wrapper starts at `opacity-0` and only crosses to `opacity-100` when the demo itself calls the `onReady` prop (a rAF after its root is attached), at which point the poster takes `aria-hidden`. The fade is a 500ms opacity transition on `--od-ease-out` with `motion-reduce:transition-none`. The poster stays underneath, so there is never a blank frame and no layout shift; if the chunk never arrives, or the demo never reports ready, the poster stays. Mobile (`useIsMobile === true`) never requests the demo chunk or model worker. The mono caption `Live demo on a small in-browser model. "Try it live" connects your own agent.` is the frame's bottom status bar.
