# conciv.dev landing redesign — design spec (v5, Zed-measured rebuild)

Date: 2026-08-16. Owner: Omri. Status: approved direction ("terminal-first / Zed-structured", palette "dark product windows on paper"). v2 folds in the 36 findings of the Codex spec review (`gpt-5.6-sol`, read-only, this worktree). v3 dropped the `Reveal` whileInView primitive (SSR bakes `opacity:0` into the HTML, invisible until JS/IntersectionObserver runs — bad for crawlers, no-JS, LCP; static page instead). v4 requires every UI element to come from a component registry (21st.dev, smoothui.dev, kokonutui.com, shadcn) adapted to `--od-*` tokens, hand-written code reserved for page layout containers and copy. v5 (2026-08-16) rebuilds the page on Zed's measured grid (1120px ruled column, 112px gutter columns, node markers, six type sizes, 8px spacing) after the owner's first-paint review, fixes the four P0 defects (empty product frame on SSR, two gutters, hero too tall, action row off-axis), lifts the component-level motion ban (registry components keep their own motion; page-level backgrounds/entrance reveals stay banned, with one owner-approved exception: a hero-only backdrop shader slot), and replaces the v4 adopted/rejected list with a per-element provenance table — see Components.

## Goal

Replace the current landing page (`apps/site/src/components/landing/*`) with a page that reads like a serious developer-tool site (reference: zed.dev structure, Bun/Warp confidence), not a template. Product screenshots and the live demo carry the page; type and rules carry the hierarchy. Primary conversion: copy the install command and follow Quick start. Audience: frontend developers already using Claude Code / Codex.

Non-goals: docs pages, widget changes, new product features, dark-mode redesign of the widget. The site keeps its stack (React 19, TanStack Start, Tailwind v4, shadcn radix-nova, Cloudflare Workers).

## Truth rules for copy (every claim must hold today)

- Claude Code is the default harness; Codex is supported. Say "Connect Claude Code or Codex", never "mounts Claude Code or Codex".
- Bundlers: say only what `apps/site/src/components/landing/framework-snippets.ts` has real code for. Rollup/esbuild are `soon` there; iOS is alpha. Do not list six bundlers as shipped. Use "one integration", not "one plugin line", except for the Vite-specific screenshot caption.
- Privacy: "Your code and prompts never pass through conciv servers. The local engine binds to localhost." Never "prompts never leave localhost" (the agent provider receives them) and never "0 servers" (a local Hono engine runs).
- Keys: "No conciv account or API key — bring your own authenticated Claude Code or Codex CLI." Never "no keys to paste".
- Tests: "Run Vitest or Playwright locally; results render as cards in the thread." Not "Vitest runs in-app".
- Diffs: "Source edits render as readable diff cards in the thread." No "before it lands" (there is no staging workflow).
- Banned words: supercharge, seamlessly, 10x, revolutionize, unlock, effortless, "it just works". Sentence case titles, no exclamation marks. Product is Beta — keep the word somewhere near the top.

## Visual system

- Palette unchanged: `--od-paper` / `--od-ink` / `--od-muted` / `--od-line` / `--od-accent` (red) with the existing dark-mode values. Red is reserved for: eyebrow labels, the spark mark, one primary button, link hover, step numerals, and the existing focus/selection/status affordances (`primary`, `ring`, caret) that already map to it in `app.css`. No new red surfaces.
- Product imagery is always a dark window. On the light page it sits directly on paper; in dark mode every screenshot gets a 1px `--od-line` keyline plus a 4px matte in `--od-panel` so the window still reads as an object. Never recolor screenshots; never place a light-widget capture.
- Type:
  - Display (h1, h2, h3): serif — `@fontsource-variable/newsreader`. Six-size scale (DESIGN.md): h1 italic 400 `clamp(34px, 3.4vw, 48px)`/1.2 tracking -0.02em; h2 upright 26/32; h3 upright 17/24; body 16/24; ui 14/20 (nav links, buttons, tabs); caption/mono/eyebrow 13/20. Registry components keep their own shipped sizes where they differ (shadcn Badge `text-xs`).
  - Body/UI: `Geist Variable` (installed).
  - Mono: `@fontsource-variable/jetbrains-mono` self-hosted; remove the Google Fonts `@import` in `app.css`, the Bricolage `@import`, `public/fonts/BricolageGrotesque-*.ttf`, and `public/fonts/LICENSE-Bricolage-Grotesque.txt`.
- Grid (v5, `apps/site/DESIGN.md` Layout): `.od-page` = 1120px column + 112px gutter columns (1344px, x=48..1392 at 1440) with 1px `--od-line` rules on both page edges and both column edges (`.od-col`), running from the nav through the footer; text sits 48px inside the column (`.od-inset`), product frame and figure grids run flush to the column rules. Sections are separated by viewport-wide 1px rules (`.od-ruled`) carrying 7px rotated-square node markers at every intersection with a vertical rule. Grids inside sections use cell rules (`divide-x/y`), never empty gaps. Spacing on the 8px scale only. Section eyebrows are mono, uppercase, `tracking-[0.16em]`, 13px, red — but sections do NOT share one heading anatomy (see structure): capabilities is image-led, how-it-works is a numbered technical document, open source is a compact ledger. No generic `section.tsx` wrapper.
- Radius: 10px for code/terminal panels and buttons' registry defaults; the product frame and capability figures are square-cornered and flush to the ruled grid (Zed). No shadow anywhere on the page; figures are border-and-caption objects (1px `--od-line`).
- Motion (v5): page-level bans only — no gradient/glow page backgrounds, no ambient shaders, no scroll-driven entrance reveals that leave SSR content invisible (`whileInView`/`initial={{opacity:0}}` on page sections is out; smoothui's block entrances are stripped when a block is adopted). Component motion shipped by an adopted registry component is kept as designed (copy-button icon swap, star-count spring, tab indicator spring, theme-switch icon rotation, sheet slide). The demo keeps its gsap ghost cursor. Hero-only exception approved by the owner: `HeroBackdrop` — a slot behind the hero copy for a Radiant shader (owner picks the shader; slot ships paper-only until then): absolutely positioned inside the hero band, clipped to it, `pointer-events:none`, `aria-hidden`, SSR = plain paper, client mount fades in over 600ms via `[data-ready]`, renders through `--od-accent` at 0.4 opacity with multiply blend (screen in dark), reduced-motion = static frame or nothing, hidden below 768px.
- Delete after `fallow dead-code --trace` confirms landing-only: `ClickSpark`, `SplitText`, `VariableProximity`, `Magnet`, `AnimatedContent`, `LogoLoop`, `smooth-scroll.tsx` + `lenis` dep, `robot-fab.tsx` (if unused), `features-section.tsx`, `install-chip.tsx`, `bundler-band.tsx`, and any `ui/*-icon.tsx` animated icons only they used.
- No gradients, no glass, no glow, no icon grid, no bento, no marquee, no typewriter, no bundler logo row.

## Page structure (top → bottom)

### 0. Nav (`site-nav.tsx` on `ui/site-header.tsx`)

Inside the same ruled column as everything else (`.od-col` + `.od-inset`), 56px, viewport-wide rule below with node markers. Brand link (spark + wordmark, serif 17) left, then "How it works" / "Docs" (14px, 32px tall, 10px padding — Zed's nav link box); right: GitHub outline button with the spring-animated star count, theme switch, and a Sheet menu button under `md`. Under `sm` the GitHub button moves into the sheet.

### 1. Hero = two siblings

**HeroCopy** (`hero.tsx`): `.od-ruled` band; `HeroBackdrop` slot absolutely behind the copy; centered column, 96px above the eyebrow on desktop (64px mobile), 48px below the action row; h1 max 720px, sub max 512px (16/24 muted).

- Eyebrow (mono, red): `Beta · Open source · MIT · dev-only`
- H1 (serif italic): **"Your coding agent, inside the app it's building."** — one exported constant `HERO_HEADLINE` so the swap to "Claude Code, in the page." is one line.
- Sub (18px muted, max 52ch): "conciv connects Claude Code or Codex to your running dev app. It sees the real DOM, edits the page live, writes the change to source, and runs your tests — without you leaving the page."
- Action row (v5, one group centred on the page axis, 8px gaps): `InstallCommand` composes `ui/package-installer-tabs.tsx` (21st Script Copy Button 1095 layout: package tabs `npm | pnpm | bun | yarn` with icons on a shadcn line-variant Tabs above; command box `$ npm i -D @conciv/it` 36px tall + copy button outside it) and takes the "Try it live" button (shadcn Button outline, 36px) as an `action` slot on the command row. The choice lives in `lib/package-installer-store.ts` (`useSyncExternalStore`, server snapshot `npm`, `localStorage` key `conciv.pm`) so the hero and step 01 share it and hydrate without mismatch. Copy: `ui/copy-button.tsx` (smoothui button-copy) — `await navigator.clipboard.writeText`, failure state "Copy failed — select the text", `aria-live="polite"` "Copied", icon swap animation, focus stays on the button. Under `md` the tabs and "Try it live" are hidden; the command box + copy button stay.
  **ProductFrame** (`product-frame.tsx`, v5): its own `.od-ruled` band, flush to the column rules (1120 wide, square corners, no shadow — Zed), frame top at y≈543 of a 900px viewport. `ui/browser-frame.tsx` (21st Safari 4117 chrome: neutral dots, centred `localhost:3000` field) in the `dark` token scope. Inside: an `aspect-[8/5]` box that ALWAYS paints `hero-demo.webp` (2240×1400 capture of the demo body, `fetchpriority=high`) on the server and on mobile; on desktop, after hydration, the lazy `Demo` mounts on top of the poster inside a `ClientOnly`/`Suspense` wrapper whose ref callback flips `demoMounted` (poster becomes `aria-hidden`), and the wrapper fades in over 500ms (`tw-animate-css`) — the poster stays underneath, so there is never a blank frame and no layout shift; if the chunk never arrives the poster stays. Mobile (`useIsMobile === true`) never requests the demo chunk or model worker. The mono caption `The live demo runs a small local model in your browser. Connect your own agent with "Try it live".` is the frame's bottom status bar.

### 2. Principles strip (`principles-strip.tsx`)

`.od-ruled` band; three ruled cells (`divide-x`, stack with `divide-y` under `sm`), each a stripped shadcn Card: serif h3 17 + 13px muted line, 24px vertical padding, no icons (Zed's Fast/Agentic/Collaborative strip):

- **One integration** — "Add the plugin to your Vite, Next.js, webpack, or Rspack dev build. Dev-only; nothing ships to production."
- **The real DOM** — "Point at any element. The agent gets the live node, its source location, and its state."
- **Your machine** — "Your code and prompts never pass through conciv servers. No conciv account or API key — bring your own Claude Code or Codex CLI."

### 3. Capabilities (`capability-section.tsx`, image-led, replaces `features-section.tsx`)

Eyebrow `ON THE PAGE`; h2 (serif) "The page becomes the agent's context."; no sub. Then an asymmetric figure sequence in ruled cells (Zed's feature grid: rows separated by rules, cells separated by rules, 32px/48px cell padding, image with 1px border, serif h3, 13px caption), not a catalogue:

- Row A (2 large figures, 50/50, stack under `md`): `grab-element.webp` — **Grab any element** / "Crosshair-pick a node; the agent gets the element, its source file:line, and its live state." and `edit-live.webp` — **Try it live first** / "Style and DOM edits land on the running page, ephemeral, until you ask the agent to write them to source." (consistent with the frame's own text: live-only, no source touched)
- Row B (3 small figures, 3/2/1 columns): `test-run.webp` — **Runs your tests** / "Run Vitest or Playwright locally; results render as cards in the thread."; `permission.webp` — **Asks before risky commands** / "Approve or deny shell commands from the chat. Read-only commands just run."; `whiteboard.webp` — **Draws with you** / "A shared Excalidraw canvas the agent can draw on, with source-anchored comments."
- Row C (full-width, 21:9): `any-running-app.webp` — **Any running app** / "Mounted on a local clone of vite.dev with one Vite plugin line. Nothing about the host changed."
  Each figure = stripped shadcn Card cell containing `<figure>` with `<img loading="lazy" decoding="async" width height alt>` (intrinsic size from `src/data/screenshots-index.json`, mirrored to `public/screenshots/index.json`) and `<figcaption>` (CardTitle h3 + CardDescription). Alt text is the factual `alt` from the manifest. Row A: 1 → 2 columns at `md`; Row B: 1 → 3 at `lg`; Row C full width.

Assets: produced by the asset agent from the stills library masters into `apps/site/public/screenshots/*.webp` (large/small tiles 1160×726, wide 2360×1012, `fab-closed.webp` 800×600, `hero-demo.webp` 1440×900) with `index.json` recording `{file, source, crop, width, height, alt}` — this manifest is the reproducibility record (masters live outside the repo). Existing PNGs in `public/screenshots/` are kept if referenced anywhere in `apps/site` or `content/` (grep first); unreferenced ones are deleted (plan task 6).

### 4. How it works (`how-it-works.tsx`, rewrite as a numbered technical document)

Eyebrow `HOW IT WORKS`; h2 "From npm to the spark in three steps."; sub "No SaaS, no second terminal." An `<ol>` of three ruled rows (`border-t`, 48px vertical padding): serif red numeral `01 02 03` at h2 size in a 96px left column (above the content under `md`), serif h3 title, one 16px muted line, real code:

1. **Install** — the same `InstallCommand` (shares the pm selection through the store).
2. **Add the integration** — `FrameworkTabs` (shadcn/Radix Tabs + smoothui animated-tabs indicator) whose panel is the same `ui/code-block.tsx` chrome; tab set and labels exactly what `framework-snippets.ts` supports (`soon` entries stay visibly `soon`, iOS labelled alpha). No logo row.
3. **Open your app** — a `ui/code-block.tsx` terminal (21st Code Block 1099 chrome: filename bar + copy button) reading `pnpm dev`, beside the small `fab-closed.webp` figure at the same height, and the line "The spark appears bottom-right. Click it, or press Mod+`for the quick terminal." (product default per`apps/conciv/src/data/settings.ts` `DEFAULT_HOTKEYS`; the site's own `vite.config.ts`overrides it to`Alt+k`for conciv.dev — the copy describes a fresh install, so the default is correct; re-verify before shipping) plus the small`fab-closed.webp` figure.

### 5. Open source ledger (`open-source-strip.tsx`)

`.od-ruled` band split into two ruled cells: left eyebrow `OPEN SOURCE` + h2 (serif, max 400px so it sets in two lines) "Open source, on your machine." + two shadcn outline buttons "Star on GitHub ›" / "Read the docs ›" (Zed's "View Releases ›"); right: a shadcn Table ledger in mono 13 — `stars <live count>` (`lib/use-star-count.ts`, shared with the nav), `license MIT`, `conciv-hosted services none`. ### 6. Footer (`site-footer.tsx`, smoothui footer-3 structure on paper)

Same ruled column: brand + one-line description (5/12) beside Product / Community / Install link columns (7/12), then a ruled bottom bar `MIT © conciv` / `beta`. Tokens only — no oklch literals, no dark bookend, no newsletter, no scroll entrance.
