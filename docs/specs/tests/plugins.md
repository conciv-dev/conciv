# Ledger: plugins

Feature rows come from `features/plugins.md`, one table per plugin. One row per feature: the flow that covers it and its status. Every status starts with one word, then a colon and the detail: `tested` (names the landed test file and test title, green), `written` (the test is written and landed, not yet proven green), `planned` (not written yet; names the file it will go in), `verify` (thought to be covered or writable, not checked yet), `blocked` (with the reason), `browser` (goes in an area browser file, not written yet), `e2e` (goes in an e2e spec, not written yet), `elsewhere` (owned by a row in another ledger) or `kept` (opencode's behaviour or a ruling, no test). A `tested` row that a test covers only in part says what is left and where it goes. The YES and NO marks of the feature list are stale; its rows are the list. Counts are at the end.

## page

The page plugin is part of the app, so it never mounts: its node tests live beside its sources in `packages/plugins/page/src`, and its on-screen journeys use the app's mount with history in `apps/conciv/src/page.dom.test.tsx`, or `apps/conciv/src/page.browser.test.tsx` where layout, real focus, canvas or capture is needed (happy-dom refuses a click with `[page.invalid-args] That element is not visible.` and answers a screenshot with `[page.handler-error] r is not iterable`).

`src/tools.test.ts` starts an engine with `createEngine`: it is a draft until the kit's start-up speed fix lands.
