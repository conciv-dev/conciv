# Ledger: plugin SDK and host, unplugin, embed, mascot, grab, client, connection machine

Task 7 of `docs/specs/2026-11-21-real-tests-plan.md`. Feature rows come from `features/sdk-embed.md`: the NO rows by id (P1, U7, E3, C18...), the YES (short) bullets and the "could not judge" items by `sdk-embed.md:<line>`. The YES/NO marks there are stale; every row was judged again against the kit as it is now (`createEngine(config, start)` with `reply`, `write`, `setting`, `stale`, `version`, `gate`, `requests`, `event`, `rpc`, `opened`, `loginCode`, `revokeBrowsers`, `restart`, `outside`, `clock`, `cli`; `mount({engine, plugins, seed, history, host, login})`).

Statuses in the last column:

- `planned: <file> › <describe>`: the test is not written yet; the file and the describe it goes in.
- `blocked: <what it needs>`: the exact kit call or product change missing today.
- `written: <file> › <describe> › <test>`: the test is written and not yet run green.
- `elsewhere: <file> › <describe> › <test>`: an e2e spec under `e2e/` already owns the row (its `e2e.md` row says `tested`).
- `kept: <why>`: the row cannot be reached through the UI, or only a banned kind of check (geometry, DOM read, selection read, animation) proves it.
- `story`: a component's look; components are stories, not tests.
- `app lane: <area> <file>`: the on-screen journey of a package the app is made of. It is written under `apps/conciv/src` by the app lane named (pane, shell, composer, sessions), not here.
- `other lane: <ledger>`: the feature is another area's (plugins, Task 6).

Every package of this area (plugin, plugin-host, client, grab, mascot, contract, unplugin, embed) has the one test setup: `@conciv/plugin-testkit` and `@conciv/harness-testkit` as devDependencies, `concivTest()` in its `vite.config.ts`, the kit bin as `test` script. A pure-function test does not call `createEngine`. Node rows that drive an engine load committed fixture plugin folders (server part only, which the engine loads by type stripping), never plugin code written as a string.

## Order

Most used first (what a user or plugin author meets in the first minute), then errors and edges.

1. **plugin-host:** loading plugins (both entries, `[dir, options]`, `conciv/plugins/`), then plugin tools (by name, the model calls one, hooks, Stop), then what the model is given, then asks, rpc, storage, skills, sessions and events, model list, server tools. Errors last: a plugin that fails to load, schema failures, bad names, the unknown tool, policy deny.
2. **contract:** the connection machine (trust transitions first, then back-off, 1008, stalls, stale attempts, the auth timeout). Every on-screen connection row stands on it.
3. **grab:** the payload and labels (every pick goes through them), then the budget edge.
4. **client:** `makeQueryUtils`.
5. **unplugin:** the vite server on a fixture project (U16, U7), the vite bridge (U12, U13), then the bundler builds (U19, U22) and `withConciv`.
6. **plugin:** `Host.resolve` and `Rpc.define` (every plugin author meets them), then `experimental()` build, then reactive helpers.
7. **mascot:** defaults and path geometry, then style merge and the slot error. Its look is stories.
8. **site:** the try panel state functions.

The app-lane rows go to the shell lane first (launcher, login, notices, plugin surfaces), then pane, then composer (grab).
