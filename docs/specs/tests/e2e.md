# Ledger: e2e apps (Task 8)

Feature rows are the `e2e` rows of the four lists in `features/` (`app.md`, `engine.md`, `plugins.md`, `sdk-embed.md`), cited as `list:line`. One row per feature: the journey that covers it, and a status cell that starts with one word: `tested` (the landed file › describe › test), `planned` (the file it will go in), `written` (the landed file › describe › test, not yet run green), `verify`, `blocked` (the reason), `browser`, `e2e`, `elsewhere` (the ledger and row that own it) or `kept`.

What an e2e app is today: a host app scaffolded by its framework's CLI, wired with `@conciv/it`, one dev server per app through `e2eConfig` (`@conciv/e2e-utils/config`), Chromium only, `testDir ./test`. Every app with a `test:e2e` script has at least one spec (the old suites were removed in a15c22d2b; init has no script until its first test). Two facts shape the open rows:

- An e2e app names a harness only by id (`conciv({harness})`); no scripted replies reach an e2e engine (`kit-plan.md` open point 3). A chat turn in an e2e app is a turn of a real CLI, and no CI test may need a signed-in one (as opencode).
- The e2e helpers `kit-plan.md:124-127` lists (a git project, answering the init prompts, sending a signal to the CLI, reading the terminal's text, a stdio hub client) are not built; the maintainer moved them to a follow-up.
