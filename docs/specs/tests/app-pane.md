# Ledger: app, chat pane, thread, tool, permission and ui cards

Feature rows come from `features/app.md` (pane section, and the composer rows the pane flows touch). One row per feature: the flow that covers it and its status. A row a test covers only in part says what is left.

Every status cell starts with one word and a colon: `tested` (the landed test file and title), `planned` (not written yet; the file it goes in), `verify` (thought writable, not yet checked), `blocked` (the reason), `browser` (an area browser file, not written yet), `e2e` (an e2e spec, not written yet), `elsewhere` (owned by a row in another ledger), `kept` (opencode's behaviour or a ruling, no test).

## Files, in order

1. `apps/conciv/src/pane.browser.test.tsx`: the thread and the run, from an empty session to a finished, stopped, compacted or failed turn, and the permission cards (they render in `chat-pane.tsx`).
2. `apps/conciv/src/pane/tool-registry-render.browser.test.tsx`: tool cards and conciv_ui cards as a scripted `TestLLM.toolCall` turn shows them.
3. `apps/conciv/src/pane.browser.test.tsx`: the status chip, the view tabs, the diff cell.
4. `apps/conciv/src/pane.browser.test.tsx`: what needs layout or a Worker: paging, the Latest chip, the virtualized thread, code highlighting and mermaid.
