# Ledger: app, sessions list, search, preview, quick pane

Feature rows come from `features/app.md` (sessions section: the rows marked NO, YES and could-not-judge; the marks there are stale). One row per feature. Each status cell starts with exactly one word: `tested` (the landed test file › describe › test), `written` (written, not yet run green, with its file › describe › test), `planned` (not written yet, with the file it goes in), `verify` (thought to be covered or writable, not yet checked), `blocked` (with the reason), `browser` (goes in an area browser file, not written yet), `e2e` (goes in an e2e spec, not written yet), `elsewhere` (owned by a row in another ledger) or `kept` (opencode's behaviour or a ruling, no test). A row a test covers only in part says what is left.

The session picker list renders through `VirtualList` (`@tanstack/solid-virtual`). With a scroll box of 0px, virtual-core renders no rows (`calculateRange` returns null when `outerSize === 0`), and happy-dom has no layout. So every flow that reads picker rows runs in browser mode, in `apps/conciv/src/sessions.browser.test.tsx`, as does every flow that opens a session that already has saved messages (maintainer ruling 2026-11-21).
