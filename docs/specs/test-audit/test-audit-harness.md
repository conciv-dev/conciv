### 5. Anything odd

- **Tests that cannot fail on code that typechecks**: 143, 152, 158, 163 (×4 each), 200, 243, 2396. The `HarnessAdapter`
  union in src/_shared/contract.ts and `HarnessHistory.list` (protocol harness-types.ts:182) already enforce these at compile time.
- **2336 runs the same input against itself for 4 of its 5 cases**: only claude defines `prepareMessages`. For the others the
  test computes `undefined ?? foreignHistory` and compares the input to itself.
- **249 and 255 spawn the real Claude CLI.** `resolveHarnessModels(claude)` reaches `claudeSdkModels`, which runs the Agent SDK
  `query()` probe (src/claude/sdk.ts:115). The result depends on whether `claude` is installed on the machine and on its
  version. These tests check the installed CLI, not conciv's mapping.
- **Test-only export in product code**: `__commandsCacheSet` (src/claude/sdk.ts:43) is used only by 911, which is a Map
  set/get tautology. This breaks the house rules "no product code for tests" and "no dunder surfaces".
- **Timing race**: 842 aborts with `setTimeout(() => controller.abort(), 0)` against a 40k-line fold. It passes only if the
  fold yields to the event loop before it finishes. That is a timing guess. A pre-aborted signal, as 3121 uses, would
  be deterministic.
- **Fragile fd count**: 2864 counts process-wide `/dev/fd`. It passes only because tests in one file run serially, and it
  only works on POSIX systems.
- **Titles that claim more than the test checks**: 1278 "without reading it", 2601 "stats without reading any message content",
  1990 "counts messages of the page" (two messages are seeded but never counted), 2592 "releases its parser state". None of
  these claims is asserted.
- **Odd grouping**: 2432 is a `describe.each` with one case, and its "stubs" describe holds `pi`, which is a real harness with history.
  2612 is a pure parser test inside the handle describe. Most tests for each harness are spread across 5 or 6 top-level describes.
- **No `vi.fn`/`vi.mock`/`vi.stubGlobal`.** The opencode CLI is a fake shell script on PATH, a fake service rather than a mock.
- **Untested behaviour I found while reading product code** (not part of the verdicts):
  - The claude `effort` setting reaching `CLAUDE_CODE_EFFORT_LEVEL` (src/claude/chat.ts).
  - `ENABLE_TOOL_SEARCH: 'false'`.
  - The `owned: false` permissive MCP args (src/claude/args.ts `claudeConnectArgs`). Every tty test uses `owned: true`.
