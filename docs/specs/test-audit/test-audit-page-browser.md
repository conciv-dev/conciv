Read start to end. Level of every row is **browser** (vitest browser mode, real Chromium, no engine). Cross-level checks against packages/builtin-plugins/test/builtin-plugins.browser.test.tsx (`builtin`, read in full this session), apps/conciv/test/conciv.browser.test.tsx (`conciv.browser`), packages/protocol/test/protocol.test.ts, packages/core/test/core-api.it.test.ts and every e2e/*/test suite (none of them drives a capture, snapshot, React bridge or grab).

Context that drives most verdicts: this file tests two different things.

- **The dying extension page driver**: `makeDomPageDriver` + `defineExtension`/`defineTool` from `@conciv/extension` (describes "a tool that outlasts...", "element capture", "page dispatcher", "page driver dispose"). Its only product users are `packages/embed/src/mount-impl.tsx` (serving extension client tools) and `packages/extension-testkit`. It dies with the extension system. The new page plugin (`packages/builtin-plugins/src/page/operations.ts`) has its own dispatcher but reuses this package's `takeElementCapture`, `buildSnapshot`, `addRef`, `selectDeep`, `reactBridge`, `dehydrate`, `isSensitiveField`.
- **Library code the page plugin and grab still use**: captureElement (grab), fallback metrics, fitImagePreview, grab text, buildSnapshot, react bridge, grabApi.

So: behaviours of shared library code are KEEP even when today they are driven through the dying driver (they must be re-hosted on `makePageOperations`); behaviours that exist only in the dying dispatcher are marked accordingly.

### 2. Lines that would go

- Today: 1,551.

### 3. Journeys a lean rewrite would use

1. **What a capture carries** (on the page plugin's driver): frozen copy, skeleton + css bundles (incl. mid-tool rule), secrets masked, read verbs uncaptured, detach, widget subtree, sanitising (one browser proof; rules owned by protocol unit), image inlining/budget/order/encoder failure/taint/opt-out, late library. Absorbs 58, 404-664.
2. **What a grab carries**: captureElement styles/pseudo/ids/svg, fallback-font metrics, fitImagePreview, elementSnippet/groundGrabText, real pointer pick in comment and pick mode. Absorbs 103-140, 759-945, 1524.
3. **What the agent reads**: buildSnapshot roles/names/state/values/refs, describeElement, refs never reaching conciv's own shadow roots, non-serializable results refused. Absorbs 1092, 1124, 1225-1312.
4. **React bridge details the tool tests don't reach**: inspect hooks + class state, override props/hooks/context + error texts, tree truncation, root discovery without recorded roots. Absorbs 1392, 1401, 1416-1437, 1468, 1511.
5. Effect disposal (1192) moves into builtin's "leaves the page as it found it" journey.

### 5. Odd things / rule breaks

- **Spies**: 623 uses `vi.spyOn(console,'warn')`, `vi.spyOn(console,'error')` and `vi.spyOn(tainted,'addEventListener')`. Only file of the five with banned spies in the browser.
- CSS implementation asserts: 103 (`clone.style.color`, `fontWeight`), 128 (`style.position`, `style.margin`), 772 (`letter-spacing: normal` string), 117 (class prefix `conciv-grab-pseudo-`).
- Geometry asserts: 759, 785 (`getClientRects`, widths `toBeCloseTo`).
- Polling an internal flag: 1537-1547 `expect.poll(() => grabApi.isActive())`.
- The whole capture/dispatcher half tests `@conciv/extension` tool definitions (extension system is dead per the port plan).
- 1057 can't happen through the new plugin (`Command.parse` rejects unknown verbs).
- `afterEach(() => document.body.innerHTML = '')` at 54, 1219, 1521 wipes the whole document body, including anything another describe's `beforeAll` mounted. It works today only because the describes that rely on `beforeAll` fixtures ("page dispatcher", "react bridge") have no such `afterEach` inside them and vitest runs describes in file order.
