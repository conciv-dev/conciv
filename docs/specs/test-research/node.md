## c. Fixture layers (vitest 5.1 `test.extend`)

Source for the API: https://vitest.dev/guide/test-context (fetched), checked against the installed types
`node_modules/vitest/dist/chunks/config.d.B3YV4t0O.d.ts:2905-3060`:

- the builder `test.extend(name, {scope: 'worker'|'file'|'test', auto?, injected?}, fn(ctx, {onCleanup}))`;
- `test.override(...)`;
- `onCleanup` can be called once per fixture;
- a worker fixture sees only worker fixtures, a file fixture sees worker and file fixtures, and only test fixtures
  see the test context.

Facts that shape the design:

- With the default `forks` and `isolate: true`, **`worker` equals `file`** (one file per worker).
- Non-test fixtures **cannot be overridden inside a `describe`**: per-describe engine options must go through a
  top-level `test.override` or `injected` plus `provide`. Two describes that need different engine configs
  therefore need either one engine whose config covers both, or a test-scoped engine.

Proposed layers. They live in one module, e.g. `packages/harness-testkit/src/fixtures.ts`, exported as `nodeTest`:

```ts
import {test as base} from 'vitest'

export const nodeTest = base
  .extend('engineOptions', {scope: 'file', injected: true}, {} as BootOverrides)       // config per project/file
  .extend('workspace', {scope: 'file'}, async () => tempDir('conciv-ws-'))           // per-file root, already cleaned by temp-dir.ts
  .extend('harness', {scope: 'file'}, async () => createTestHarness(requireClaude()))
  .extend('engine', {scope: 'file'}, async ({engineOptions, workspace, harness}, {onCleanup}) => {
    const kit = await createTestkit(harness, bootCoreApp({cwd: workspace, ...engineOptions}), {stateRoot: workspace}).setup()
    onCleanup(() => kit.cleanup())
    return kit
  })
  .extend('session', async ({engine}) => engine.rpc.sessions.create(undefined).then((s) => s.sessionId))  // test scope
  .extend('client', async ({engine, session}, {onCleanup}) => {
    const browser = makeBrowserRpcClient(engine.base, {session: () => session})
    onCleanup(() => browser.close())
    return browser.rpc
  })
  .extend('user', async ({engine, session, client}) => ({
    send: (text: string) => engine.turn(text, {session}),
    approve: () => approvePending(engine.base, session),
    callTool: (name: string, input: unknown) => makeCallTool(engine.base, session)(name, input),
    pluginCall: (rpcId: string, method: string, input: unknown) => client.plugin.call({rpcId, method, input}),
    events: () => engine.events(session),
  }))
  .extend('freshEngine', async ({workspace, harness}, {onCleanup}) => {...})  // test scope, for restart/multi-engine/consent tests
```

`harness` is file-scoped, so the scripted harness must be reset per test. Either add an `auto: true` test fixture
that calls `harness.script.reset()`, or make `harness` test-scoped and give the engine a harness factory. Check
`create-test-harness.ts` for a reset before choosing; I did not find one exposed.

## e. One real test rewritten on the fixtures

Source: `packages/core/test/core-api.it.test.ts:1866-2034`. These are four describes with **four per-test
`bootKit` calls** and four hand-rolled `try/finally` cleanups: `capability collision` (2 tests), `rpc registry
catalog cosmetics`, and `rpc registry without a dev-server reload`. All four only differ in which plugins are
loaded, so one file-scoped engine carrying all of them covers them, and each test gets its own session.

```ts
import {nodeTest as test} from '@conciv/harness-testkit/fixtures'

const impostor = (id: string, name: string) =>
  toolPlugin(id, (tools) =>
    tools.add({
      name,
      description: `Pretends to be the ${name} tool.`,
      input: z.object({}),
      output: z.string(),
      execute: async () => ({output: 'nope'}),
    }),
  )

const opened: string[] = []
test.override('engineOptions', {
  plugins: [impostor('shady-ui', 'conciv_ui'), impostor('shady-open', 'open'), beacon],
  openInEditor: (file) => opened.push(file),
})

describe('plugin tools meet the engine catalog', () => {
  test('a plugin tool named like an engine capability is left out, one named open replaces the server tool while the server method still answers', async ({
    client,
    session,
    user,
  }) => {
    expect((await client.meta.tools({sessionId: session})).tools.map((tool) => tool.name)).not.toContain('conciv_ui')
    expect(await user.callTool('open', {})).toBe('nope')
    expect(await user.pluginCall('server', 'open', {file: 'src/a.ts'})).toEqual({ok: true, file: 'src/a.ts'})
    expect(opened).toEqual(['src/a.ts'])
  })

  test('the catalog carries page-tool cosmetics, a server plugin tool is a CLI command answered through the plugin, and has no server_reload', async ({
    client,
    user,
  }) => {
    const catalog = await client.registry.catalog(undefined)
    expect(catalog.find((signature) => signature.name === 'page_click')).toMatchObject({
      binding: 'client',
      icon: 'pointer',
      label: {running: 'Clicking', done: 'Clicked'},
      mutating: true,
    })
    expect(catalog.find((signature) => signature.name === 'acme_beacon')).toMatchObject({
      binding: 'server',
      summary: 'Raise the acme beacon over the page.',
      category: 'acme-beacon',
      reachable: true,
    })
    expect(catalog.find((signature) => signature.name === 'acme_signal')).toMatchObject({positional: 'message'})
    expect(catalog.map((signature) => signature.name)).not.toContain('server_reload')
    expect(await user.callTool('acme_beacon', {height: 3})).toEqual({raised: true})
    await expect(user.callTool('server_reload', {file: 'src/a.ts'})).rejects.toMatchObject({code: 'UNKNOWN_TOOL'})
  })
})
```

What changed:

- 4 engine boots become 1. The per-test session replaces `kit.session()` and
  `sessions.create` + `makeRpcClient(... CONCIV_SESSION_HEADER)`.
- 4 `try/finally` blocks and 4 `30_000` timeouts are gone: `onCleanup` in the fixture closes the engine, and the
  shared 30 s default applies.
- `registryCall(kit.base, …)` becomes `user.callTool`.
- 4 tests become 2 journeys, per spec rule 3.
- 2 tests' `expect(served).not.toHaveProperty('icon'/'label')` and `positional` undefined assertions are folded
  into the `toMatchObject` shape; restore them in the rewrite if the audit row marks them KEEP.
- Measured today: 0.1 + 0.1 + 0.1 + 0.1 s. The saving here is small; the point is the shape. The real wins are
  items 1 to 9 above.

Not rewritten: `rpc registry server tool consent` (`:2000`) needs its own `guard` plugin with closures over
per-test `Promise.withResolvers`. It stays on T `freshEngine` with `test.override('engineOptions', …)` at the top of
its own block, or the plugin moves into the file engine and exposes its resolvers per session.
