Every file was read in full; where the audit and the file disagree, the file wins.

Destinations: L2-APP (happy-dom plus Testing Library over an in-process engine, stays in apps/conciv), L2-PLUGIN:<pkg>, L3-BROWSER (Playwright, reason given), STORYBOOK, NODE:<pkg>, UNIT, DELETE-*.

How to read the L2-APP rows: the browser file drives `coreControl` (browser commands into a node engine), `bootedCore` and `createShellHarness`. In L2 the same steps become direct calls on an in-process engine, and a "reload" is `harness.dispose()` plus a fresh mount, which happy-dom can do. Faults (`gate`, `fail`, `offline`, `handshake-hold`, `garble`, `cut-on-release`, `chat-frame-gate` and the rest) stay engine-side and carry over.

## 4. What cannot move to happy-dom, and suspected blockers

### Looks like L2 but needs a browser

- 212 (card at two widths), 1011 (notice in view above the composer), 1980 (crowded pill row), 2385 (short-screen model menu), 4198 (card covering the prompt row): real layout.
- 2952 to 3213 (M-PAGING), 8087, 8100, 12252 (M-EVICT): the thread is a TanStack virtual list anchored to the end (`packages/ui-kit-chat/src/behaviors/create-thread-virtualizer.ts`, `observeElementRect` plus ResizeObserver); paging thresholds, anchoring and eviction need real scroll geometry and wheel input.

- 9136 to 9900 terminal rows marked L3: xterm sizes its grid with the fit addon from measured character cells; `tput cols`, `tput lines`, busy state from OSC sequences, screenshots of colours, focus stolen on start.
- 9530, 9601, 9789: real focus across a shadow root and the host page.

- 12778: Alt-click inspect resolves the element under the pointer (hit testing).
- 13100: a second real tab holds a newer IndexedDB version (cross-tab).
- calm-perf (4): frame budgets.

### Suspected happy-dom blockers (check each before the rewrite starts)

1. Virtual thread rows: with zero sizes from happy-dom the virtualizer may render no rows, and almost every L2-APP thread assertion depends on rows rendering (sent messages, tool cards, notes, Stopped line). This is the biggest risk. The fix is a test option on the thread that renders all rows or a fixed item size, not a mock.
2. ResizeObserver: happy-dom ships none that reports sizes; the composer actions host (`ComposerActionsHost`) measures widths to decide the overflow menu (M-OVERFLOW 1963 1996 2014 depend on it).
3. tiptap / contenteditable composer: caret and selection (1176, 4525, 4540, 746), IME `isComposing` keydown, and `beforeinput` with `isTrusted` (12749).
4. Ark / zag focus gating: listbox highlight follows `highlightedValue` (our `data-active`), fine, but focus-return and focus-trap checks (11300 dialogs, 8216 width handle and tab arrows, 12388 Tab order in Settings) need happy-dom focus to behave like the browser.
5. IndexedDB: none in happy-dom; the draft store (12992 13070 13132) and the local draft journeys need `fake-indexeddb` (a real implementation in memory, not a mock).
6. localStorage quota: 10022 and 10115 fill storage until it throws; happy-dom has no quota, so they need a storage with a quota supplied by the host options (a real limit, not a stub).
7. Clipboard: 7373 copies through `navigator.clipboard`.
8. CSS visibility: `toBeVisible` on the launcher pill on hover and on hidden-by-class elements depends on the stylesheet.
9. Product timers that tests wait out: `CALL_DEADLINE_MS` 3 s in 12167, the query retry count, the reconnect and handshake windows in the login and connection journeys, the draft save retry clock (11670). Each becomes an option the test shortens.
10. Same-origin `apiBase: ''` and the dead port `http://127.0.0.1:9` (10616, 12212): fine in node, but the in-process engine needs a real fetch target or the L2 shell must take the engine client directly.
11. xterm in happy-dom: the 7 terminal L2-PLUGIN rows assume the terminal surface mounts without measuring; if xterm throws on zero-size cells they move to the browser file too.
