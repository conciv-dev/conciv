# Test split: apps/conciv (group "app")

Where every test that sat under `apps/conciv` at `9d4f4834f` (the last commit that has all the old tests) goes in the rewrite. Every row cites its file and line at `9d4f4834f`; read a file with `git show 9d4f4834f:<path>`. Runners, kits and rules are in `docs/specs/test-rewrite-after-port.md`; where this file and that one disagree, that one wins.

Destinations are today's runners. `node` and `node (table)`: vitest in node, `src/x.test.ts` beside `src/x.ts`, a table being `it.each` rows. `happy-dom`: `src/x.dom.test.tsx` beside `src/x.tsx`, the whole app on a real engine through `createEngine` and `mount`, driven with Testing Library and user-event. `browser mode`: the one `src/<package>.browser.test.tsx` of a package, only for layout, scrolling, the virtual list, canvas and real focus. `e2e`: `e2e/<app>/test/*.spec.ts`, the built bundle in a host app. `story`: a `*.stories.tsx` state with a play. `perf gate`: the frame budget project. `DELETE-DUP`, `DELETE-NOTHING` and `DELETE-COVERED` drop a test whose behaviour is proven elsewhere or that tests no product code. `not carried` drops a behaviour no runner can reach today, with the reason. The target column names the file the test is written in, beside an existing source module (checked with `git ls-tree` at HEAD).

The kit is `createEngine({plugins, harness, replies, settings, files, permission, log})` and `mount({engine, seed: {storage}, route})`, plus `createHarnessEngine` for node tests that need the engine address. `harness` (ruled 2026-11-20) takes a real adapter from `@conciv/harness`; the kit scripts only its chat (`packages/harness-testkit/src/scripted-harness.ts:36`), so its models, slash commands and terminal are the adapter's own (Decision 5). Under ruling A (2026-11-20) `replies` take the shapes of opencode's test model (`packages/ai/src/testing.ts` in opencode): `text`, `toolCall` and `toolCalls`, `failAfter` (the run fails part-way), `hangAfter` (the stream never ends, so the turn stays running) and a `Gate` held until `release` (with `started` to wait for it). The old tests also leaned on core controls (`coreControl`, `bootedCore`, `createShellHarness`), connection faults and proxies, held socket calls, fake-indexeddb, spies, `expectLog`, and the `/flow`, `chat`, `component`, `pane`, `widget` and `fault` fixtures. Those stay ruled out. A row that needed one keeps the part of its behaviour a user reaches without it, moves to a node test of the module that owns the rule, or is `not carried`. Nothing here asks for new kit API beyond those two rulings; the choices that would bring more rows back are listed under Decisions at the end.

### Suspected happy-dom blockers (check each before the rewrite starts)

1. Virtual thread rows: with zero sizes from happy-dom the virtualizer may render no rows, and most happy-dom thread assertions depend on rows rendering (replies, tool cards, notes, the Stopped line). 5. Clipboard: 7373 copies through `navigator.clipboard`.
6. CSS visibility: `toBeVisible` on elements hidden by class depends on the stylesheet.
7. ## Decisions

Numbers are kept so the row citations stay true; 3 and 6 are answered by ruling A, and 5 by the `harness` ruling.

1. **A chat connection the test writes.** Pick: a `ChatSessionConnection` passed through `createChatSession({connect})` counts as a fake the product accepts, not a stub, so the 9 session rules that needed a held or failed socket call go to `packages/ai/src/session/session.test.ts`. Alternative: call it a stub and mark those 9 rows not carried.
2. **A second client on one engine.** Pick: not carried (240, 6166 and the other rows that need a delete or an answer from another client); the kit gives the test no rpc and does not say two `mount` calls may share one engine. A run from another client is `engine.session.send` and is carried (1450). Alternative: allow two `mount` calls on one engine in a test, which needs the maintainer's yes.
3. **A turn that stays running.** Answered by ruling A: a `hangAfter` reply keeps the turn running and a `Gate` holds it until `release`. M-STOP, M-QUEUE, M-AWAY, M-VIEWTABS, the launcher status and the fixture panel's running state are happy-dom journeys again.
4. **An untrusted or locked app.** `mount` always passes a trusted token. Pick: the login journey goes to e2e (tanstack-start), the trust and revoke rules to the connection machine node test, and a refused draft save is made in node by an rpc client without the engine token; the unsaved notice and the revoke screens are not carried. Alternative: a `mount` option to start untrusted, which is new kit API.
5. **Models, slash commands and the terminal.** Ruled 2026-11-20: `createEngine` takes a `harness` option and passes it to `createHarnessEngine` (`packages/harness-testkit/src/harness-engine.ts:24`), which scripts only its chat (`packages/harness-testkit/src/scripted-harness.ts:36`); the test passes a real adapter from `@conciv/harness` (table above). M-MODEL (17 rows) returns to `apps/conciv/src/composer/session-model-prompt.dom.test.tsx`, 2385 to `apps/conciv/src/conciv.browser.test.tsx`: 12 rows on `codex`, whose models and efforts come from a file the test writes, and 5 on `claude`, the only adapter with slash commands (2277 2332) and an `Older versions` group (2405 2427 2548). The 17 terminal rows return to `@conciv/plugin-terminal` on `claude`, the only adapter with a terminal. Still not carried: M-HARNESS (3286 to 3485 and 3333, 12 rows) and 9691, since the engine runs one harness (`harnesses: []`, `harness-engine.ts:196`); 9841, since `claude` never lists zero models (`packages/harness/src/claude/sdk.ts:100`); 7940, since no scripted reply compacts. Every `claude` row waits on Decision 14.
6. **Tool calls in the thread.** Answered by ruling A: `toolCall` and `toolCalls` replies draw tool cards, so M-TOOLCARDS, M-PAGECARD, M-PAGEQUEUE (12644 12660), 4104 and the tool outcome rows 8131 8138 are happy-dom journeys. The Grep and Glob rows (8149 x2) stay a story: those are harness CLI tools, and the scripted chat runs none.
7. **Approval cards from outside calls.** Narrowed by ruling A: the agent's asks (186 212 282 8131 12753) are a `toolCall` reply under a `createEngine({permission})` rule that asks, which raises the card in the turn. Only the outside-agent rows (5101 5115 5136) still raise the card with `engine.session.tool(name).call`. Pick: the first writer run proves that an outside call under an asking rule draws the card. Alternative: if it does not, those 3 rows are not carried.
8. **Product timers in happy-dom.** Pick: rows that waited out a deadline go to node tests that set `EngineConnectionTimings` (7084 7109); no happy-dom row waits out a timer. Alternative: a `mount` option that passes `Platform.timings`, which is new kit API.
9. **Node tests that need the engine address.** `createEngine` hides the address; `createHarnessEngine` returns it. Pick: `pane/draft-storage.test.ts` and `runtime/plugin/manager.test.ts` use `createHarnessEngine` and build `makeAppData` on its address. Alternative: move those rows to happy-dom journeys that read the result after a remount.
10. **Where the perf gate lives.** Pick: `apps/conciv/src/calm-perf.browser.test.tsx`, kept out of `test` as today, as a second browser-mode file in the package (an exception to the one-file budget, needs the maintainer's yes). Alternative: one describe in `conciv.browser.test.tsx` that the perf project selects.
11. **Thread rows in happy-dom.** Pick: a product option on the thread that renders every row (default unchanged), if blocker 1 is real. Alternative: move every happy-dom step that reads a reply or a tool card to browser mode.
12. **Project files written mid-test.** `createEngine({files})` writes only at start. Pick: not carried (8938 10812 10850: a plugin revision reload and engine-only plugins added while open). Alternative: a kit way to write a project file during a test, which is new kit API.
13. **App components with no reply path.** Pick: notices, the engine notice, ContextTracker and RunErrorRow while compacting stay app stories, since neither a reply nor the app can raise those states. QueueStrip and the run error rows are happy-dom journeys now. Alternative: happy-dom journeys where a fixture plugin raises a notice, and not carried for the rest.

14. **Adapters whose lists come from a CLI.** `claude` reads its models and slash commands by probing the claude CLI through the Agent SDK (`packages/harness/src/claude/sdk.ts:118`, `:128`), and its terminal starts `claude` (`packages/harness/src/claude/index.ts:26`). A test on it needs the claude CLI where it runs, CI included, and the models and commands it shows are whatever that CLI lists. That covers 22 rows: 2277 2332 2405 2427 2548 and the 17 terminal rows. `opencode` also lists models through its CLI (`packages/harness/src/opencode/models.ts:96`), so no row uses it; `codex` reads a file the test writes in a temp `CODEX_HOME` (`packages/harness/src/codex/models.ts:61`), so its 12 rows need no CLI. Pick: carry the 22 rows on `claude`, steps naming a model or command by what the list shows, never a fixed name, and install the claude CLI in the CI jobs that run happy-dom and browser mode; whether its probe needs a signed-in account is not checked here and must be before the rewrite. Alternative: the 22 rows stay not carried until an adapter offers commands, model groups and a terminal without a CLI.
