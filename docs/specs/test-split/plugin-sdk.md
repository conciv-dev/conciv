# Test split: plugin SDK group (packages/plugin, packages/plugin-host)

Source: worktree aidx-wt-test-split at origin/main 86d94e743. Every test file of both packages was read in full; the audits in docs/specs/test-audit were used as hints only. Line numbers are worktree lines.

Counting: a test is one generated case. An `it.each`, `test.each`, `forEach` or `for` loop is one row marked "(each xN)" and counts N. Where a file's source has fewer test calls than cases, the header says both.

## What the two packages become

- packages/plugin-host (39 files today) becomes two files:
  - `packages/plugin-host/test/plugin-host.test.ts`: the fast node file. Holds every journey below plus the unit tables.
  - `packages/plugin-host/test/plugin-host.slow.test.ts`: real git, tar and a local npm registry (PH-NPM install steps), the cross-process file lock (PH-LOCK EffectFlock), and the native OS watcher block (PH-FS). These spawn processes or wait on the OS, so they go in their own file to run in parallel with the fast one. The native watcher block must run on CI there (today it is skipped on CI).
- packages/plugin (3 files today) becomes two files:
  - `packages/plugin/test/plugin.test.ts`: the node file; shared-events.test.ts folds in.
  - `packages/plugin/test/plugin.dom.test.tsx`: happy-dom, for the six Solid helper tests that run in a real browser today. None of them needs layout, focus or canvas.

## Journeys (merge-ids)

plugin-host, fast file:

- PH-BUS: publish, subscribe, session routing, the unpersisted product bus.
- PH-STATE: the State domain (transforms, replay, groups, observers, interrupt safety), with the two fast-check properties.
- PH-STORE: database open and migrate, KV, plugin storage.
- PH-LOCK: KeyedMutex (fast file); EffectFlock (slow file).
- PH-FS: watcher life cycle, ready signal, sharing, FileSystem.find, global folders; the native block is in the slow file.
- PH-NPM: where plugins come from (config plugin source folders, fast file); install, resolve, check and update (slow file).
- PH-SKILL: skill registry, SKILL.md files on disk and virtual, folder watching, symlinks, the skill tool, the report skill.
- PH-INSTR: instruction state and code mode instruction text.
- PH-PERM-RULES, PH-PERM-ASK: permission rules and the ask flow.
- PH-TOOL, PH-TOOL-INVALID, PH-TOOL-CALL, PH-TOOL-SERVER: tool registry life cycle, overlays, visibility, hooks, execute, server tools.
- PH-SCHEMA: tool schema projection and validation (node part; the rest are unit tables).
- PH-PLUGIN: plugin activation order, inventory, failure isolation, all-or-nothing registry edits, promise adapter input boundary, child sessions, bundle chunks, module loading and policy.
- PH-SUPER: supervisor first activation, debounce, 24 h refresh, removals, built-in order, duplicate ids, reload races, server_restart asks, load errors.
- PH-RPC: events and rpc between plugins, handler failures typed as rpc.internal, service names.
- PH-TYPES: type contracts proven by tsc.

plugin SDK:

- PL-TYPES (type contracts proven by tsc), PL-RPC, PL-SCOPE, PL-HOST (host and Host.resolve), PL-BUNDLE (app part bundles, inert modules, experimental build, published declarations), PL-EVENTS (Conciv.make event stream; the 16 opencode shared-events cases stay one describe), PL-SOLID (createKeyed, createLatest, createVisitState, usePlugin, bindPlugin; happy-dom file).

Unit tables (U-*), all in the node file of their package: U-SCAN-LIMIT, U-HOOK-OUTPUT, U-SCHEMA-PROJECTION, U-SCHEMA-KINDS, U-INPUT-ERROR, U-OUTPUT-ERROR, U-PERM-EVALUATE, U-CM-SEARCH, U-CM-PAGING, U-CM-BUDGET, U-CM-RENDER, U-CM-UPDATE, U-INSTR-DIFF, U-INSTR-RENDER, U-SKILL-AVAILABLE, U-SKILL-FILE, U-MARKDOWN, U-NPM-KEY, U-NPMRC, U-FS-REALPATH; in packages/plugin: U-PLUGIN-ID, U-BAD-BUNDLE and the other U- tables named in its section.
