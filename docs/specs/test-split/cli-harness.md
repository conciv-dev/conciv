## 4. Things that cannot move to happy-dom, and suspected blockers

Nothing in this group renders a component, so nothing here is a candidate for happy-dom, and no Ark/zag focus, tiptap,
ResizeObserver, IntersectionObserver, canvas or clipboard blocker applies. What the rewrite of this group does need:

- **Real processes, not happy-dom:** cli bin tests (338-354, 1236-1509, 1767-2161, 2213-3120, 3350) spawn `dist/bin.js`
  and need a fresh build; harness-init bridge tests spawn the bridge; harness opencode model tests run a fake CLI on PATH;
  cli 3472-3493 and 6009-6148 spawn children. These stay NODE on real processes.
- **Globals the rewrite must stop touching:** `captureStdout` replaces `process.stdout.write` with
  `vi.spyOn(...).mockImplementation` (cli helpers) and `helpText` does the same to `console.log`: a stub of a global;
  the CLI should take an output sink. cli 3591-3603 and 3841 mutate `process.stdin/stdout.isTTY` and CI env; cli 4127
  mutates `process.env.PATH`; cli 3651 calls `process.emit('exit', 0)`, which fires every exit listener in the worker;
  harness opencode models swap `process.env.PATH`; vitest-config uses `vi.stubEnv` (Decision 7 counts it as a stub).
- **Timing guesses:** harness 847 aborts with `setTimeout(0)` against a fold (use a pre-aborted signal); harness-testkit
  565, 827, 844, 904, 927 sleep 20-50 ms before asserting absence, and 844/861 assert wall-clock spans (move the scripted
  run onto fake timers); 956 asserts `< 500 ms`; cli 1888/1915 and 1253 poll with `vi.waitFor` 5 s; cli 2503 waits out the
  hub's per-engine timeout on a hung engine (make the timeout an option the test shortens).
- **Shared state:** cli 1767 and 1814 share one engine, a `seen` map and an `accepted` queue (queue rows are
  order-dependent); cli 596 sets `CONCIV_PORT` and never unsets it; harness 2384 leaves `test-x` in the registry so 178

  2859 rename the shared db away and back; harness 2873 counts process-wide `/dev/fd`; harness-testkit 1014 sets
  `--expose-gc` process-wide.

  the page plugin's `./testing` export); `vitest-config/src/shards.ts` still lists deleted extension packages (plan,

- **Product code kept alive by tests:** `__commandsCacheSet` (harness src/claude/sdk.ts:43), `harnessModes` and
