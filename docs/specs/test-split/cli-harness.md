# Test split: cli-harness group

Updated 2026-11-20 to the rulings in `docs/specs/test-rewrite-after-port.md`. Row line numbers are the old tests at
`9d4f4834f` (`git show 9d4f4834f:<path>`), and so is every line cited in a "why" cell or in sections 3 and 4. A
DELETE-DUP or DELETE-COVERED cite names the old test whose row carries the behaviour; that row says where it lives now.
Tests deleted before 9d4f4834f have no row; each section note names them and the commit that removed them.

Target column: the new test file, next to the code it proves (`src/x.test.ts` in the section's package, or a full
`packages/...` path when it is another package). The old `test/` folders and the `<pkg>.node` targets are gone. A row
marked `not carried` has its reason in "why". Decisions are at the end of the file.

How the node tests of this group run now:

- The CLI is driven as the built bin in a child process (`node dist/bin.js ...`); its env (CONCIV_PORT, CONCIV_TOKEN,
  CONCIV_HOME, PATH, CI) goes to the child, never into `process.env`, and its help and output are read from the child's
  stdout, never through a `console.log` spy.
- An engine is `createHarnessEngine` from `@conciv/harness-testkit` (its `address` gives the port and token the bin
  needs); a test plugin is a file the test writes with `files` under `conciv/plugins/`, which the engine discovers in
  its root without any config entry (Decision 7). An approval is
  `session.approve()`. Fake engines that only answer `/health` or `tabs.get` are hand-written http servers in the test
  (a real service the CLI talks to, not a mock).
- Ruled out here: `@conciv/plugin-page/testing` (`pageTabs`), the kit's old helpers (`createTestkit`,
  `createFakeHarness`, `makeScriptedRun`, `hold`/`release`, run-stream waiters, `loginThroughTerminal`,
  `withAutoApproval`, `harnessAvailable`), `vi.spyOn`/`vi.stubEnv`, and writes to `process.env` or `isTTY`.

Files: packages/cli, harness, harness-init, harness-testkit, skills, publish, bundle-size, vitest-config, oxlint-plugin,
uno-preset. Inputs: test-audit-cli.md, the cli and harness rows of test-audit-big-five-delta.md, test-audit-harness.md,
test-audit-harness-testkit.md, test-audit-repo-tooling.md, test-audit-small-node.md, and the runner table in
test-rewrite-after-port.md.

How the files were checked: the small files (harness-init, harness-testkit, uno-preset, the new oxlint blocks) were read
in full. For cli.test.ts and harness.test.ts the call-site list was taken from the worktree, every changed hunk since the
audit heads was read (`git diff 51708bc06 HEAD` for cli, harness, publish, harness-testkit; the harness and repo-tooling
files did not change between 992822d36 and 51708bc06), and the tests whose verdict depended on it were read in the
worktree (cli 420-436, 921-960, 2184-2388 imports, 6065-6140; harness 248-264, 914-922, 1505-1516). Every
`it`/`test`/`it.each`/`it.skipIf`/loop-generated call site has a row; counts were checked with grep.

No test in this group needs a DOM. Nothing here goes to happy-dom, browser mode or a story. The one e2e journey is the
CLI page verbs against a real tab (CLI-PAGE).

Destination words: `node:<pkg>` = vitest node over real files and processes. `node (table)` = a pure function as an
`it.each` table, also node. `e2e` = Playwright under `e2e/`. `not carried` = the behaviour has no test after the
rewrite, reason in "why". DELETE-* as in the brief.
