# Test split: core group

Packages: core, chat, ai, contract, client, db, protocol, storage-history, tools, serve, it. Every row cites the test at
`9d4f4834f` (`git show 9d4f4834f:<path>`), the last commit with every old test. Plan and rulings:
`docs/specs/test-rewrite-after-port.md`. Updated 2026-11-20 to those rulings.

How to read a row: destination is the runner (`node`, `node (table)` for an `it.each` over a pure function, `happy-dom`,
`browser mode`, `e2e`), a `DELETE-*` reason, or `not carried`. Target is the test file next to the code it proves
(`src/x.test.ts` beside `src/x.ts`). Journey is the group whose rows become one test; one test per old test is never the
target.

What the kit gives here: `createEngine({plugins, replies, settings, files, permission, log})`, `mount({engine, seed,
route})` and `createHarnessEngine`. `replies` takes the reply shapes of opencode's test model (ruled 2026-11-20): text, a
tool call, a reply that fails part-way, a reply that never ends (the turn stays running), and a reply held until the
test releases it. A core node test that needs more than the kit calls the product itself (`start`,
`makeApp`, the module under test) on temp dirs, and reaches the engine through the product rpc client and the MCP door.
No new kit API is proposed; what would need one is a Decision below.

Who mounts the app (AGENTS.md, Testing): every package in this group, and the page plugin, is part of the app, so none
of them mounts it. Every happy-dom row here lives in the app's tests under `apps/conciv/src` (app.md owns those files)
and joins the app journey named in its row, so it never becomes a second test of the same thing. No row here goes to
browser mode, and no row here renders one component without the app.

## Decisions

Each with my pick first.

- **D1. The page rows.** Pick: they follow `docs/specs/page-plugin-out-of-core.md`: follow-up driver per its section 6,
  owed and reply rows per its ruling 4.1, the rest to the page plugin suites (plugins.md owns those file names).
  Alternative: keep them in core until that plan lands.
- **D2 and D3** (a run kept live, a tool call in a turn) are answered by the replies ruling of 2026-11-20 and removed.
- **D4. Fake CLI binaries.** Codex, claude and hub CLI rows need a fake executable. Pick: they go to the harness area
  (cli-harness.md) on `createHarnessEngine({harness})`, the binary path given through the harness config, never a
  `process.env` write. Alternative: not carried.
- **D5. Start and delete failures made by a bad row.** Corrupt `usage_json`, `DROP TABLE`, corrupt permissions.
  Pick: keep them, writing the bad row into the test's own temp db (the input, not app state). Alternative: not
  carried, or a real cause only (a directory where a file goes, a taken port).
- **D6. Global swaps in contract (831, 854).** Pick: the token storage and the page origin become options of
  `browserRpcConnection` with today's defaults (product options, not kit). Alternative: allow the hand swap as a fake.
- **D7. A tab.** Pick: rows that need a tab run in an app happy-dom journey where the mounted app is the tab (the page
  plugin is part of the app, so it never mounts it),
  and rows that need a tab that never answers become page plugin connection node tests with the call windows as
  options and fake timers. Alternative: not carried.
- **D8. Budgets and build guards.** Pick: the dist guards (core.test 5079, 5091, ai 1152) become a repo build check, not
  src tests; any core file that passes 1,000 lines asks for an exception. Alternative: split by describe into more
  modules.
- **D9. Raw sockets in serve and the hand-written events server in client.** Pick: keep them; a real ws client that
  stops answering and a fake stream server are fakes of the peer, not kit faults. Alternative: not carried.
