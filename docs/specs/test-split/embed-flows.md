# Test split: embed-flows

Group: packages/embed, packages/unplugin, packages/mascot, packages/mascot-react, packages/react, packages/preact,
packages/solid, packages/try, packages/grab, every e2e/* app, apps/site. Every test file below is the file as it stood at
`9d4f4834f`, the last commit with every old test. The audit files in `docs/specs/test-audit/` were used as hints only.

Rules this plan follows (`docs/specs/test-rewrite-after-port.md`):

- Line numbers are lines at `9d4f4834f`.
  - The react/preact/solid suite rows cite `widget-suite.ts`, which was deleted in `9d4f4834f` itself; they give its lines
    at its last commit.
  - The mascot stories have no line numbers.
- Destinations name today's runners:
  - `node`: `src/x.test.ts`;
  - `node (table)`: an `it.each` table in a `src/x.test.ts`;
  - `happy-dom`: a `src/x.dom.test.tsx`; for the shell and plugins, on `createEngine` + `mount`;
  - `browser mode`: one `src/<package>.browser.test.tsx` per package, only for layout, scrolling, canvas and real focus;
  - `e2e`: Playwright Test under `e2e/` with `e2e-utils`, for the built bundle in a real host;
  - `story`: a `*.stories.tsx` play.
- `DELETE-DUP` and `DELETE-COVERED` name the test that keeps the behaviour. `DELETE-NOTHING` deletes a test that proves
  nothing a user sees. `not carried` gives the reason.
- The kit is `createEngine({plugins, replies, settings, files, permission, log})`, `mount({engine, seed: {storage}, route})`
  and `createHarnessEngine`. A plugin tool is called with `engine.session.tool(name).call(input)`.
- `replies` takes the reply shapes of opencode's test model (`_ref/opencode/packages/ai/src/testing.ts`, ruled
  2026-11-20): text, a tool call, a reply that fails part-way, a reply that never ends (the turn stays running) and a
  reply held until the test releases it. A row that needs a running turn or an agent tool call uses one of these.
- Ruled out, so no row leans on them:
  - connection faults and proxies;
  - held or failed socket calls;
  - fake-indexeddb;
  - the old `/flow`, `chat`, `component`, `pane`, `widget` and `fault` fixtures;
  - `expectLog`;
  - mocks.
- Who mounts the app (ruled 2026-11-20, as opencode): a package the app is made of (anything in the dependency closure of
  `apps/conciv`; here the page, terminal and ios plugins and the mascot) never mounts the app. A row that mounts the app targets `apps/conciv/src`;
  the mascot rows render the library alone, so they stay in packages/mascot as tests without the kit, and each says
  "no kit, no app".
- A row whose target is `src/index.test.ts` tests through the package entry. When a row's subject is one source file, the
  writer puts it beside that file instead. For example, `tip-anchor.ts` rows go beside `tip-anchor.ts`.

How to read the tables:

- One row per call site. A loop or `it.each` site says `(xN)` in the test cell and counts as N tests.
- Browser rows name the browser reason:
  - `layout`: real layout, geometry, scrolling, viewport, observers;
  - `canvas`;
  - `focus`: real focus or :focus-visible;
  - `bundle`: the built bundle in a host page;
  - `reload`: a real page reload or navigation;
  - `cross-tab`: a second tab, window or profile.
- Only `bundle`, `reload` and `cross-tab` need e2e. `layout`, `canvas` and `focus` are browser mode on `mount`, where the
  test page is the host page.
- The built-widget journeys of embed.it go to `e2e/vite-vanilla/test/embed.spec.ts`, the smallest host that loads the
  built widget (Decision E1).
- Mascot rule (Decision 6 in the plan, "rewrite to what the user sees, or delete; no exception"): every mascot geometry
  test says which case it is:
  - it needs real layout: browser mode, layout;
  - it is only a tween, style or DOM read: DELETE-NOTHING, "geometry read";
  - the behaviour is pure math that already lives in a pure function (`packages/mascot/src/core/path.ts`,
    `tip-anchor.ts`): `node (table)`;
  - the behaviour is an API contract seen through a fake effect handle, a ref or a thrown error: `happy-dom` in the
    package's `.dom.test.tsx`.

## 4. Things that cannot move to happy-dom, and suspected blockers

Cannot move, though they look like they could:

- Composer caret and IME (embed.it 359, 381): caret placement in a contenteditable and IME composition need a real editor
  engine. happy-dom has no real Selection/Range layout for ProseMirror and no composition events from an input method.
  381 goes to a ui-kit-tap story play (Storybook's Chromium, `cdp()`); 359 goes to e2e (caret across a real reload).
- Focus order (embed.it 822, 1180, 2053-2107; unplugin 1683, 1730): `Tab` order, focus traps and `:focus-visible` are not
  computed by happy-dom, and user-event's tab simulation does not honour shadow-root delegation or `inert`. The in-panel
  rows go to browser mode in apps/conciv; the DevTools dock rows go with the unplugin e2e apps.
- Host page key isolation (embed.it 1156/1170) depends on how real Chromium retargets key events out of the widget's
  shadow root to a host `window` listener (e2e).
- Selection containment (embed.it 2887, 2901): a mouse-drag selection across a shadow boundary; happy-dom has no hit
  testing (e2e).
- Alt inspector (embed.it 1635): the inspector picks the element under the pointer (hit test), so it needs layout (page
  browser mode).
- Local-first drafts across reload and tabs (embed.it 2513-2667, 2524, 2559): IndexedDB plus a real reload, so e2e.
  fake-indexeddb is ruled out; in happy-dom, drafts come from `Platform.draftStore`, which `mount` fills with an in-memory
  store.
- Queue lost and outage (embed.it 886, 919, 991, 1059, 1205, 1245): connection faults are ruled out. These rows prove the
  machines that own the behaviour in node:
  - `engine-connection-machine.ts` for reconnect and the heartbeat;
  - `pane-attachments.ts` and `draft-storage.ts` for the lost queue.

  The notice and the disabled Send on screen are not carried.

- Mascot resize, visibility and scale (mascot.it 498, 550, 751, 1328, 1704-1720, 1852, 1867, 1943, 2788, 2840) need a
  layout engine: ResizeObserver, IntersectionObserver, scroll and measured boxes. happy-dom implements none of them with
  real sizes.
- Canvas effects (mascot.it 883, 913) and the terminal (embed.it 97): happy-dom has no 2D canvas context.

Suspected blockers for the happy-dom moves:

- tiptap/ProseMirror contenteditable (embed.it 263, 294, 328, 439, 456): typing, chip nodes and the typeahead plugin read
  DOM selection. happy-dom's Selection support is partial, so chip insertion via Enter may not serialize the same string.
- Ark/zag focus gating: zag gates `data-highlighted`/`focusVisible` on the listbox holding DOM focus (AGENTS.md landmine).
  The trigger menu asserts `aria-activedescendant`, which is not gated, so 439/456 should work. The model and session
  menus (popover positioning via floating-ui) get zero-size rects in happy-dom, harmless for role asserts.
- ResizeObserver and IntersectionObserver are absent in happy-dom. Any shell component that builds one at mount (thread
  virtualizer, pane resize) needs to work without it; a no-op from the kit would be a stub.
- Mascot happy-dom rows (mascot.it, wrapper slot, effect-child, leak and reduced-motion rows) need a DOM but no layout and
  no kit. GSAP drives its ticker from `requestAnimationFrame`, which happy-dom provides on timers, so the
  manual clock (`gsap.ticker` removed, stepped by hand) should still work; confirm on the first row written.

Guards (rulings carried from 2026-11-19):

- Leak guards are kept and checked through GSAP's public API after work stops and after unmount: mascot.it 335, 826
  (x16), 2261; solid-mascot.browser 264; react-wrapper.browser 315. These are `happy-dom` rows in M-LEAK.
- Listener-count and layout-read-count tests are deleted: mascot.it 967, 1007, 1776, 1893; react-wrapper.browser 332, 347.
- Reduced motion is kept: mascot.it 1386 and 2312 run in happy-dom with reduced motion set, plus one browser mode check
  of the real media query (M-REDUCED).

## 5. Decisions

Each lists the pick first.

- **E1, where the built-widget journeys run.**
  - Pick: `e2e/vite-vanilla/test/embed.spec.ts`. The host app runs the engine with the scripted harness, so the e2e journeys
    that need a reply (embed.it 160, 589, 609, 2428, 2778 and the queued-send rows) get one. Today the e2e apps run real
    harnesses only; this is e2e app config, not kit API.
  - Other: the journeys that need a reply are not carried, and only boot, reload and focus without a reply stay.
- **E2, a hand-written app data that refuses a draft read (embed.it 1059).**
  - Pick: allowed, as a fake service the product accepts (rule 2); `appendDraft` is tested against it in
    `draft-storage.test.ts`.
  - Other: 1059 is not carried.
- **E3, an engine that goes away and comes back (embed.it 1737).**
  - Pick: not carried. The kit has no restart and no connection faults.
  - Other: a `restart()` on the engine `createEngine` returns, which would be new kit API.

- **U1, the unplugin bundler journeys (28 rows, 36 tests: webpack and rspack pages, node_modules install, cold cache,
  DevTools dock, pop-out).**
  - Pick: one e2e app per bundler under `e2e/` (webpack and rspack apps do not exist yet).
  - Other: browser mode in packages/unplugin, with the bundler started on the node side through browser commands.
- **S1, the site journeys (13 rows of site.it).**
  - Pick: an e2e suite for the built site under `e2e/`, since Playwright is only allowed there.
  - Other: browser mode in apps/site.
