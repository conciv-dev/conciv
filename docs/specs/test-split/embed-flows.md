# Test split: embed-flows

Group: packages/embed, packages/unplugin, packages/mascot, packages/mascot-react, packages/react, packages/preact,
packages/solid, packages/try, packages/grab, every e2e/* app, apps/site. Code read on the worktree
`/Users/omrikatz/Public/web/aidx-wt-test-split` (origin/main 86d94e743). Every test file below was read on that worktree; the
audit files in `docs/specs/test-audit/` were used as hints only. Line numbers are worktree lines.

How to read the tables:

- One row per call site. A loop or `it.each` site says `(xN)` in the test cell and counts as N tests.
- L3 rows name the browser reason from the brief: `layout` (real layout, geometry, scrolling, viewport, observers),
  `canvas`, `focus` (real focus or :focus-visible), `bundle` (the built bundle in a host page), `reload` (real page reload or
  navigation), `cross-tab` (a second tab, window or profile).
- L2-APP rows land in `apps/conciv` (Testing Library on happy-dom over an in-process engine). L2-PLUGIN rows land in the named
  plugin's own test file on `@conciv/plugin-testkit` `mount({plugins})`.
- Mascot rule (Decision 6 in the plan, "rewrite to what the user sees, or delete; no exception"): every mascot geometry test
  says whether it needs real layout (L3-BROWSER, layout) or is only a tween, style or DOM read (DELETE-NOTHING, "geometry
  read"). Where the behaviour is pure math that already lives in a pure function (`packages/mascot/src/core/path.ts`,
  `tip-anchor.ts`), the row becomes UNIT instead. Where the behaviour is an API contract observable through a fake effect
  handle, a ref or a thrown error, the row becomes NODE with a happy-dom environment (see section 4).

## 4. Things that cannot move to happy-dom, and suspected blockers

Cannot move, though they look like they could:

- Composer caret and IME (embed.it 359, 381): caret placement in a contenteditable and IME composition need a real editor
  engine; happy-dom has no real Selection/Range layout for ProseMirror and no composition events from an input method. 381
  goes to a ui-kit-tap story play (real Chromium, `cdp()`), 359 stays L3.
- Focus order (embed.it 822, 1180, 2053-2107; unplugin 1644, 1691): `Tab` order, focus traps and `:focus-visible` are not
  computed by happy-dom; user-event's tab simulation does not honour shadow-root delegation or `inert`.
- Host page key isolation (embed.it 1156/1170): depends on how real Chromium retargets key events out of the widget's shadow
  root to a host `window` listener.
- Selection containment (embed.it 2887, 2901): mouse-drag selection across a shadow boundary; happy-dom has no hit testing.
- Alt inspector (embed.it 1635): the inspector picks the element under the pointer (hit test), so it needs layout.
- Local-first drafts across reload and tabs (embed.it 2513-2667, 2524, 2559): IndexedDB plus a real reload; happy-dom has no
  IndexedDB (a fake-indexeddb package would be a stand-in, not the platform).
- Queue lost and outage (embed.it 919, 991, 1059, 1205, 1245) are marked L2-APP, but today their faults are Playwright
  `routeWebSocket` injectors (`holdRpcCalls`, `failRpcCalls`, `gateRpcCalls`, `garbleRpcReplies`). In happy-dom these must
  become engine-side faults in the in-process engine (close the chat stream, hold a procedure), and the heartbeat and
  reconnect-ceiling timers must be options (plan rule 2). Until those exist the rows cannot move.
- Mascot resize, visibility and scale (mascot.it 498, 550, 751, 1328, 1704-1720, 1852, 1867, 1943, 2788, 2840): ResizeObserver,
  IntersectionObserver, scroll and measured boxes need a layout engine; happy-dom implements none of them with real sizes.
- Canvas effects (mascot.it 883, 913) and the terminal (embed.it 97): happy-dom has no 2D canvas context.

Suspected blockers for the L2 (happy-dom) moves:

- Shadow root: the widget mounts inside a shadow root; Testing Library queries do not pierce it. `mount({plugins})` must render
  the shell outside a shadow root or the queries must be scoped to it.
- tiptap/ProseMirror contenteditable (embed.it 263, 294, 328, 439, 456): typing, chip nodes and the typeahead plugin read DOM
  selection; happy-dom's Selection support is partial, so chip insertion via Enter may not serialize the same string.
- Ark/zag focus gating: zag gates `data-highlighted`/`focusVisible` on the listbox holding DOM focus (AGENTS.md landmine); the
  trigger menu asserts `aria-activedescendant`, which is not gated, so 439/456 should work; the model and session menus
  (popover positioning via floating-ui) get zero-size rects in happy-dom, harmless for role asserts.
- ResizeObserver and IntersectionObserver are absent in happy-dom; any shell component that constructs one at mount (thread
  virtualizer, pane resize) needs a guard or the kit must provide a no-op, which is a stub.
- Clipboard: none of this group's L2 rows uses it.
- Mascot NODE rows (mascot.it 1418-2508 marked NODE, wrapper slot and effect-child rows): they need a DOM but no layout, and the
  layer table has no slot for a framework-free library on happy-dom outside the shell. The proposal here is each package's
  node file with `environment: 'happy-dom'` for that describe. GSAP drives its ticker from `requestAnimationFrame`, which
  happy-dom provides on timers, so the manual clock (`gsap.ticker` removed, stepped by hand) should still work; confirm before
  the move. If that environment is refused, these rows fall to DELETE-NOTHING too.

Guards that Decision 6 deletes and that have no other home (for the maintainer to rule on, one at a time):

- Mascot leak guards: mascot.it 335, 826 (x16), 2261; solid-mascot.browser 264; react-wrapper.browser 315 (no emitter, tween,
  rAF loop or node left after work stops or after unmount). Only site.it:433 survives as a user-level unmount check.
- Mascot perf guards: mascot.it 967 (no layout reads per frame), 1007 (eye box measured once).
- Listener hygiene: mascot.it 1776, 1893; react-wrapper.browser 332, 347 (one pointermove listener, also under StrictMode).
- Reduced motion: mascot.it 1386, 2312. Accessibility basics, but there is nothing user-visible to assert; storybook already runs
  with `reducedMotion: 'reduce'`, so a story render under reduced motion is the only remaining smoke.
