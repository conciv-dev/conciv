# egm-design review: `docs/designs/design-driver.md` lines 1–301 (revision 3), feature-spec standard

Verdict: changes required. Not ready for implementation. The text problems of round 2 are fixed (spike figures match records, records beside the document, route a label, security reworded, store decided). The browser-only architecture brings its own problems: the pixel path breaks when tab width differs from image width (the normal case); the engine cannot reach the tab outside a tool call; the pairing rule stops `text` deltas from firing; HMR rounds burn the budget; takumi cannot get system font bytes in a browser. A smaller design: the mirror as the only target-width source, filled by the serializer the document already specifies, no takumi, no rrweb; slots only where two implementations exist; HMR rounds for the overlay only.

## Blockers

**B1. The engine cannot reach the tab outside a tool call** (160, 178–187, 133). Today the engine reaches the tab only through `page.call` on `ServerToolPageAccess` handed to a tool step (`types.ts:236-241`, `captures/tab.ts:36`); `server.ts` holds no tab handle. No channel exists for engine-started requests. Also undefined: which tab answers with two tabs open; how a session binds to a tab; what an `hmr-update` (no session) triggers with several sessions. **Fix:** specify the server-to-tab request channel as a core change, or take D1 (HMR marks stale, rounds inside `design_diff`).

**B2. Rounds on HMR exhaust the budget and fire `stalled`/`oscillating` falsely** (178, 202, 204). Eight saves before the first `design_diff` hit `budget`; two saves to other files demote untouched items; half-finished edits oscillate; capture-path noise oscillates (B5). **Fix:** HMR rounds for freshness; `round`, `budgetLeft`, demotion, `stalled`, `oscillating` only over runs observed by `design_diff`.

**B3. The pairing rule stops `text` deltas from ever firing and turns expression cells into "create this" items** (183, 185, 197, 208; CUJ 4). Text pairs only on equal normalized strings, so "Create" vs "Create invoice" never pairs: `extra` plus `unbuilt`, no `text` delta. A cell rendering `{invoice.total}` as "$980" against "$1,200" never pairs; the target node becomes `unbuilt`, heads the structure brief, and the agent hard-codes "$1,200": the trap section 5 exists to close. Line 172 then estimates every changed text in the body font. **Fix:** pair text by geometry after alignment (nearest or overlapping box, string similarity as tie-break); a `data`/`placeholder` node overlapping a live `expression` is paired, never `unbuilt`.

**B4. Pixels, residual, `done` and the text mask are undefined when widths differ** (13, 28–31, 99, 181, 189, 202, 204). Live pixels are at live width; the target at image width; the pixel diff, `residualShare`, tile gate, diff image, `done` and `groupText` (`text-groups.ts:214-231`, one coordinate space) cannot be computed across widths. Target-width pixels via Region Capture need the mirror at 1:1 on screen, impossible in a pane; snapdom is a different renderer. **Fix:** define the pixel source per case (equal: live capture; differ: snapdom of the mirror with fidelity measured, or pixel gates suspended with a visible "pixels not comparable" state); reproject OCR runs through the alignment before `groupText`.

**B5. Screen Capture plus Region Capture rests on unverified assumptions** (30, 181, 189, 278; Problem 3). `getDisplayMedia` needs a user gesture; HMR rounds have none. A full reload kills the stream; re-acquiring needs a gesture; rounds silently drop to snapdom and two renderers alternate (feeds B2). Occluded or minimized windows produce no frames: the stall Problem 3 cites. The crop includes the x-ray pane and widget (snapdom removes `[data-conciv-root]`, `capture.ts:101-103`); needs Element Capture or hiding. Viewport-only: a 1136-tall design on an 800 viewport is partial. DPR 2 frames need downscaling; "1:1" never holds on Retina. No spike measured capture against a target PNG. **Fix:** spike capture fidelity first; add snapdom-only as an explicit alternative; record the capture path per round; never score across paths.

**B6. takumi in the browser cannot get system font bytes; the subset gate misses the measured error sources** (31, 78, 99, 182, 224). The spike read `/System/Library/Fonts/*.ttf` and ran wasm in Node. Browser JS cannot read system fonts (Local Font Access is Chromium-only, permission-gated); both pages that passed the subset use system fonts; Google Fonts bytes need gstatic, contradicting "no network call". The gate misses `font-optical-sizing: auto` (default), SF Pro implicit optical sizing (p95 7.4 px at 390 > `geometryPx` 2), root font size ≠ 16 px, dropped `<br>` and inline spans, canvas `aspect-ratio`, JS-driven layout. pretext cannot repair a finished layout. The sweep ignores the gate. **Fix:** drop takumi (M1); if kept, gate on fetchable web fonts, 16 px root, no system-ui, and a takumi tolerance from the spike's p95.

**B7. Type estimation by off-screen render search has no browser rasterization path and no viable cost** (77, 147, 172, 279). The spike used Playwright element screenshots. Off-screen elements cannot be screen-captured; snapdom costs tens of ms × 49 × 2 × distinct texts (a 100-text page is minutes); canvas `fillText` rasterizes differently (polarity emboldening moved results 2 ink rows). "Within 0.5 px" never measured in a browser path. **Fix:** spike the in-browser rasterizer; bisection (about 6 renders) instead of a linear sweep; a fallback (kind-aware ratios ±2 px) when unavailable.

## Majors

- **M1.** takumi redundant beside the mirror; precedence incoherent (13, 31–32, 149, 182, 244). Mirror only; remove takumi, wasm, gate, ordered `sources`; add "mirror only" alternative.
- **M2.** "Width-invariant" properties are not (13, 31, 99): fluid type, `vw`/`%` padding, wrap-driven gaps, provenance by media condition. Read everything from the mirror when widths differ.
- **M3.** rrweb adds a dependency and continuous recording the round does not need, and reintroduces side effects (46, 182, 216): nested iframes reload, autoplay media, inline handlers in the app's origin without `sandbox`. Fill the mirror per round from the serializer into `srcdoc`; `sandbox="allow-same-origin"`; placeholders for iframes and media; await `fonts.ready`; reword Non-Goal 46.
- **M4.** The mirror shows the live-width DOM laid out at the target width (13, 99): JS branching on `matchMedia`/`ResizeObserver` renders the live structure. List as a limit; lower confidence when inline widths differ from the stylesheet.
- **M5.** Measurement lives in the overlay (160, 216); whiteboard precedent mounts only while engaged. Failure modes unaddressed: no tab, pane closed, navigation mid-round, CSP `worker-src`/`wasm-unsafe-eval`, tab memory. Measurer and worker in the always-mounted client; overlay UI only; add a failure-modes table.
- **M6.** Segmentation's measured failures drive the brief (76, 171, 183, 197, 202). Adopt the spike's gate (partial when depth-1 image leaves cover > 30%); image nodes never produce `unbuilt` brief items; report the gate.
- **M7.** Alignment and ranking under-specified; ranking contradicts top-down (33, 184, 187): depth weighting ranks deeper higher; units unnormalized; pairing by overlap happens before alignment (a 56 px centring offset defeats overlap); scale conflated with font size (known from `scale`); shifts at unpaired containers have no row. Rank by inverse depth then normalized size; align before pairing; fix scale to 1/`scale`; define the container-shift row.
- **M8.** Enricher contract unchanged but cannot express the new enrichers (168–174): `run({node, raster})` cannot ask the tab, see pairs, or create siblings; estimates is a round step; tab contracts must be async. Define `Enricher.run({model, measurer}) => Promise<TargetNode[]>` at root scope.
- **M9.** Pin anchors unstable (36, 68, 186, 212): `data-conciv-source` shifts with edits and is shared by `.map` siblings; node ids must be deterministic; stall needs a stable item key. Remap pins through edits with a "pin lost" state; node id = hash of kind plus rounded box; item key = anchor + kind + node id.
- **M10.** `disagreement` rows in the agent's geometry stage are a tool fault the page cannot fix (32, 185, 199). Overlay-only, out of score and `done`; vanishes with M1.
- **M11.** Section 1 contradicts D6; most slots have one implementation; `REGISTRIES` is server-side so client slots cannot register there; ordered and gate-driven selections are not enums; `TargetStore` listed as a slot at 63 and not at 158. Keep existing slots plus `captures`, `RoleRules`, `Ranker`; plain functions for the rest; specify the tab-side registry; answer D6 in Alternatives.
- **M12.** Fate of `matchers`, `geometry`, `color` registries and when the windowed fallback runs (49, 142–156) unstated.
- **M13.** Reused names change meaning (64, 144–156, 185): `Pair` lacks node id/source/confidence; `Capture` is a server contract; `unbuilt` replaces `missing`; `trimToInk` is imported from `paddle.ts` by `text-groups.ts:4`. Name new types or list field changes; move `trimToInk` to `raster.ts`.
- **M14.** No Risks & Mitigations; missing alternatives (snapdom-only, Element Capture, mirror-only, per-round serialization, budget on `design_diff` only); no ceilings (tab memory, wasm and model size, first-round estimation cost, rrweb overhead).
- **M15.** The sweep is new scope with a known false-positive source (takumi p95 7.4 px at 390). Future Improvements, or run on the mirror.
