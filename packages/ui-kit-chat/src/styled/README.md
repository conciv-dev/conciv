# styled

## Overview

The themed component set built on the primitives: thread, composer, markdown with worker-based highlighting and mermaid diagrams, action bars, activity, groups, model selector and small display parts. Classes are UnoCSS utilities over `--chat-*` tokens.

## Interface

- `thread.tsx:Thread` - `{Root, Viewport, Welcome, Messages, Composer}`; types `ThreadComponents`, `ThreadRootProps`, `ThreadMessagesProps` (`tools`, `grouping`, `groupEntries`, `pageSession`, `attachmentCards`, `readOnly`: the assistant action bar shows Copy only, no Refresh or More; `refreshDisabled`: every assistant action bar's Refresh is shown disabled).
- `composer.tsx:Composer` (`ComposerProps`); `markdown.tsx:Markdown` (`MarkdownProps`: `content`, `streaming`, `highlight`, `compact`; `compact` renders `chat-markdown-compact` (one type size from the container, no heading scale or block spacing, fences as inline code), never wakes the highlight worker, and renders links as text), `markdown.tsx:MarkdownHighlightProvider` (a `readonly string[]` context, empty by default; a `Markdown` without its own `highlight` marks those words, so a whole `Thread` can be highlighted without threading a prop through it), `markdown.tsx:HighlightedText` (plain text that marks the same context words through the kit's Ark `Highlight`, `ignoreCase matchAll exactMatch`; `Thread` renders each user prompt with it, so a match found only in a prompt is marked too), `markdown.tsx:warmHighlighter`, `isHighlighterWarming`.
- `action-bar.tsx:AssistantActionBar` (`readOnly` renders Copy only; `refreshDisabled` forwards `disabled` to `ActionBar.Reload`; `copyText` replaces the text Copy writes), `UserActionBar`; `activity.tsx:Activity` (`{Root, Timeline}`); `group.tsx:Group` (`{Root, Trigger, Content}`); `reasoning.tsx:Reasoning`, `ReasoningText`.
- `harness-model-selector.tsx:HarnessModelSelector` (`HarnessModelSelectorProps`): data in (`status` `loading` | `failed` | `ready`, the session's `models`, optional `others` harnesses with `failed` and `retry`, `value`, `effort`, `disabled`, `switchBlocked`, `history`), callbacks out (`onRetry`, `onModelChange`, `onEffortChange`, `onSwitchHarness`, `announce`, `registerLayer`); `appearance` `prompt` (the composer's mono prompt and `❯` caret) or `pill` (default: the pill reads `Models…` while loading, `No models` disabled when nothing is listed, the model name with `Select model` as its name otherwise, `Couldn’t load models` after a failed read, the same pill and chevron showing a retry icon and `Models`); `disabled` disables the trigger except while `status` is `failed`, so the Retry inside stays reachable (a pick while disabled is the owner's to refuse)
- `model-selector.tsx:ModelSelector` (`StyledModelSelectorProps`), the Combobox compound kept only for the old terminal extension; `branch-picker.tsx:BranchPicker`; `follow-up-suggestions.tsx:FollowUpSuggestions`; `attachment-ui.tsx:AttachmentUI`; `attachment-dispatch.tsx:AttachmentByMime`, `createDocumentAttachmentAdapter`, type `AttachmentCardSlot`.
- `now-line.tsx:NowLine`, `morph-label.tsx:MorphLabel`, `virtual-lines.tsx:VirtualLines`, `shimmer.ts:SHIMMER`, `classes.ts:FOCUS`, `turn-classes.ts`, `text-metrics.ts:createTurnEstimator`.
- `highlight-worker.ts` / `highlight-shared.ts` - worker message types `MainToWorkerMessage`, `WorkerToMainMessage`.
- Subdirectory: [trace](./trace/README.md) - trace list and rows.

## Invariants

- `useModelMenu(onClose?)` → `ModelMenu` (`{popover, state, search, expand, confirm, ask, settle}`) and `styled/harness-model-selector.tsx:HarnessModelSelector`: the one model selector (the composer prompt and the Terminal toolbar), its owner keeps the menu so it can open it (`popover().setOpen(true)`): a ui-kit-system `usePopover` machine plus one store of its search text, unfolded `Older versions` sections and pending harness-switch confirm; `onClose` runs whenever the popover closes (unless the confirm is open) and when the confirm settles. The menu never waits on the session's model list: while it loads the prompt reads `loading models` and the open menu holds its focused `Search models` field over a `Loading models…` status and no rows, so `/model` typed before the list arrives still lands on the search field. The composer prompt is a mono trigger (lowercase model name sliding in on change, the harness in parentheses when more than one harness is available, then signal bars for the effort that fill and drain one bar at a time) followed by a separate `❯` caret; it renders the picker through `Popover.RootProvider` (`lazyMount`, `unmountOnExit`), a `Model` dialog holding one ui-kit `Listbox` built from `meta.harnesses` with a `Search models` field (`Listbox.Input`, `autoHighlight`): one option group per harness, the session's own first (labelled with its name, visible only when more than one harness is available); each group lists its first model group (name and description, check on the selected one), capped at 4 rows when longer (the default, the selected one and the newest others) with a `N more models, type to search` line, since a harness like OpenCode lists hundreds and rendering them all stalls every model switch and each later group as a `Collapsible` section (`Older versions`, folded unless it holds the current model); a search lists every model of every harness, folded sections included, whose name, id or harness name contains it (`useFilter` `contains`, case and accent insensitive); a harness that listed no models says `<harness> has no usable models`; below a separator an `Effort` section: a `SegmentGroup` of the current model's `efforts` in order (`xhigh` reads `High+`) and a fixed-height note for the chosen level
- `HarnessModelSelector`: the current harness is the session row's `harnessKind`, else `defaultHarness`; shown model falls back session model, then that harness's `defaultModel`, then null; a current harness with no models still shows the prompt, labelled with the harness name and enabled, so the menu opens and another harness can be picked (only the pill turns disabled when nothing is listed); rows and the prompt name the harness in parentheses (`Opus 5.5 (Claude)`) only when more than one harness is available; the trigger shows effort bars only when the session effort is one the current model lists; the Effort section is hidden when the current model has no `efforts`; picking an effort keeps the popover open, picking a model (click or Enter, even the current one) closes it; a null effort leaves no segment checked and the note reads the model default; the popover opens on the search field, arrows move from the current model (or, while searching, from the first match), Enter picks; Escape clears a non-empty search and otherwise closes; closing clears the search and refolds the sections; every close returns focus to the composer; nothing matching shows `No models match “<search>”`
- `HarnessModelSelector`: picking another harness's model switches the harness with that model (`sessions.switchHarness` with `model`); those rows are disabled while a run is in progress or a switch is pending; an empty chat switches at once, a chat with messages first confirms with the history size estimated from the messages' text length / 4 (never the session's context usage, which counts the old harness's system prompt and tools); picking it closes the popover first and the confirm mounts only once the popover finished exiting (`onExitComplete`), so the two never overlap; the popover never restores focus itself (`restoreFocus: false`), the composer gets it once the confirm is cancelled or confirmed; another harness whose model list failed shows a retry button; a failed catalog shows `Couldn’t load the other harnesses: Retry loading models` and keeps the session's own models; a current harness whose list failed names the prompt `Couldn’t load models` and offers a muted `Couldn’t load models` line over a `Retry loading models` row named `Couldn’t load models: Retry loading models` (every retry row reads the same way); the composer never waits on another harness's model list
- `HarnessModelSelector`: Retry keeps focus inside the open menu while the list is read again, so a control that takes focus once the models arrive (the Terminal) does not close it; a failed read is announced once, when it shows
- `markdown.tsx:MarkdownProvider` / `useMarkdown` (types `MarkdownCodeBlocks`, `MarkdownCodeBlock`, `MarkdownCodeAction` exported) - opencode's markdown context (`session-ui/src/context/markdown.tsx`) with `openLocalFile`, `localFileExists` and `codeBlocks` only: `openLocalFile` is not inherited, `localFileExists` and `codeBlocks` are, and `codeBlocks={false}` turns content off below. `Markdown` (not `compact`) hands the two file handlers to `Streamdown`; a fence whose language `codeBlocks.current().render` lists becomes a `FencedView` whose `view` mounts `codeBlocks.render(target, {code, language}, fallback)` and whose `fallback` is the kit's own highlight of that fence (Shiki tokens, the mermaid diagram, or plain code until the worker answers), so a declined, failed or thrown view shows the normal code block, and `undefined` from `render` calls `fallback()` (opencode `session-ui/src/components/markdown.tsx:416`). Differences from opencode: content mounts once the whole message stops streaming (the mermaid rule), where opencode mounts each fence once its closing fence arrives (`markdown.tsx:330-457`); the base highlight is requested for every claimed fence, as the source; `codeBlocks.actions` and `MarkdownCodeAction` (its `icon` a `string`) are declared, not drawn.
- `markdown.tsx` caches highlights and diagrams in bounded stores of `MAX_CACHE_ENTRIES` (512), evicting oldest first.
- Turns are spaced by padding, not by the list gap: each turn sits in a `TURN_FRAME_CLASS` frame with `TURN_LEAD_CLASS` top padding, except the first turn and an outside call that follows an outside call (`thread.tsx:TurnFrame`); the viewport zeroes its `data-thread-list` gap and the estimator adds the same padding.
- Only the last of consecutive outside calls shows the assistant action bar, Copy only; it copies every call of that run as fenced `name(arguments)` blocks.
- `markdown.tsx:createBackend` returns `null` when `Worker` is undefined, so highlighting is skipped outside browsers.
- `now-line.tsx` and `morph-label.tsx` honor `(prefers-reduced-motion: reduce)`.

## Side Effects

- `markdown.tsx` starts an inline web worker (`highlight-worker.ts?worker&inline`) and posts `highlight` requests; `highlight-worker.ts` runs Shiki and posts results.
- `markdown.tsx` lazily imports `mermaid` and renders diagrams to SVG; it creates probe elements in `document` to read colors.
- `text-metrics.ts:createTurnEstimator` creates hidden DOM probes to measure text; `now-line.tsx` runs an interval timer for the spinner frames (`FRAME_MS` 90).
