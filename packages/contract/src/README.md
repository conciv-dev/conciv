# contract/src

## Overview

Defines the oRPC `contract` router between conciv core and its clients (auth, sessions, settings, drafts, markers, chat, registry, tabs, code, page, meta, skill, agent, fs, plugin, experimental, event) and the zod row schemas those procedures use. It also provides two client factories: a plain fetch client for node callers and a browser client. The browser client keeps one connection per engine api base in an Effect `RcMap` held on a `globalThis` pool: every procedure (one-shot calls and event-iterator streams) rides one socket to `${apiBase}/rpc-ws` through oRPC's `StandardRPCLink` over our own peer client. The connection is a pure machine (`engine-connection-machine.ts`, `transitionConnection`) and a scoped Effect driver (`engine-connection.ts`, `makeEngineConnection`) over `effect/socket`: each connection attempt is one run of the socket's reader, the machine owns the reconnect delays, open streams resubscribe after the socket comes back, and its open/close state is the reachability subscribers hear. `index.ts` re-exports `rows.ts`, `source-location.ts`, `contract.ts`, `client.ts`, `code-reply.ts` and `browser-transport.ts`.

## Interface

- `contract` (`contract.ts`): oRPC router with `auth{trust,exchange,requestCode,issueCode}`, `sessions{list,search,changes,get,preview,create,resolve,open,restore,rename,delete,model,effort,compact,switchHarness}`, `settings{all,set,delete,changes}`, `drafts{get,set}`, `markers{list}`, `chat{events,send,join,hydrate,stop,permissionDecision,uiReply}` (`events`, `send`, `join`, `settings.changes` and `sessions.changes` are eventIterators; `sessions.changes` yields `{version}`, the search index version, the current one first), `registry{catalog,call}`, `tabs{list,get}`, `location{get}` (opencode's `location.get`, `protocol/src/groups/location.ts`: the engine's folder and project), `code{describe,execute,discover}`, `page{queue{wait},changes,clearChanges}`, `editor{openFromFrames}`, `meta{models,harnesses,commands,tools,engine,hubAgents,connectHub,disconnectHub}`, `skill{list}`, `agent{list}`, `fs{find}`, `plugin{call,list,experimental,experimentalChunk}`, `experimental{persistentPty{create,remove,output,write,resize,inject}}`, `event{subscribe}` (opencode's `event.subscribe`, `protocol/src/groups/event.ts`: input `{types?}`, an eventIterator of `EventEnvelopeSchema`, the engine's one event stream; its first event is `server.connected`).
- `EventEnvelopeSchema` (`contract.ts`): the envelope of every event on `event.subscribe`, `{id, type, created?, durable?, data, location?, metadata?}`, not a typed union (ruling): the precise union is the SDK's type. `created` is optional because the source's `server.connected` has none (`protocol/src/groups/event.ts:27-35`). `durable` is the source's `{aggregateID, seq, version}`, carried by durable events (`session.deleted`, `session.instructions.updated`) and absent on ephemeral ones.
- `ChatHydrationSchema` / `ChatHydration`, `ChatPendingApproval` (`contract.ts`): chat hydrate payload (messages, activeRun, lastRun, pendingApprovals, interrupts, and `page` when the input carried a `limit`). `chat.hydrate` input takes an optional `limit` (positive integer) and `before` (the `page.cursor` of the newer window); `ChatHistoryWindow` is that pair.
- `sessions.preview` (`contract.ts`): read-only window of a native transcript. Input `{harness, nativeId, cwd?, before: cursor | null, limit: 1-100}` (`cwd` is an all-projects hit's own project, this project when absent); output `{messages, earlier: cursor | null}`, newest window first, `earlier` is the `before` for the window above it. The cursor is an opaque string the harness minted; a window may hold a few more than `limit` messages, since it starts on a whole turn. A missing, empty or unreadable transcript is `NOT_FOUND`.
- `ToolCommandSignatureSchema` / `ToolCommandSignature` (`contract.ts`): registry catalog entry (name, path, binding `server|client`, icon from `TOOL_ICON_KEYS`, label, mutating/reachable, approval `'ask'`, input/output schema, errors).
- `RegistryCallErrorName` (`contract.ts`): `UNKNOWN_TOOL`, `INVALID_ARGS`, `HANDLER_ERROR`, `APPROVAL_DENIED`.
- `EngineStalenessSchema` / `EngineStaleness` (`contract.ts`).
- `CodeExecuteResultSchema` / `CodeExecuteResult` (`contract.ts`): `code.execute` output, discriminated on `ok`: `{ok: true, result, logs, toolCalls}` or `{ok: false, error: {message, name?, code?}, logs, toolCalls}`; `toolCalls` are the ids of the tool calls the run made, in start order (the id each called tool gets as `ctx.id`). `CodeDescriptionsSchema` / `CodeDescriptions`: `code.describe` output `{execute, discover: string | null}`.
- `SessionMetaSchema` / `SessionMeta`, `SessionHitSchema` / `SessionHit` (`SessionMeta` plus `excerpt: string | null`, `matched: string[]`, `cwd: string | null` (the other project's cwd for a hit outside this project), `resume: string | null` (the shell command that resumes that hit in its own project) and `preview: NativeSessionRef | null` (the transcript the match came from, which after a harness switch is an earlier transcript, not the session's current `native`), the rows of a `sessions.search` page; `sessions.list` keeps `SessionMeta`), `PersistedAttachmentSchema`, `DraftRowSchema` / `DraftRow`, `MarkerKindSchema` (`'new' | 'compact'`), `MarkerRowSchema` / `MarkerRow`, re-exported `UsageSnapshotSchema` / `UsageSnapshot` (`rows.ts`).
- `RawFrameSchema` / `RawFrame`, `SourceLocSchema` / `SourceLoc`, `OpenSourceSchema` (`source-location.ts`): the one declaration of the source-location types; the plugin SDK re-exports the plain types from `@conciv/plugin/experimental/page`.
- `makeRpcClient(apiBase, {headers?, interceptors?})` -> `RpcClient` (`client.ts`): oRPC client over `RPCLink` at `${apiBase}/rpc` using `abortableFetch`, with oRPC's `ResponseValidationPlugin` and the caller's `interceptors` (oRPC's own `RPCLinkOptions['interceptors']`, copied into the link so the plugin's own interceptor never lands in the caller's array; they run outside the validation, so they see its `ValidationError`), so every answer is parsed against the contract's output schema (an engine of another version answering outside the contract fails with a `ValidationError`, never as unchecked data).
- `codeExecuteReply(result)` -> `CodeReply` (`code-reply.ts`): the one formatter from a `CodeExecuteResult` to MCP content, used by core's `/api/mcp` and the hub: `{result, logs}` as JSON text with images split out as image blocks, or the content parts with a `{logs}` part, or `{error, logs?}` with `isError`; every text is capped at 50000 characters to a `conciv:truncated` envelope keeping the first 4000. `cappedText`, `cappedValue` (a value whose JSON exceeds the cap becomes the truncation payload, images kept beside it; an unserializable one becomes `{error: 'value could not be serialized', reason}`) and `safeStringify` are the caps it uses, shared with chat and core.
- `engineTooOld(error)` (`client.ts`): true for an oRPC NOT_FOUND (an engine without the procedure) or a `ValidationError` (an answer outside the contract).
- `abortableFetch(request, init, {signal?})` (`client.ts`): fetch wrapper passing `signal ?? null`.
- `makeBrowserRpcClient(base | () => base | null, {session?, timings?})` -> `BrowserRpcClient {rpc, bound, bind, rebind, close}` (`client.ts`); types `RpcClient`, `RpcClientOptions`, `BrowserRpcClientOptions`, `BrowserRpcClient`.
- `browserRpcConnection(apiBase, tokenSource?, timings?)` -> `{link, trust, release}` (`browser-transport.ts`): holds the shared connection for a normalized api base and its `EngineConnectionTimings` (`timings` is merged over `defaultEngineConnectionTimings`; equal timings share one connection, different timings never share a socket) until `release()`; a token source given here is stored on the connection's trust and is the one every later `requestTrust()` asks; a trust observer keeps its handle for as long as it listens, so it never sits on a closed connection. `resetBrowserRpcConnection(apiBase)` reconnects the socket of every connection of that base now instead of waiting out the backoff and creates nothing when the base has no connection.
- `heldBrowserRpcLink(currentApiBase, session?, timings?)` -> `{link, release}` (`browser-transport.ts`): ClientLink that resolves the api base per call, puts `concivSessionId` in the call context, and holds the connection for the base it last called and its timings; `release()` lets it go, and a connection closes when its last holder releases it.
- `subscribeRpcReachability(apiBase, listener, timings?)` -> unsubscribe (`browser-transport.ts`). Every holder merges `timings` over `defaultEngineConnectionTimings` the same way, so holders with equal timings share one connection.
- `EngineConnectionTimings` / `defaultEngineConnectionTimings` (`engine-connection-machine.ts`): reconnect, open, call, auth and connection-loss timings, plus `offlineGraceMs` (default 1000), how long the engine stays offline before the app calls the connection lost.
- `EngineTrust` on every `BrowserRpcConnection.trust` (`browser-transport.ts`): the one trust owner per api base. `isTrusted()`, `status()` (`checking | trusted | untrusted | revoked | unreachable`), `subscribe(listener)` (the listener gets the new and the previous status), `requestTrust({storedOnly?})` (stored token first, then the connection's token source when the stored one is missing or refused, unless `storedOnly`; while a token source can still be asked, a refused stored or empty token changes no status: it is published only once the source token is refused too or the source gives none, and a `storedOnly` ask that is refused with a source set leaves the status as it was; a call while an ask is in flight gets that ask), `requestTrustWithToken(token)`, `requestTrustWithCode(code)` -> `{token} | {refused}`, `requestAuthCode({reissue?})`.
- `readMagicLinkCode()` / `forgetMagicLinkCode()` (`browser-transport.ts`): read `#conciv_otp=` with `URLSearchParams`, and strip it from the URL only once the engine has answered the exchange (a reload before then keeps the code and retries it).
- `LOGIN_CODE_PATTERN`, `ExchangeResultSchema`, `SOCKET_TRUST_FRAME`, `SocketTrustFrameSchema`, `ENGINE_TOKEN_MAX_LENGTH` (`contract.ts`).
- `RPC_UNBOUND_MESSAGE` = `'conciv core not connected yet'` (`browser-transport.ts`, re-exported from `client.ts`); types `RpcClientContext`, `SessionAccessor`, `BrowserRpcConnection`, `ReachabilityListener`.

## Invariants

- `sessions.rename` requires `title` of 1-120 characters and declares `NOT_FOUND`; `sessions.model` declares `NOT_FOUND` and `UNKNOWN_MODEL`; `sessions.effort` takes a `ReasoningEffortSchema` value or null and declares `NOT_FOUND` and `UNSUPPORTED_EFFORT`; `sessions.switchHarness` takes a non-empty `harnessId` and an optional non-empty `model` and declares `NOT_FOUND`, `UNKNOWN_HARNESS`, `UNKNOWN_MODEL` and `SESSION_RUNNING`; `meta.models` and `meta.commands` take a `sessionId`; `SessionMetaSchema` carries a nullable `effort` (`contract.ts`, `rows.ts`) and `lastRunAt: number | null`, the start of the session's newest run (null until it has run; search hits carry it through `SessionHitSchema`); `sessions.create` answers `{sessionId, session}` with the new row.
- `chat.stop` requires `runIds` to be non-empty strings; `chat.permissionDecision` and `chat.uiReply` declare `UNKNOWN_REQUEST` (`contract.ts`).
- The dev-server methods and `open` are the server plugin's, reached through `plugin.call`.
- `registry.call` requires a non-empty `name` and `input` as `record<string, unknown>`, and declares the `registryCallErrors` set (`contract.ts`).
- `ToolCommandSignatureSchema` applies `.catch(undefined)` to `icon` and `label` (invalid values become `undefined`); `errors` defaults to `[]` (`contract.ts`).
- `StreamChunkSchema` checks only that a chunk is a non-null object, then casts it to `ChatEvent` (`contract.ts`).
- `DraftRowSchema` requires `selectionStart` / `selectionEnd` to be integers >= 0 and maps null `attachments` to `[]`; `drafts.set` takes the whole row, `updatedAt` included, which the engine stores as sent (`rows.ts`, `contract.ts`). `MarkerRowSchema.afterMessageId` is the id of the message the marker follows, `null` before the first message (`rows.ts`).
- `BrowserRpcClient.bind` throws `conciv rpc client already bound` when a base is set and `conciv rpc cannot bind an empty api base` for `''` (`client.ts`).
- `heldBrowserRpcLink`'s `link.call` throws `RPC_UNBOUND_MESSAGE` when the current api base is null (`browser-transport.ts`).
- Connections are keyed by `normalizeApiBase` (origin + pathname without trailing slash, resolved against `location.href` when present), so equivalent bases share one connection (`browser-transport.ts`).
- Retry policy (`ClientRetryPlugin`): a call retries any failure that is not an `ORPCError` while its connection is open and its own signal is not aborted, so the error a call in flight gets when the socket closes is retried; a one-shot call retries `CONNECTION_LOSS_RETRY_DELAY_MS` = 250 apart until `CALL_DEADLINE_MS` = 3000 after it started (each try waits for its connection attempt, so the last can end up to one attempt later); a caller's own `context.shouldRetry` replaces the deadline and the `ORPCError` rule for its call, never the connection check: once the connection is closed the call stops retrying whatever the caller's predicate says; `auth.trust` is never retried (`retry: 0`); a contract event-iterator call (`getEventIteratorSchemaDetails` on its output schema) retries without a cap, each retry waiting for the socket to open again and resuming with oRPC's `lastEventId`; a closed connection is not alive and stops retrying.
- Answer deadline: `auth.trust`, `auth.exchange` and `auth.requestCode` each carry an `Effect.timeout` of 3 s, an answer deadline, so a call whose frame is sent but never answered on a socket that stays open rejects; every other call keeps the retry-only rule above and has no answer deadline (`answered`, `engine-connection.ts`).
- Known limit, answer deadline: an `auth.trust` that times out on a socket that stays open moves the status from 'checking' to 'unreachable', and only the next socket `open` (the machine's `ask-trust` on open from 'unreachable') or a Retry asks again. A self-healing re-ask would need a bounded retry, which is new per-connection state. Reconnecting the socket on the timeout was refused: a reconnect resets the machine's retry counter, so it would loop every `CALL_DEADLINE_MS` with no back-off and drops every one-shot in flight each time. The magic-link code is read once at mount (`startEngineLogin`); a mount that ended 'unreachable' leaves it in the URL until a reload.
- The socket link is oRPC's `StandardRPCLink` over our own peer client (`socketClient`, `browser-transport.ts`), with the send rules of oRPC's websocket link except two: a frame for a socket that is not open (connecting, closing or closed) reopens it when reconnects were stopped and waits for that connection attempt, then is sent on `open` or fails on `close` or when the connection is released; and an `ABORT_SIGNAL` frame for a socket that is not open is dropped, never sent on a later socket. A frame is written only while the machine says the socket is open, under the lock that applies the machine's transitions, so nothing is written on a socket the machine already saw close. The `close` event that always follows closes the peer and ends every call still in flight. Every failure the transport itself raises (a socket that is not open, a call ended by that close, a link with no api base bound yet) is an `engineUnreachable` error, which `isEngineUnreachable` tells apart from an engine's `ORPCError` and from any other error (`engine-connection.ts`). A request frame that cannot be encoded or sent rejects its call; any other frame that cannot be sent closes its own call with that error. A received frame that cannot be decoded is logged and closes every call in flight with the decode error, since it names no call the client can trust.
- The engine token lives in localStorage; a `SecurityError` (storage blocked) or `QuotaExceededError` leaves the token in memory only, and any other storage error is logged (`storageEffect`, `engine-connection.ts`).
- Trust is per socket: the socket sends `{type: SOCKET_TRUST_FRAME, token}` on every open before any queued call, and an `auth.trust` or `auth.exchange` that succeeds on the socket trusts that socket too. A `REVOKED_SOCKET_CLOSE_CODE` close stops the reconnects (the machine moves the socket to `closed`) and forgets the held token; the next call reopens the socket without it (`browser-transport.ts`). Every socket `open` asks trust again from `unreachable` (stored token, then the connection's token source), so only a page whose own ask went unanswered asks again on open; a page that never asked stays `checking`, one ask in flight per connection, cleared when it settles or the connection closes. An `auth.trust` answered with a 401 is a refusal of the token it carried, as `{trusted: false}` is (`untrusted` for no token, `revoked` for a held one), never a missing answer. A trust ask that gets no answer sets `unreachable` only from `checking`: a connection that drops after an answer keeps its status, and the lost-connection notice is reachability's.
- The token is stored under `conciv:engine-token:<normalized api base>` in localStorage; an `UNAUTHORIZED` reply, an `UNAUTHORIZED` error on an open event-iterator stream, or a 1008 close for the token currently held forgets it and sets `untrusted` / `revoked`, a refusal for an older token is ignored (`browser-transport.ts`).

## Side Effects

- Holds one connection per normalized api base in the `RcMap` of `globalThis.__concivBrowserRpcConnectionsV7`, shared across bundle copies (`connectionPool` in `browser-transport.ts`); connections for different bases live side by side. Each connection counts its holders (`browserRpcConnection` handles, `subscribeRpcReachability` subscriptions, and `heldBrowserRpcLink`, so every `makeBrowserRpcClient`): it closes and leaves the map when the last holder releases it (the last release closes its `Scope`). Trust status and reachability votes are signals on each connection's `PubSub`; `subscribeRpcReachability` holds the connection for its base until it unsubscribes, and a vote only dispatches while its connection is still open.
- HTTP calls to `${apiBase}/rpc` through the fetch `RPCLink` (`makeRpcClient` in `client.ts`, node callers only); the browser opens one WebSocket to `${apiBase}/rpc-ws` per connection attempt (`connectAttempt` in `engine-connection.ts`): delays 0, then 250 ms growing 1.3 times per failed attempt up to 2 s, reset after 1 s up; an open that takes 30 s is given up.
- Adds the `CONCIV_SESSION_HEADER` header (from `@conciv/protocol/chat-types`) to a socket call when the context has `concivSessionId` (`sessionHeaders`, `engine-connection.ts`).
- `makeRpcClient` is the node client and sends `CONCIV_VERSION_HEADER` (`x-conciv-version`, from `@conciv/protocol/rpc-types`) set to the contract package.json version; browser code uses the socket link (`makeBrowserRpcClient` / `heldBrowserRpcLink`).
- Reads `location.href` when defined (`normalizeApiBase`).
- Calls reachability listeners with `true` when the socket opens and `false` when it closes for any reason but a revocation (`engine-connection.ts`).
- `rebind` / `close` release the client's hold on its previous base; the shared connection closes only when no other client holds it (`heldBrowserRpcLink`).
