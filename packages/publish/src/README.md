# publish/src

## Overview

The `conciv-publish` citty command tree. It runs release guards (workspace root, changesets, public package set, catalog usage, changeset coverage), versions and publishes through changesets and turbo, reconciles npm with `PUBLIC_PACKAGES` (first publish, trusted publishing, git tags), and mirrors `native/swift` into the `conciv-dev/conciv-swift` repository.

## Interface

- Subcommands of `conciv-publish` (`cli.ts`): `version`, `check-changesets` (`--require-coverage`, `--base <ref>`), `check-catalog`, `check-typecheck-coverage`, `check-test-budget`, `check-turbo-depends-on`, `check-dependency-loops`, `check-plugin-ui-kit`, `check`, `release`, `snapshot` (positional `tag`, default `beta`), `sync` (`--dry-run`, `--json`, `--verbose`, `--log-level <level>`), `swift-mirror` (`--dry-run`).

## Invariants

- `check-turbo-depends-on` checks that no `turbo.json` task depends on a `<package>#<task>` edge (root `//#` tasks aside) and no package `build.dependsOn` leaves out `^build`, and that each `typecheck` waits for the build of every package whose dist it reads, also a dist read only through another package's built d.ts (`assertTasksDependOnUpstreamBuilds`, `assertTypeTasksDependOnDistReads`, `workspace-imports.ts`).
- `check-dependency-loops` allows no loop between workspace packages, counting every edge: `dependencies`, `devDependencies`, `peerDependencies` and `optionalDependencies`. Each loop prints as its package path with the field of each edge (`assertNoDependencyLoop`).
- `atRoot()` uses `process.cwd()`; `assertWorkspaceRoot` throws `conciv-publish must run at the workspace root ...` unless cwd contains `pnpm-workspace.yaml` and `.changeset` (`cli.ts`, `guards.ts`).
- Dist-tags match `/^[a-z][a-z0-9-]*$/` (`assertValidTag`); package names match `/^@conciv\/[a-z][a-z0-9-]*$/` (`assertValidPackageName`).
- Non-private packages must not be at `0.0.0` at release (`assertVersioned`). `assertBootstrappable` requires a package in `PUBLIC_PACKAGES`, present in the workspace, not private, not `0.0.0`.
- Every changeset `.md` (except `README.md`) names at least one release, every named package exists, and the file is not a symlink (`assertChangesetsResolve`, `parseChangesetPackageNames`, `assertNotSymlink`).
- `--require-coverage` requires `--base`. Changed code in a published package, or in a workspace package with published transitive dependents, needs an added changeset naming a published package (`assertPublishedChangesCovered`).
- Coverage ignores `test/`, `*.test.*` and `*.spec.*`; files in the package's `files` allowlist always count; otherwise only extensionless files or `CODE_FILE_EXTENSIONS` count (`guards.ts`).
- The set of non-private `@conciv/*` packages must equal `PUBLIC_PACKAGES` (`assertPublicSet`); every `@internal/*` package must stay private (conciv's own builds inline them) and `assertPublicSet` names one when it is not; public packages must not depend on private workspace packages in dependencies, optionalDependencies or peerDependencies (`assertPublicDepsPublic`); and after the build no d.ts a public package's `exports` reach, following relative imports between d.ts files, imports a private workspace package, and no d.ts a named (non-wildcard) export points at, or that one re-exports with `export *`, exports a name the bundler generated (`*_exports` namespace helpers, `__` runtime helpers) (`assertPublicTypesPublic`, run by `check`, `check-public-types` in CI repo checks, `release`, `snapshot`, and `sync` before a first publish). A d.ts no export reaches is never loaded by a consumer, so it may name one.
- An external dependency used by two or more manifests (root included) must use `catalog:` (`guards.ts`).
- Every workspace package with tracked TypeScript files either has a plain-JSON `tsconfig.json` that extends `@internal/tsconfig/*` or is named in `OFF_PRESET_PACKAGES` (`typecheck-coverage.ts`: today's framework-owned e2e and example apps and `native/swift`); a listed package that moves onto the preset is reported so the list shrinks. A listed package still has its `test/` files and `playwright.config.ts` (the repo's own files inside a framework scaffold) in the program of a tsconfig its `typecheck` script runs; the e2e apps do it with `tsconfig.e2e.json`. A preset package sets no `include`, `exclude` or `files` in `tsconfig.json`, `tsconfig.build.json` or any tsconfig its `typecheck` script runs (the preset owns them), and every git-tracked `.ts`/`.tsx`/`.mts`/`.cts` file it owns is in the program of a tsconfig that script runs with `tsc -p <tsconfig>` (bare `tsc` means `tsconfig.json`), read from `tsc --listFilesOnly`; `--showConfig` would drop the files an inherited `${configDir}` include matches under TypeScript 6. TypeScript 7 ships no `readConfigFile`, so preset tsconfigs are read with `JSON.parse`.
- `check-test-budget` counts the test cases of every git-tracked `*.test.*`/`*.spec.*` JS or TS file outside a `fixtures/` folder, per owning workspace package, with `oxc-parser`, so a comment or a string never counts. A case is a call of `test`, `it` or a name bound to `test.extend(...)`/`it.extend(...)`, through `concurrent`, `sequential`, `skip`, `only`, `todo`, `fails`, `fail`, `fixme`, `each`, `for`, `skipIf` and `runIf`; a curried form (`test.each(table)(...)`) counts once, and `describe`, `use`, `step` and hooks never count. A package over its `test-budget.json` number (0 when absent) fails, naming the package, its count and its budget; one under it prints a note to lower the number (`test-budget.ts`). RuleTester cases (`packages/oxlint-plugin`) are entries of `tester.run`, not calls, so they are not counted.
- Turbo order comes from real dependencies alone: a task in the root or a package `turbo.json` depends on no `<package>#<task>` (root `//#` tasks aside), and a package `build.dependsOn` keeps `^build` (`workspace-imports.ts`). An import missing from `package.json` is fallow's unlisted-dependency finding.
- A plugin package under `packages/plugins/` draws through `ctx.ui` (conciv's own plugins read conciv's members with `OpaqueUi.toInternal`): no build source (git-tracked `src/**` and root `vite.config.*` and `tsdown.config.*`, minus `test/`, `__tests__/`, `*.test.*`, `*.spec.*`, `*.stories.*` and `*.fixtures.*`; imports are `from`, `import`, `import()`, `import.meta.resolve()` and `require()` specifiers) imports a `@conciv/ui-kit*` package, and its `package.json` names none in `dependencies`, `devDependencies`, `optionalDependencies` or `peerDependencies`. The only exceptions are the built-ins `@conciv/plugin-page` and `@internal/plugin-terminal` (`KIT_BUILT_INS`), which draw with the kit directly (`workspace-imports.ts`).
- Every published package that runs in node declares the same `engines.node`, of the form `>=X.Y.Z` (`readFloor`, `node-floor.ts`); `check-node-floor` refuses a `--node` binary older than that floor. It imports every `exports` subpath of those packages except the entries that are not node code, named in `NOT_NODE_ENTRIES` (browser parts, the `plugin-experimental` bundles the app evaluates, and `@conciv/backend-test-utils`, which needs a running vitest): a new non-node entry is added there by name.
- `pnpm-workspace.yaml` must be a mapping with a string-array `packages` (`readWorkspaceGlobs`); each package.json must pass `manifestSchema` (`workspace.ts`).
- Registry: `trusted` means `latest` has `_npmUser.trustedPublisher`; 404 means `missing`; other non-OK statuses throw (`sync.ts`).
- Sync plan: `publish` iff missing, `trust` iff not trusted, `tag` iff the local version exists on npm (or the package is missing) and git tag `name@version` does not exist (`sync.ts`).
- The Swift version must be bare semver (`BARE_SEMVER`); the release commit is found with `git log -S` and needs full history (`swift-mirror.ts`). `swift-mirror` requires `GH_MIRROR_TOKEN`, and an existing tag must match the assembled tree (`withMirrorAuth`, `assertTaggedTreeMatches`, `cli.ts`).

## Side Effects

- Spawns `pnpm exec changeset ...`, `pnpm exec turbo run ...`, `pnpm install --lockfile-only` with inherited stdio through execa (`cli.ts`).
- Publishes to npm: `changeset publish`, and `pnpm --filter <name> publish --access public --no-git-checks` (`firstPublish`).
- `sync` checks every package to first-publish with `assertBootstrappable`, builds them all in one `turbo run build publint attw` with a `--filter` per package, and publishes nothing if that run fails (`applySyncPlan`).
- `sync` runs `npm whoami` first, in every mode including `--dry-run`. A package the registry reads `untrusted` (its trust was wired by hand but no CI-published version exists yet) counts as trusted when `npx --yes npm@^11.15.0 trust list <name> --json` lists a config naming `conciv-dev/conciv` and `release.yml`; the plan and the healthy count reflect that (`gatherSyncStates`). Only packages with no such config get `npx --yes npm@^11.15.0 trust github <name> --repo conciv-dev/conciv --file release.yml --allow-publish` (`wireTrust`); a package's trust setup runs after its own first publish.
- npm calls in `sync`: a call that can ask the user (first publish, trust setup) runs on the real terminal through `atRoot`'s `run` (stdin and stderr inherited, stdout the terminal, or stderr with `--json`), one package after another, so npm shows its 2FA QR code and browser link and waits (`npmOnTerminal`). Only the trust list read captures its output, since sync parses it; it runs 8 at a time and its arguments are fixed, so no other npm call can be captured (`readTrustList`). A read that fails counts as no trust config. A trust setup that fails is checked again with that read and counts as done when the config is there, so a read that failed while planning does not end in npm's 409. A call that still fails fails only its package; the others go on, and sync exits non-zero naming the failed packages without pushing tags. Rerunning is idempotent.
- `sync` output (the npm user, one line per package result, the plan, the healthy count) is plain stdout. With `--json`, stdout holds only the JSON: those lines go to the logger at info, and the child processes sync runs (turbo, changeset) write their stdout to stderr. Diagnostics (each npm command, its duration, captured npm output) are `Effect.log*` calls that one Effect `Logger` forwards to evlog, JSON on stderr, at the level chosen as `@conciv/cli` chooses it: `--log-level`, then `--verbose` (debug), then `CONCIV_LOG_LEVEL`; unset or invalid is `off` (`log.ts`).
- `fetch('https://registry.npmjs.org/<name>')` (`registryRecord`).
- Git: `git diff --name-status --no-renames <base>...HEAD` (`guards.ts`); `git ls-files` and `tsc -p <tsconfig> --listFilesOnly` per package (`typecheck-coverage.ts`); `git ls-files` per plugin package (`workspace-imports.ts`); `git ls-files` (`test-budget.ts`); `git tag -l`, `git tag`, `git push origin refs/tags/...` (`sync.ts`); `pnpm exec changeset git-tag` (`cli.ts`); `git log -S` and `git archive | tar -x` (`swift-mirror.ts`).
- `check-node-floor` (`node-floor.ts`) creates and removes a temp dir `conciv-node-floor-*`: it runs `pnpm pack` in every published package, writes a consumer `package.json` (the tarballs, plus every non-conciv peer at its catalog version) and a `pnpm-workspace.yaml` overriding each `@conciv/*` to its tarball, runs `pnpm install --ignore-scripts --prefer-offline` there, then runs the given Node binary on the cli's `--help`, on one `import()` per node entry (4 at a time), and on a script that starts the engine with `CONCIV_SIMULATE=1` and `HOME` in the temp dir, creates a session and lists it over the rpc.
- Creates and removes temp dirs `conciv-askpass-*`, `conciv-swift-src-*`, `conciv-swift-*`, `conciv-swift-tag-*`; writes a `0o700` `askpass.sh` that prints `$GH_MIRROR_TOKEN` (`cli.ts`).
- `assembleMirrorTree` deletes then copies `Package.swift`, `Sources`, `Tests`, `README.md`, `RELEASE_HYGIENE.md`, `LICENSE` into the destination (`swift-mirror.ts`).
- Pushes to `https://x-access-token@github.com/conciv-dev/conciv-swift.git` (`push --force origin main`, `push origin <tag>`) with `GIT_ASKPASS` and `GIT_TERMINAL_PROMPT=0`; commits as `conciv-swift-mirror <noreply@conciv.dev>` (`cli.ts`).
- Reads `pnpm-workspace.yaml`, scans for package.json files (skipping dot dirs and node_modules) (`workspace.ts`), and reads `.changeset/*.md` (`guards.ts`).

## Verification

- Run: `pnpm exec turbo run test --filter=@internal/publish` from the repo root (turbo builds the package and its dependencies first)
