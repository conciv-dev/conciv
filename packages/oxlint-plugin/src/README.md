# oxlint-plugin rules

## Overview

The oxlint JS plugin `conciv`: `plugin.js` registers the rules. A rule with its own concern and real size lives in its own file; the small one-concern rules (`no-delegated-focus`, `tool-card-shell`, `solid-test-render`, `user-event-only`) live in `plugin.js` itself, the two timing rules (`no-timers-in-tests`, `no-inline-timeouts`) in `test-time.js`, and the three vocabulary rules (`banned-vocabulary`, `core-purity`, `no-of-suffix`) live in `vocabulary.js` beside the matcher they share. Rules use oxlint's `createOnce(context)` visitor API, and `ast-walk.js` holds the generic AST walker.

## Invariants

- `no-comments.js:default` reports every comment except directives matched by `DIRECTIVE_RE` (`eslint-`, `oxlint-`, `@ts-`, `@__PURE__`, `prettier-ignore`, `@license`, `sourceMappingURL` and others) and autofixes by removing it.
- `no-locator-poll.js:WEB_FIRST_REPLACEMENTS` maps a locator read inside `expect.poll` (`textContent`, `isVisible`, `count`, `getAttribute`, `inputValue` and others) to the web-first assertion to use instead.
- `no-predicate-waits.js:default` flags an exported declaration whose parameter type is a function returning `boolean`, a boolean union or `Promise<boolean>` (`BOOLEAN_TYPE_CHECKS`).
- `test-time.js:TIMER_NAMES` (`no-timers-in-tests`) (`setTimeout`, `setInterval`, `setImmediate`) are reported wherever referenced, except as a member object or a non-computed property key; the rule has no filename filter and relies on config scoping.
- `no-signal-ref.js:default` flags a `createSignal` whose setter is only used as `ref={setter}` and whose getter is never read from a reactive scope.
- `no-inner-html.js:default` reports a string of HTML written into the page: an assignment (also `+=` and a computed string key) to `innerHTML` or `outerHTML` (`HTML_PROPERTIES`), a call of `insertAdjacentHTML` on anything or of `document.write`/`document.writeln`, and a JSX `innerHTML`/`outerHTML` attribute (Solid's prop). Reading `innerHTML`/`outerHTML` is not reported. React's `dangerouslySetInnerHTML` is oxlint's own `react/no-danger`. Both are enabled for the whole repo (`.oxlintrc.json`).
- `no-suppress-hydration-warning.js:default` reports the JSX attribute `suppressHydrationWarning` (any value) and any non-computed object key of that name (a spread object literal, a `createElement` props object): a hydration mismatch is fixed, never hidden. Enabled for the whole repo (`.oxlintrc.json`) with one exception, a file-scoped override for `apps/site/src/routes/__root.tsx` (maintainer ruling): the site's `<html>` keeps the attribute because fumadocs' theme (next-themes) writes `class` and `style.colorScheme` on `<html>` from a script before hydration, and the prerendered site cannot render the visitor's theme on the server. No other file may use it.
- `router-idioms.js:default` reports bare `useSearch`/`useNavigate`/`useParams`/`useLoaderData` imports in files matching `ROUTE_FILE` (`src/routes/`), `useRouterState` selects that read `matches`, and `validateSearch` / `*SearchSchema` zod fields without `.catch(...)`.
- `solid-test-render` (`plugin.js`) reports `render`/`hydrate` imported from `solid-js/web` in files matching `TEST_FILE`, except `RENDER_EXEMPT_FILE` (`test/fixtures/host/main.tsx`).
- `no-delegated-focus` (`plugin.js`) reports a JSX attribute whose lowercased name is `onfocusin` or `onfocusout` (`DELEGATED_FOCUS`): Solid delegates those to the document, so they never run for a focus move inside a shadow root. Enabled for `packages/ui-kit-*/src/**` and `packages/frontend-defaults/src/**` (`.oxlintrc.json`).
- `no-forced-click.js:default` reports, in a test or spec file, `force: true` in the options of a `click` or `dblclick` call (kit input, user-event, Playwright locator). `rm`/`rmSync` and other calls with a `force` option are not reported. The maintainer-approved forced clicks (the element picker, which turns page pointer events off while it picks) carry an `oxlint-disable-next-line` for this rule.
- `no-hand-made-temp-dir.js:default` reports, in files matching `TEST_FILE`, under `e2e/` (`E2E_FILE`) or under `packages/*-test-utils/src/` (`TESTKIT_SOURCE`), outside `packages/vitest-config/src/` (`HELPER_FILE`), an fs call imported from `FS_SOURCES` (`node:fs`, `node:fs/promises`, `fs`, `fs/promises`; named or through the module object) that creates a path (`CREATED_PATH_ARGUMENT`: the first argument of `mkdtemp`, `mkdir`, `writeFile`, `appendFile`, the destination of `cp`, `copyFile`, `symlink`, each with its `Sync` twin) built on the OS temp dir: a `tmpdir()` call, `process.env.TMPDIR` or a `/tmp` string, directly or through the initialiser of one `const` in the same file (one hop, no further data flow). The message names the alternative for the place: in a test `tempDir(prefix)` and, for vitest configs and browser commands, a folder under the package's `test-results/conciv-home`; in `e2e/` the app run state folder `e2e/.conciv-e2e/<app>` (or the e2e config's `runFolders`) that the shared state cleanup reporter removes; in a test-utils source a folder the caller owns and passes in. Reading from the temp dir, passing it as a `cwd`, and `rm` are not reported. In those files and in `vitest.config.*` / `playwright.config.*` (`CONFIG_FILE`) it also reports `process.on('exit', ...)` / `process.once('exit', ...)` on the undeclared global `process` (`exitHook`), the cleanup a crashed or killed run can skip. Kept sites carry an `oxlint-disable-next-line` with a reason or an exclusion in `.oxlintrc.json`.
- `tool-card-shell` (`plugin.js`) reports a `CollapsibleCard` import from `@conciv/ui-kit-chat` (`KIT_SOURCE`) in any file outside `packages/ui-kit-chat/` (`KIT_FILE`).
- `no-query-existence-assert.js:default` reports, in `test/unit` and `test/e2e` test files (`DOM_TEST_KINDS`) and in any file importing `@solidjs/testing-library` or a `@testing-library/*` package, an `expect(X)` whose matcher only says the node exists, where X is a Testing Library query call (`QUERY_NAMES`: `getBy`, `getAllBy`, `queryBy`, `queryAllBy`, `findBy`, `findAllBy` with `Role`, `LabelText`, `PlaceholderText`, `Text`, `DisplayValue`, `AltText`, `Title`, `TestId`; bare, on `screen.`, on `within(...).` or any other object), its `await` or `as` cast, or a `const` bound to one. The matchers are `EXISTENCE_MATCHERS` (`toBeDefined`, `toBeUndefined`, `toBeNull`, `toBeTruthy`, `toBeFalsy`, `toBeNil`, `toBeNullable`, with or without `.not`), `toBe(null)` / `toEqual(null)` / `toStrictEqual(null)`, `toHaveLength` on a single (not `AllBy`) query, and a non-negated `toBeInTheDocument` on a `getBy`/`getAllBy`/`findBy`/`findAllBy` query (the query already threw if nothing is there); `toHaveLength` on an `AllBy` query, and `toBeInTheDocument` / `.not.toBeInTheDocument` on a `queryBy`/`queryAllBy` query, are not reported. The case list is eslint-plugin-jest-dom's `prefer-in-document` (plus `toBeUndefined`, `toStrictEqual(null)` and `toBeInTheDocument` on a throwing query); the message names the jest-dom matchers to use instead, and `.not.toBeInTheDocument()` on a `queryBy` only for absence. No autofix. Enabled for test files in `.oxlintrc.json`.
- `user-event-only` (`plugin.js`) reports, in `test/unit` test files (`isDomTestFile`), a `fireEvent` import (named or aliased) from `TESTING_LIBRARY_SOURCES` (`@solidjs/testing-library`, `@testing-library/dom`), and a `.fireEvent` read on a namespace or default import of those sources; the message sends the test to `userEvent.setup()` from `@testing-library/user-event`.
- `lucide-per-icon.js:default` reports value imports from the `lucide-solid` barrel; it autofixes only when every per-icon path resolves, else reports `barrelImportUnresolved` without a fix.
- `test-file-budget.js:default` checks the test layout of every package its globs name, skipping files under `test/fixtures/`: the package lacks one of `test/unit`, `test/it`, `test/e2e`, `test/fixtures`, `test/utils` (`missingFolders`, reported on the first sorted code file); a `*.test.*` or `*.spec.*` file is outside `test/unit`, `test/it` and `test/e2e` (`outsideLayout`); its name kind (`.unit.test`, `.it.test`, `.e2e.test`) is not its folder (`wrongKind`, read with `readTestKind` from `@internal/vitest-config/test-layout`); it is over 1,000 lines (`tooLong`); the package has more test files than `src` source files (`overSources`, reported on the first sorted test file). Walking skips `IGNORED_DIRECTORIES` and nested packages.
- `bannedVocabulary` (`vocabulary.js`) exempts whole files listed in `PREEXISTING_MODULES` and allows specific terms at paths in `PREEXISTING_TERM_SITES`.

## Side Effects

- `lucide-per-icon.js:tryResolve` resolves `lucide-solid/icons/<name>` from disk with `createRequire(filename).resolve` and caches results per directory.
- `test-file-budget.js:packageFiles` reads the package tree with `readdirSync`/`existsSync` and caches it per package in `filesByPackage`; `displayDirectory` reads `process.cwd()`.
- All other rules are pure AST visitors with no I/O.
