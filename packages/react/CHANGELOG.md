# @conciv/react

## 0.0.25

### Patch Changes

- [#1217](https://github.com/conciv-dev/conciv/pull/1217) [`74d3b55`](https://github.com/conciv-dev/conciv/commit/74d3b550f749a7beb5fade7d735d7a41caf8ad41) Thanks [@omridevk](https://github.com/omridevk)! - Every library builds with tsdown, as devframe builds its packages; Vite builds only the app bundles (the widget, the
  shell and the plugins' `./plugin-experimental` bundles). A library's `dependencies` and `peerDependencies` stay
  external, so some kits now import packages they used to bundle. `@conciv/unplugin` depends on `@conciv/protocol`.

- [#1214](https://github.com/conciv-dev/conciv/pull/1214) [`1173bd1`](https://github.com/conciv-dev/conciv/commit/1173bd1df39283754eae2b9e3f420ba33777941a) Thanks [@omridevk](https://github.com/omridevk)! - Works on Node 22 and later (22.16 or newer, the first 22.x with the `node:sqlite` APIs the engine uses). Node code builds for node22, and `Promise.try` and `URL.parse`, which Node 22 lacks or added late, are not used.

- [#1212](https://github.com/conciv-dev/conciv/pull/1212) [`1237734`](https://github.com/conciv-dev/conciv/commit/1237734bce516783f7dbc4f40e6ef2c8fba4765d) Thanks [@omridevk](https://github.com/omridevk)! - Every package builds with Vite: one shared library build in `@internal/vite-config` (Vite environments, `rolldown-plugin-dts` for the declarations). tsdown and the separate `tsc` declaration step are gone. Libraries with several entries ship one file per module, so no declaration chunk sits outside `exports`. `experimental()` configures only the `client` environment.

## 0.0.23

### Patch Changes

- [#1029](https://github.com/conciv-dev/conciv/pull/1029) [`6bca3ec`](https://github.com/conciv-dev/conciv/commit/6bca3ecc90ec1e16be822cf759f39e9a7e7d9fce) Thanks [@omridevk](https://github.com/omridevk)! - Hosts no longer pass the terminal extension: the Terminal panel is built into every widget. The example apps, the framework components' docs and the install guide drop `@conciv/extension-terminal`.

- [#1193](https://github.com/conciv-dev/conciv/pull/1193) [`35e9999`](https://github.com/conciv-dev/conciv/commit/35e9999ccf358fae142e6d521e0f795ad10862b4) Thanks [@omridevk](https://github.com/omridevk)! - Plugin UI in any framework, as TanStack Devtools: `mountRender(mount)` in `@conciv/frontend-plugin-api` turns a framework-free `(element, props) => cleanup` mount into the render every registry takes. `reactRender(Component)` in `@conciv/react` and `preactRender(Component)` in `@conciv/preact` draw a component as a panel, settings page, slot, composer pill menu, code block or tool card, through a portal inside `<ConcivWidget/>`'s tree, so the host app's providers reach it and its props stay live. `@conciv/react` now needs React 18 or later.

- [#1121](https://github.com/conciv-dev/conciv/pull/1121) [`8f7fcbd`](https://github.com/conciv-dev/conciv/commit/8f7fcbd4b15811e5d5580e49a23be47be0e81b2b) Thanks [@omridevk](https://github.com/omridevk)! - The widget no longer mounts old SDK extensions. Their panel views, view lock, status, composer and empty slots, slash commands, tool cards, attachment cards and page-level `Surface` are gone, and so are the Views settings tab (with its hide, pin and order preferences and Reset views) and the generated extension settings pages (with Reset extension settings). Plugins add that UI through the plugin registries.

  `createConciv` no longer takes `extensions` (`ConcivInit.extensions` and the `ExtensionsInput` type are removed), and `mountConciv(plugins?)` takes plugin entries as its only argument. The React, Preact and Solid wrappers drop their `extensions` prop. The `virtual:conciv-extensions` module from `@conciv/extension-compiler` mounts the widget with no extensions, and the package drops its `./dedupe` export and the server-side extension loaders.

- [`0bc80ef`](https://github.com/conciv-dev/conciv/commit/0bc80ef1b0ded255ab9e66a84baf6b5724f2d59f) Thanks [@omridevk](https://github.com/omridevk)! - The wrapper components pass plugins, grabProvider and engineToken through.
