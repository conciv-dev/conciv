# core/src/api/rpc

## Overview

oRPC router that implements the `@conciv/contract` procedures for sessions, chat, drafts, markers, navigation, registry, captures, page, server, editor, meta and plugin. `mount.ts` defines the base `os` builder and a session-scoped middleware that resolves the caller's session from a header.

## Interface

- `makeRpcRouter(deps)` (`router.ts`): builds the full router
- RPC `sessions.list`, `.preview`, `.create`, `.resolve`, `.open`, `.restore`, `.rename`, `.delete`, `.model`, `.effort`, `.compact`, `.switchHarness` (`sessions.ts`, `sessionsRouter`)
- RPC `chat.events` (streaming), `chat.hydrate`, `chat.stop`, `chat.permissionDecision`, `chat.uiReply` (`chat.ts`, `chatRouter`)
- RPC `settings.all`, `settings.set`, `settings.delete`, `settings.changes` (streaming) (`router.ts`): one `{scope: 'global' | 'project', namespace}` settings file each, every answer the full `{generation, version, value}` snapshot
- RPC `drafts.get`, `drafts.set`, `markers.list`, `navigation.get`, `navigation.set`, `captures.list` (`router.ts`)
- RPC `registry.catalog`, `registry.call` (`router.ts`)
- RPC `page.symbolicate`, `page.changes`, `page.clearChanges`, `page.queries` (streaming), `page.reply` (`router.ts`)
- RPC `page.queue.wait({sessionId, queueId, waitMs})` (`router.ts`): the queue store's `wait`, a queue result (marked delivered) or `{status: 'playing', done, of}`; NO_QUEUE for a queue this tab does not have
- RPC `tabs.list`, `tabs.get({sessionId})` (`router.ts`): `createTabs` (`../tabs.ts`)
- RPC `code.describe`, `code.execute({sessionId?, typescriptCode})`, `code.discover({sessionId?, toolNames})` (`router.ts`): `openCodeSession` (`../mcp.ts`), the same function `/api/mcp` runs; without `sessionId` a hub-origin call is the outside run; NO_CODE_MODE when the engine has no code runner (or, for `code.discover`, no discover tool)
- RPC `server.config`, `.resolve`, `.graph`, `.transform`, `.urls`, `.reload`, `.restart` (`router.ts`): each calls the matching `BUILTIN_SERVER_TOOLS` entry
- RPC `editor.open`, `editor.openFromFrames` (`router.ts`)
- RPC `meta.models` and `meta.commands` (per session: the session's harness), `meta.harnesses` (the available set, each harness with its models and default model, and the default harness), `meta.tools`, `meta.engine` (`router.ts`); `meta.hubAgents` is an event iterator of `{installs, connections}` (found harnesses with a `hub` that are not connected, and the connected ones, each `{harnessId, name}`) from PATH detection and the home db only, no model listing and no spawning: it yields the current pair, then watches the conciv home folder and yields again whenever `home.db` or its WAL changed on disk and the pair differs, so a connect or disconnect from the CLI or another engine reaches the widget as a push (the home folder is created if missing so it can be watched; the db is not); and `meta.connectHub` / `meta.disconnectHub` call `createHubInstaller` (`hub.ts`), a thin caller of `createHubConnections` (`@conciv/harness-init/hub`) whose connect installs `npx -y @conciv/cli@<core version> mcp serve --agent <harness>` and whose disconnect forgets the row and bumps the home's hub generation, then removes the CLI entry best-effort; `generation()` feeds the chat plane's `hubGeneration`, so every outside Allow granted under an older generation asks again (an unreadable home db gives a null generation: no Allow admits and none granted then ever admits)
- RPC `plugin.call({rpcId, method, input?})` (`router.ts`): runs `Rpc.call` of `@conciv/plugin-host` on the plugin host runtime (`RpcDeps.pluginHost`) and answers the method's output; any failure is the one typed error PLUGIN_RPC whose data is opencode's `{type, message, data?}` (a system failure `rpc.unavailable`, `rpc.method_not_found`, `rpc.invalid_input`, `rpc.invalid_output`, `rpc.internal`, or the method's declared error); a defect outside the handler is logged and becomes `rpc.internal`. Callers build the typed client with `makeRpc` of `@conciv/plugin`
- RPC `plugin.events({rpcId, types?})` (`router.ts`): an event iterator of the contract's RPC event envelopes, `Bus.subscribe` bridged through oRPC's `EventPublisher`; with `types`, one `Rpc.eventDefinition('rpc.<rpcId>.<name>')` each, without, every bus event whose type starts with `rpc.<rpcId>.`
- `PAGE_ERROR_NAME` (`router.ts`): PageErrorCode to NO_PAGE_CLIENT, PAGE_TIMEOUT, UNKNOWN_TOOL, INVALID_ARGS, HANDLER_ERROR
- `os`, `makeSessionOs`, `makeHubAdmission`, `callerScope`, `RpcDeps`, `ChatContext`, `SessionOs`, `CompositeRpcRouter` (`mount.ts`)

## Invariants

- `headerSessionId` / `callerScope` (`mount.ts`): a malformed session header throws BAD_REQUEST; a missing one on a session-scoped procedure throws BAD_REQUEST too, so a 401 only ever means the login gate refused
- `registry.call` (`router.ts`): answers the session's registry tools and the conciv assist tools (`deps.assist`, e.g. `conciv_ui`), UNKNOWN_TOOL for any other name; page errors map through `PAGE_ERROR_NAME`, a tool's declared error (`toolError`) keeps its code and message, any other thrown error is HANDLER_ERROR with its message
- `makeSessionOs` / `makeHubAdmission` (`mount.ts`; `app.ts` also wraps every mounted extension router in `makeHubAdmission`, so `ext/*` procedures naming a session pass the same consent): every hub-origin request (`conciv-origin: hub`) is refused first with APPROVAL_DENIED when `deps.hub.refusal(client)` names the calling agent as disconnected (a harness id with no connection row in the conciv home db; `terminal` and unknown clients pass), whatever `hubAccess` says; one that names a session, by the session header or by an input `sessionId`, then passes `deps.admitOutside` for that session (which holds the call up to 50 s for the user's Allow, and stops waiting when the request aborts) and throws APPROVAL_DENIED on refusal, and once the Allow lands the disconnected check runs again, so an Allow clicked after a disconnect still refuses; hub-origin requests that name no session (catalog, list, create, resolve) skip the consent prompt, and non-hub requests run unchanged; a hub-origin `chat.permissionDecision` or `chat.allowOutside` is always refused with APPROVAL_DENIED ("outside agents can't answer permission requests; decide it in the tab"), whatever the consent state, before any consent prompt; a hub-origin `meta.connectHub` or `meta.disconnectHub` is always refused the same way ("outside agents can't connect or disconnect agents; do it in the tab"), so an outside agent never adds or removes conciv-hub in a harness CLI; `chat.uiReply` (the in-page agent's `conciv_ui` question) and `page.reply` (the widget's page-query channel) answer no permission card and stay under plain consent
- `hubTraced` (`router.ts`): registry.call, page.changes, page.clearChanges, server.* and editor.open from a hub-origin request publish their tool call chunks with the `metadata.conciv` marker; any other request publishes nothing
- `plugin.events` (`router.ts`): the bus subscription is open before the handler answers (the stream runs in a fiber forked with `startImmediately`, which subscribes synchronously), so a client that has awaited the call misses no event published afterwards; the fiber stops when the iterator ends or the request aborts
- `plugin.call` / `plugin.events` (`router.ts`): name no session, so a hub-origin call passes `makeHubAdmission`'s disconnected check and skips the consent prompt, like the other session-less procedures
- `refuseUnapproved` (`router.ts`): skipped for widget-origin callers and for outside agents that named their tab (a hub-origin request that also carries `conciv-named-tab: 1`, sent by `conciv tools --tab`), whose own permission mode decides; a hub-origin request without it (the CLI's home db fallback, acting on the user's latest session) still asks; tools with `approval: 'ask'` go through `plane.admitCall` and throw APPROVAL_DENIED on refusal (registry.call, server.reload, server.restart)
- `callTool` (`router.ts`): throws when a tool has no outputSchema and parses output with it; `NO_BUNDLER` maps to the NO_BUNDLER error
- `page.reply`, `chat.permissionDecision`, `chat.uiReply` (`router.ts`, `chat.ts`): UNKNOWN_REQUEST when nothing is pending
- `sessions.rename` (`sessions.ts`): NOT_FOUND without a row; `sessions.model` / `sessions.effort` create the row first (`ensureRow`, as a turn does), so a session that has not run a turn can switch; `model` throws UNKNOWN_MODEL for a missing or disabled model and resets the session effort to null when the new model does not list it; `sessions.effort` throws UNSUPPORTED_EFFORT unless the session's model (row model, else the harness default, else the first listed) lists the effort, and null always clears it
- `cleanTitle` (`sessions.ts`): strips control characters, collapses whitespace, truncates to 120 characters
- `sessions.create` (`sessions.ts`): ids are `conciv_<uuid>` validated with `SessionId.parse`; the row takes the boot (default) harness
- `sessions.switchHarness` (`sessions.ts`): NOT_FOUND without a row, UNKNOWN_HARNESS outside the available set, a no-op for the current harness (an optional `model` is ignored then), SESSION_RUNNING while a run is active, UNKNOWN_MODEL when `model` is not an enabled model of the target harness; otherwise one transaction sets the harness and the given model (else null), clears the native id and effort, and drops the transcript anchor
- `harnessMenuEntryOf` (`sessions.ts`): a harness whose model list throws is logged and listed with no models, `defaultModel` from the adapter (else null) and `modelsFailed: true`; the others still answer
- `ChatContext.harnessFor` (`mount.ts`): the session row's harness when it is available, else the default harness

## Side Effects

- `drafts.set` (`router.ts`): upserts into the `drafts` table
- `sessions.*` (`sessions.ts`): writes `sessions` and `markers`; `delete` tombstones the row and deletes drafts, plane state, captures and page changes
- `sessions.list` (`sessions.ts`): reads the transcript history of every available harness with `transcriptHistory`; a harness whose listing throws is logged and contributes nothing. It never reads the search index; once the first list has answered it calls `search.listed()`, which starts the background index build. A page that comes back short while `next` is set (sessions dropped as earlier transcripts of a switched session, or Codex rows whose rollout is gone) is filled from the following pages, so a page holds `limit` sessions whenever more exist; a session a refill lists again (a search hit in another transcript of the same session) is counted once.
- `sessions.search` (`sessions.ts`): `{term, includeHidden?, cursor?, limit, everywhere}` (`everywhere` false by default), the same pipeline as `sessions.list`, each hit also carrying `cwd` (null for this project, the other project's cwd otherwise) and `resume` (for another project's hit, its harness's `resume.command({cwd, nativeId})`, rendered as `cd <cwd> && <bin> <args>` with shell quoting, cmd quoting on Windows; null for this project's hits and for a harness with no `resume` sidecar); a hit from another project gets a row with that project's cwd, so it never lists in this project; native sessions come from the in-memory Orama index (`sessions/session-search.ts`) and conciv-only rows match on `title LIKE`; the search answers from the index at once and queues one background refresh
- `sessions.preview` (`sessions.ts`): `{harness, nativeId, cwd?, before, limit}`; reads the page through that harness's `HarnessHistory.tail(cwd, nativeId, {limit, before, signal})` at `cwd` (an all-projects hit's own project, this project when absent; refused by `withinProject` for that cwd when the harness has it), so the read costs the size of the page, not of the transcript, and returns it as is: `messages` from the newest safe turn boundary at or past `limit` messages before `before` (the end when null), and `earlier`, the harness's opaque cursor for the page above (core never parses it). The request's abort signal reaches the read. It writes nothing and creates no row; a preview with `cwd` asks the search index to cover that folder (`search.cover`, a background refresh the preview never waits on). An unknown harness, a transcript outside that project, an unreadable transcript, or a first page (`before: null`) with no messages is NOT_FOUND; a later page with none (a transcript whose oldest lines hold no messages) is an empty page.
- `sessions.changes` (`sessions.ts`): streams the search index version, the current one first (`search.changes(signal)`); the search itself comes in through `RpcDeps.search`, created and disposed by `makeApp`
- `settings.*` (`router.ts`, `settings/settings-storage.ts`): `project` is `<stateDir>/settings/<namespace>.json`, `global` is `<concivHome>/settings/<namespace>.json`; one Devframe shared state per file, opened (read once) on first use and shared with every extension's `ServerApi.scope(namespace).settings`; writes are debounced 100 ms and land as a `<file>.<pid>.tmp` renamed over the file; an unreadable file logs a warning and reads empty until the next change; `changes` yields the current snapshot first; the engine's dispose flushes a pending write
- `server.reload` / `server.restart` / `editor.open` (`router.ts`): reload or restart the dev server, or open an editor
