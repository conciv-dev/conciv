# core/src/sessions

## Overview

Session persistence and plumbing: an in-memory per-session pub/sub bus for chat events, listing of harness slash commands, and Drizzle CRUD on the `sessions` table that maps conciv session ids to native harness session ids and builds the session list.

## Interface

- `listCommands` / `mcpUrlFor` / `CommandSource` (`commands.ts`): commands tagged 'mcp', 'plugin' or 'harness'
- `createSessionBus` / `SessionBus` (`session-bus.ts`): publish, listen, events(sessionId, signal)
- `createSessionSearch` (`session-search.ts`): one Orama index per engine over every native session's title and message text, held in a `node:worker_threads` worker (`search-index-worker.ts`) that the main thread calls through an oRPC client over a `MessageChannel` port (`@orpc/client/message-port` `RPCLink`, `@orpc/server/message-port` `RPCHandler`). The worker holds only the index (states, remove, list, read, rename, search) and never touches a harness or the db. Every document carries the `cwd` it belongs to (an Orama `enum`): a project-scoped search filters `where: {cwd: {eq}}`, an `everywhere` search drops the filter. The refresh walks the current project first (`list({cwd})`, documents stored under the engine's cwd, today's timing); the first `everywhere` search adds a second scope, after which each refresh also walks `list({everywhere: true})`, keeps only the sessions of folders no `{cwd}` scope owns (the project and every covered folder), and reads each one's body through `messages(<its own cwd>, id)`, so every harness's containment check runs against that session's own project. `cover(cwd)` adds a `{cwd}` scope for a folder no `{cwd}` scope already covers, whether or not an `everywhere` scope exists (a `sessions.preview` of another project's session calls it; the `everywhere` walk can miss such a folder's sessions, a Pi transcript without a header cwd for one, so it neither lists nor removes them) and queues a refresh without waiting on it, so later `everywhere` searches find that folder's sessions. Each scope removes only the documents it owns. The worker starts on `listed()` (after the first `sessions.list` answers), which also starts the background build on the next `setImmediate`; nothing is read before that, and a search before it answers no native sessions. A build or refresh is single-flight through a `@tanstack/pacer` `AsyncQueuer` (concurrency 1, one trailing run): a title pass walks every `list` page per harness (sessions no longer listed are removed; title, `updatedAt` and `sizeBytes` come from the walk) and bumps the index version (publishing an `indexed` event) when it changed the index, then a text pass reads unread sessions one at a time, smallest transcript first (each read streamed by the harness), sends each session's text to the worker, and bumps it again when any read returned text (a read that fails changes nothing searchable, so it never bumps the version). A search answers from the index at once and queues one refresh. A session's text is re-read when it is new, unread, or changed and last read at least 30 s ago (`LIVE_REINDEX_MS`); hits take their meta from the index document, never from `meta()`; each returned hit also carries `excerpt` and `matched`, worked out in the worker for the returned hits only: the query and every word of the title and body run through the index's own Orama tokenizer (`index.tokenizer`, so normalization, diacritics and any stemming or stop words match the index), a word matches a query token by Orama's own rule (it starts with the token, or `boundedLevenshtein(token, word, tolerance).isBounded` from `@orama/orama/internals`, with the search's `typoTolerance`), the excerpt starts at the line of the first matching body word (or the last whitespace of any kind within 80 characters before the point 80 characters ahead of it, else that point itself, prefixed with `…`, when that line runs longer than 300 characters) and runs about 300 characters on to the next whitespace, `excerpt` is null when only the title matched, and `matched` is the distinct matching words as written in the title and the excerpt; `pages()` hands them on through `NativePage.found` (keyed by native id) and `listSessionMetas` spreads them onto each row (null and `[]` for rows the index did not answer); every document is parsed by a zod schema in the worker before it is inserted; a session whose `messages` throws keeps its old body with `read: false`, is logged once, and is retried on each later refresh; a harness whose `list` throws is logged and the others keep indexing; ids where the index and the walk disagree after a title pass are logged. `changes(signal)` subscribes to the `indexed` events and yields the current version first, so a late subscriber never waits for a pass to learn where the index stands. If the worker exits (a crash or running out of memory), its in-flight calls (searches and renames included) are aborted and the index is dropped, so the next `listed()` starts a fresh worker and rebuilds. `dispose()` stops the queue, aborts in-flight index calls without logging them, and terminates the worker; `makeApp` creates the search, hands it to the RPC router through `RpcDeps.search`, and disposes it before the db closes
- `createChatSession` / `renameSession` / `deleteSession` (`session-actions.ts`): what `sessions.create`, `sessions.rename` and `sessions.delete` do, callable from more than the RPC handlers. `createChatSession` adds a chat row and its `new` marker; `renameSession` cleans the title (control characters out, whitespace collapsed, 120 characters), writes it and retitles the search index when the row has a native session, answering `'missing'` for an unknown session; `deleteSession` tombstones the row, then drops its drafts, clears the chat plane, deletes its captures and page changes, and publishes `session.deleted` on the plugin host bus
- `rowById` / `currentRow` / `rowByNativeId` / `rowByNativeRef` (`session-rows.ts`)
- `createRow` / `ensureRow` / `nativeIdFor` / `recordNativeId` (`session-rows.ts`)
- `resolveRow` / `openNativeRow` / `ensureAgentRow` / `mintExternalRow` / `anonymousExternalRow` (`session-rows.ts`)
- `tombstoneRow` / `restoreRow` / `setPermissions` (the session's own permission rules, merged after the agent's) / `setMetadata` (replaces the session's whole metadata record) / `recordActivity` / `sweepEmptyRows` / `switchRowHarness` (`session-rows.ts`)
- `listSessionMetas` / `SessionListInput` / `NativeList` / `RowScope` / `NativePage` / `Found` (`session-rows.ts`): `SessionHit[]` sorted by updatedAt descending, each carrying its `harnessKind`, the `excerpt` / `matched` its native page found and the `preview` reference of the transcript that page listed (an earlier transcript's own harness, id and cwd after a harness switch) (`sessions.list` drops both through its output schema)

## Invariants

- `listCommands` (`commands.ts`): uses the session's harness (`harnessFor`); `{commands: []}` without `harness.commands`; mcpUrl passed only when `capabilities.mcp === 'http'`
- `createSessionBus` (`session-bus.ts`): empty listener sets are deleted; `events` unlistens on abort, cancel and finally
- `session-rows.ts`: rows are validated with `SessionRecordSchema.parse`; default ids are `conciv_<uuid>`
- `claimNativeRow` (`session-rows.ts`): insert onConflictDoNothing on (harnessKind, cwd, harnessSessionId), then re-read
- `resolveRow` (`session-rows.ts`): conciv id, then harness id, then latest non-deleted chat row for the cwd (by realpath), then a new id
- `listSessionMetas` (`session-rows.ts`): skips invalid rows, filters by cwd and deletedAt unless `includeHidden`, materializes unclaimed native sessions; a native session is claimed by the row whose current (harnessKind, native id) matches or whose earlier-natives list (`chat_metadata` namespace `conciv.session.earlierNatives`, key = session id, read in one query, zod `.catch([])`) holds it; a hidden owner is undeleted instead of listing the native separately; in a search, a hit in an earlier native transcript answers its owning session instead (a page lists each session once); a harness page may come back short while its `next` is set (Codex leaves out threads whose rollout is gone), so the merged page stops at the newest `next` among the harness pages (the frontier): entries older than it wait for the following page, whose cursor is the frontier when the page holds fewer than `limit`, so no harness's unread sessions are skipped and an empty harness page never ends the listing
- `switchRowHarness` (`session-rows.ts`): one transaction appends the outgoing non-null `{harnessKind, nativeId}` to the session's earlier-natives list, sets `harnessKind`, nulls `harnessSessionId` and `model`, and deletes the session's transcript anchor; the earlier-natives list only claims list entries and never feeds resume

## Side Effects

- `session-rows.ts`: SQLite reads and writes on `sessions`
- `session-actions.ts`: SQLite writes on `sessions`, `markers`, `drafts`, captures and page changes; `deleteSession` clears the chat plane and publishes on the plugin host bus; `renameSession` retitles the search index
- `listSessionMetas` (`session-rows.ts`): inserts or undeletes rows while listing; `logError` for invalid rows
- `listCommands` (`commands.ts`): calls the harness adapter's `commands`
