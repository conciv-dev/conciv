# core/src/runtime

## Overview

Builds the per-session and engine-wide scope objects that join the session event bus, the chat plane and the DB.

## Interface

- `makeCoreRuntime(deps)` / `CoreRuntimeDeps` (`core-runtime.ts`): `CoreRuntime` with `forSession(id)` and `engine`; a session's `run.stop(runIds?)` stops the plane's live run and then interrupts that session's in-flight `experimental.idle` trigger (`deps.interruptIdle`, `app.ts`), answering `{ok: true, stopped}` with `stopped` true when it stopped a live run or interrupted an idle trigger (as opencode, whose interrupt answers true while the execution's idle hook still runs); when it stopped or interrupted something, the idle slot stays taken until the plane's run of that session has settled, so a run stopped while its turn ends starts no idle hook after the stop; the `runIds` filter applies to the live run only; a session's `run.compact()` interrupts that session's in-flight `experimental.idle` trigger the same way first, then runs the plane's `compact` (which stops the live run and waits for it in `hydrate`), so a compact sent while an idle hook waits on its own session does not hang
- `makeSessionPrimitives` / `SessionPrimitives` (`primitives.ts`): {stream}
- `SessionScope` (`scope-types.ts`): {id, stream, asks, history, run}
- `EngineScope` (`scope-types.ts`): {staleness, symbolicate, navigation: {get, set}}
- `CoreRuntime` (`scope-types.ts`)
- `provideInstructionEntries` / `loadInstructionEntries` (`instruction-entries.ts`): the plugin `InstructionEntry` key on the plugin host's `KV` store, one row per session and key under the reserved prefix `conciv.instruction-entry:<sessionId>:`, a removed entry kept as `{value: null, removed: true}`; `loadInstructionEntries` turns a session's rows into one instruction source each (`api/<key>`), which `pluginInstructions` (`permission-cards.ts`) combines with code mode and skills
- `provideBundlerSource` / `provideEditorSource` / `provideApp` / `provideConfiguredPolicies` / `provideGlobalRoots` (`plugin-runtime.ts`): the plugin host's `BundlerSource`, `EditorSource` (the engine's editor opener, which only the engine's internal plugins get), `App` (core's package version) and `ManagedPolicy.ConfiguredPolicies` (the config's `policies` decoded with `ConfigPolicy.Info`) and `Global` (`cache` and `state` under conciv's home and `config` conciv's home itself, where the `skill/` and `skills/` folders are scanned, made when the layer is built) as layers
- `makePluginRuntime(input)` (`plugin-runtime.ts`): the plugin host's one `ManagedRuntime`, with `input.clock` (when given) provided under the whole graph, composed in the host fixture's order: `Plugin`, `SdkPlugins`, `InstancePlugins` (the embedder's SDK plugins, and the engine's own `post` built-ins (`conciv.page`) stamped as built-ins so the plugin list hides them, each wrapped with `PluginPromise.fromPromise`), `PluginUpdate`, `ConfigPluginSource` over `Tool`, `Permission`, `SkillInstructions`, `SessionProjector`, the instruction entries, over `Agent`, `PermissionSaved`, `permissionSessions`, `Skill`, over `PluginHooks`, over `Rpc`, `KV`, `EventFeed`, over `Bus`, over the location, app, servers, bundler, editor opener, configured policies and plugins, models, sessions, the native watcher and `Npm` (with `EffectFlock`), over `FSUtil`, over the database, the global roots and `NodeFileSystem`. `supervise` builds `PluginSupervisor.layer` into a scope forked from the runtime's scope, as opencode's instance layer builds its `PluginSupervisor` node: building takes the registry hold and forks the activations (`forkScoped`), it never awaits them, so `makeApp` calls it before it returns `fetch` and the hold exists before any request; a plugin whose activation fails is logged and the hold is released, one that hangs keeps every `Plugin.awaitActivation` waiting but blocks neither `makeApp` nor listen; `awaitActivation` only awaits `Plugin.awaitActivation`; `start` calls `makeApp` only after the port is bound, and awaits `awaitActivation` after it; `closeRpc`, `closePlugins` (closes that scope: the supervisor's `registry.close`) and `closePermissions` are the explicit steps `makeApp`'s dispose runs in the ruled order; `prompt(event, signal)` awaits `Plugin.awaitActivation` and triggers the `session.prompt` hooks in a fiber that the turn's abort signal interrupts (`runPromise(effect, {signal})`): on a stop an Effect hook's body stops and its finalizers run, no later hook runs and no event returns to the turn, while a promise-style hook's function is abandoned and runs on until it settles by itself (the promise adapter gives hooks no signal), and `promptHooked` awaits it and says whether any `session.prompt` hook is registered, so a chat turn with none builds, copies and compares no prompt event; `context(name, request, signal)` awaits `Plugin.awaitActivation`, reads the session (`Session.Service.get`) for its agent, triggers the `session.context` or `session.compaction` hooks on the model request (sessionId, model, agent, system, messages, options, tools) and answers the event the hooks leave; it runs in a fiber the turn's abort signal interrupts, as `prompt` does: on a stop an Effect hook's body stops and its finalizers run, no later hook runs, no edited request returns to the turn, the harness is not called and the run ends stopped, while a promise-style hook's function is abandoned and runs on until it settles by itself
- `provideServersSource({home, engineId})` (`servers-source.ts`): the plugin host's `ServersSource`, every running conciv engine on the machine: the home database's live engine rows after `checkEngines` (`@conciv/db`), so a dead row is retired first and an unreachable one is listed with `connected: false`. One ref per id, built once; `name` is the folder name of the row's `root`, `url` the row's `apiBase`, no `password`, `local` true, `builtin` when the id is this engine's, `compatible` true until a call through its client fails with `engineTooOld` (an oRPC interceptor on the client marks the rows with that `apiBase` and rethrows the same error), then false until the engine's row (`id`, `pid`, `root`, `apiBase`) changes, `connected` when the last check reached it, `client` the SDK's client builder `Conciv.make` (`@conciv/plugin`) over the contract client for `apiBase` (`makeRpcClient` with that interceptor): a plain object of the contract's groups plus `rpc` and the shared `event` stream, one per `apiBase`, no origin header (an engine-to-engine call is trusted, no consent prompt). `list()` and `get()` are synchronous: they read the home database's engine rows on each call, while `connected`, `name` and `url` come from the last check
- `provideHarnessModels(harness)` (`plugin-runtime.ts`): the plugin host's `Model` key from the harness's model list as `buildHarnessMenuEntry` (`api/rpc/sessions.ts`) resolves it, each model `Model.Info.default(harness id, model id)` with the harness's `name`, `contextWindow` (as `limit.context`) and `disabled` (as `enabled: false`) laid over it; `available` lists the enabled models of the asked types (chat when none are asked), `default` is the harness's default model when it is listed and enabled, else the first enabled one
- `provideSessions(started)` (`plugin-sessions.ts`): the plugin host's `Session` key on conciv's own session rows. `started()` hands it core's chat context, runtime, session search and plugin host, read at each call because they exist only later in `makeApp`. `get` is the row (`rowById`; missing or deleted fails `Session.NotFoundError`); `list` pages this project's sessions through `listedSessionPage`, or `searchedSessionPage` for a `search` term (`api/rpc/sessions.ts`), limit 30 by default and 1 to 100, its `next` cursor the JSON of conciv's own list cursor (a cursor that does not parse fails `Session.InvalidListCursorError`), no `previous`; `create` looks a supplied `id` up first, before the agent and model checks (the source's order, `core/src/session.ts:291-293`), and with no folder filter (the source's `store.get`): an `id` of a live session returns that session unchanged, nothing of the second input applied (no rename, metadata, permissions or model); an `id` of a deleted session is refused with `Session.NotFoundError` carrying that id (the same error `get` answers for it), before anything is written, and the tombstoned row, its markers and its `conciv.session.earlierNatives` entry stay as they were, so the session can still be restored (the source has no tombstones: its `Deleted` projector removes the row, `core/src/session/projector.ts:963-966`, so its `create` with that id makes a fresh session); otherwise the session id is the supplied `id`, or a minted one when none is supplied; then it refuses an `agent` other than `build` with `Session.AgentNotFoundError` and a model the default harness does not list with `Session.NotFoundError`, both carrying that id, before anything is written; then it is `createChatSession` with that id on the default harness; then `renameSession`, `setMetadata`, `setPermissions` and the model switch for the inputs given (`null` is not given); a supplied `parentId` is ignored; `remove` is `deleteSession`; `rename` is `renameSession`; `setMetadata` / `setPermissions` copy the input through the row schema's field and write the row; `switchAgent` accepts `build` and fails `Session.AgentNotFoundError` for any other agent; `switchModel` fails `Session.NotFoundError` unless `providerId` is the session's harness id and the harness lists the model enabled (and, with a `variant`, lists it among that model's efforts), then is `switchSessionModel` and, for a `variant`, `switchSessionEffort`; `compact` is the session runtime's `run.compact` (native `/compact` or the fallback summary turn), answering a `compaction` dated when it was asked, with no `id` or `delivery`; `wait` is the plane's `settled`; `interrupt` is the session runtime's `run.stop` and answers its `stopped`, `resume` changing nothing (no steering inbox). `SessionInfo`: `model` `{id: row model, providerId: harness id, variant: row effort}` when the row has a model, `agent` `build`, `cost` and `tokens` from the row's usage (0 when unknown), `time.created` and `time.updated` the row's `createdAt` and `updatedAt`, `title`, `metadata` and `permissions` the row's, `location.directory` the row's cwd; `projectId` undefined, the rest absent

## Invariants

- `navigation.set` (`core-runtime.ts`): a write dated more than 24h ahead is not applied; the upsert is last-writer-wins on `updatedAt` in a single row with id 'navigation'

## Side Effects

- `makePluginRuntime` (`plugin-runtime.ts`): building the runtime watches the project root for a `conciv` entry (and `conciv/` itself when it exists) through `ConfigPluginSource`; `supervise` loads the built-in `conciv.skill` (the `conciv` and `report` skills), `conciv.tool.skill` and `conciv.tool.server` plugins first, then the embedder's plugins, `conciv/plugin*/` files and the configured plugins, then the built-in `conciv.config.skill` plugin last (it offers the skills in `skill/` and `skills/` under conciv's home and the project's `conciv/` folder, rescanned when they change), installing configured packages that are not installed; the latest registration of a tool name wins, so a project plugin's tool named `open` or `server_*` replaces the engine's, as opencode

- `provideInstructionEntries` (`instruction-entries.ts`): `KV` reads and writes on the project database
- `provideGlobalRoots` (`plugin-runtime.ts`): makes the `cache` and `state` directories and sets the host's `Flock` state root when the layer is built
- `provideServersSource` (`servers-source.ts`): nothing runs until a plugin first reads `servers`; then, inside the layer's scope, a watch of the home folder (`homeDbReads`, `lib/home-db-watch.ts`) re-checks on every change of the engine rows, and a health re-check runs every 10 s (opencode's `SERVER_HEALTH_POLL_MS`); checks run one at a time; closing the scope aborts the watch and stops the poll; a failed check is logged and keeps the last snapshot
- `provideHarnessModels` (`plugin-runtime.ts`): each call lists the harness's models (a failed listing is logged and answers no models)
- `navigation` get/set (`core-runtime.ts`): SQLite select and upsert on the `navigation` table
