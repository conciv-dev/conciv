# core/src/page

## Overview

The per-session page bus that carries page queries to browser tabs, the change journal that records page edits, and the page action queues that play queued page actions and report their outcome.

## Interface

- `makePageBus(timeoutMs=5000)` / `pageQueryStream` / `makeJournal` / `PageEnv` (`page-bus.ts`); each subscriber is one browser tab with an engine-assigned id (`b1`, `b2`, ...) and a focus getter (`{focusedAt, visible}`, fed by the push socket's `page-serving` frames); `PageBus.ask(sessionId, query, route?, signal?)` sends the query to exactly one browser tab, the one `{browserTab}` names or else the one focused last (then visible, then subscribed last), under a random request id only that tab sees; a browser tab that unsubscribes fails its in-flight queries with `no-widget` ('browser tab <id> closed before it replied') and a late reply settles nothing, except for a page tool call (`route` `{mutating}`, passed by `runClientTool` from the tool's mark): a reading call waits for a browser tab of the session to serve again (a new subscriber, or one already there) and is sent once more to the one focused last, failing as before when none serves within 5 seconds or the call's own timeout, which the resend never extends; a changing call is never sent again and fails at once with `no-widget` 'the page reloaded or closed during <tool>; it may already have run. Take a new snapshot before continuing'; and a named browser tab that is not open fails `no-widget` naming the open ids; an aborted `signal` (the caller's tool request signal, carried on `ToolRequest.signal`) fails the call at once with the signal's reason, drops its waiter, and never resends; `PageBus.openSessions()` lists `{sessionId, browserTabs}` (ids, the default target first) for every session with at least one subscriber
- `makePageQueues({bus, journal})` / `PageQueues` / `QueueRecord` / `QueueStart` / `startQueueFollowUp` / `owesFollowUp` / `holdForNextReply` / `pageQueueChunks` (`page-queue.ts`); a queue is hub work (`fromHub(record)`, read by the engine's `finished` listener, `undelivered` and `owedTurn`) when its call id is in the session's in-flight hub call ids or its queue id is in the session's hub queue ids, two exact sets with no cap: `hubCall(sessionId, callId)` adds an in-flight id at a hub request's start and for each of its child calls, `hubReplied(sessionId, callIds)` runs at that request's reply on every exit (success, tool error, abort, thrown error) and first moves every not yet delivered queue those call ids started, finished or not, into the hub queue ids, then drops the call ids; a queue id leaves when its result is delivered; `cancelSession(sessionId)` is the session's follow-up work cancelled on session delete (`deleteSession`, at the place of opencode's `jobs.cancelSession`): it drops the session's queue records, so a result that lands later is never announced or owed and waiting on that queue answers `no queue ... on this tab`, and both sets; `holds(record)` reads whether a record is still kept, which `announce` and each `startQueueFollowUp` attempt check, so a follow-up whose queues were cancelled answers `stopped` and is not retried; `owesFollowUp(queues, sessionId)` reads, without claiming, whether a finished result is owed a follow-up turn, the same check `startQueueFollowUp` starts with; `holdForNextReply(queues, sessionId)` moves the session's owed results to `nextReply` without starting a turn, which the engine does when a run ends `aborted` (a user stop, a steer, a compact or clear ending the run, the startup sweep), so the result arrives with the agent's next reply; `wait(sessionId, queueId, waitMs, signal?, replied?)` takes a `replied` promise, the caller's reply, from oRPC `RpcContext.replied` (HTTP `/rpc` from the node response's `close` and its `writableFinished`, already settled when the response closed before the request reached the router; the websocket per request frame, true once the reply frame was sent on a socket still open, false when it was skipped for an aborted request, the peer closed or the send failed; it settles on every exit); it claims the finished result it hands over and marks it delivered only once that reply has gone out; a reply that did not finish writing, or a `replied` that rejects, puts the result back where it was (`owed` or `nextReply`), so it leads the next reply; `undelivered` (the hub's `/api/mcp` and `code.execute`/`code.discover`) and `play` still mark a result delivered at the hand-over. The finished event (`finished` listeners: the chat card, and the follow-up turn for non-hub work) runs once per queue, one tick after finish, only when the result is then still owed or claimed (`announce` returns on `delivered`, on `nextReply`, or when `holds(record)` is false): a result already delivered (`play`, `undelivered`, or a wait whose reply already went out) or held for the next reply is not announced; a result a caller still holds a claim on then is announced, and a claim that goes back to owed later is not announced again. The limit: a reply counts as gone out once it is handed to the kernel, which is not the client having read it; full closure would need a client acknowledgement, which is not built. The source's waiters are in-process (opencode `job.ts:424-427`, `:463-465`) and consume the result the moment they have it; "delivered once the reply has gone out" extends that rule across conciv's network leg
- `makePagePlugin(host)` / `PagePlugin` (`page-plugin.ts`): core's adapter to the page plugin's `experimental.page` RPC. Every `call` first awaits `Plugin.awaitActivation`, so a call that arrives while the plugins are still starting waits for them instead of answering 'unavailable'. The wait ends: `makeApp` builds the supervisor (which takes the registry hold) before it serves, an activation that fails is logged and still releases the hold, and disposing the engine closes the registry, which opens the latch (a call then answers 'unavailable'). Only a plugin activation that never settles keeps it waiting, as it keeps every `Plugin.awaitActivation` caller. `symbolicate(frames)` rejects when the plugin cannot answer; `symbolicateOrNone(frames)` answers null and logs, except for `rpc.unavailable` (`unlisted`: the plugin configured out with `-conciv.page`), which stays quiet

## Invariants

- `ask` (`page-bus.ts`): 'no-widget' without a subscriber for the session (with the message `the page is showing another session; switch back to this session to use page tools` when another session has one), 'timeout' on expiry

## Side Effects

- `makeJournal` (`page-bus.ts`): writes page changes to the DB
