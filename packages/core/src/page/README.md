# core/src/page

## Overview

The per-session page bus that carries page queries to browser tabs, the change journal that records page edits, and the page action queues that play queued page actions and report their outcome.

## Interface

- `makePageBus(timeoutMs=5000)` / `pageQueryStream` / `makeJournal` / `PageEnv` (`page-bus.ts`); each subscriber is one browser tab with an engine-assigned id (`b1`, `b2`, ...) and a focus (`{focusedAt, visible}`, set from the `page.queries` input and updated by `page.focus`); `PageBus.ask(sessionId, query, route?, signal?)` sends the query to exactly one browser tab, the one `{browserTab}` names or else the one focused last (then visible, then subscribed last), under a random request id only that tab sees; a browser tab that unsubscribes fails its in-flight queries with `no-widget` ('browser tab <id> closed before it replied') and a late reply settles nothing, except for a page tool call (`route` `{mutating}`, passed by `runClientTool` from the tool's mark): a reading call waits for a browser tab of the session to serve again (a new subscriber, or one already there) and is sent once more to the one focused last, failing as before when none serves within 5 seconds or the call's own timeout, which the resend never extends; a changing call is never sent again and fails at once with `no-widget` 'the page reloaded or closed during <tool>; it may already have run. Take a new snapshot before continuing'; and a named browser tab that is not open fails `no-widget` naming the open ids; an aborted `signal` (the caller's tool request signal, carried on `ToolRequest.signal`) fails the call at once with the signal's reason, drops its waiter, and never resends; `PageBus.openSessions()` lists `{sessionId, browserTabs}` (ids, the default target first) for every session with at least one subscriber
- `makePagePlugin(host)` / `PagePlugin` (`page-plugin.ts`): the engine's in-process calls to the page plugin's RPC Definition (`experimental.page`, from `@conciv/plugin-page/rpc`) through the plugin host's `Rpc.Service.call` (a declared failure becomes an `Error` with its message), each answer parsed by that method's own output schema; core lists that plugin itself, activated last (`makePluginRuntime` `post: [concivPage]`); `queueWait` answers the hub's `page.queue.wait`: with the caller's reply promise (`replyWentOut`, from oRPC `RpcContext.replied`, as #927) it asks the plugin's `queue.claim`, which claims a finished result still owed or held for the next reply (one already claimed or delivered is handed over with nothing claimed), and settles it through `queue.settle` once the reply settles: `delivered` when the reply went out, back to where it was (`owed` or `nextReply`) when it did not or the promise rejected, so it leads the next reply; without a reply promise it asks `queue.wait`, which marks the result delivered at the hand-over; `attachedSessions()` is `sessions.attached` (the session ids with a tab attached; unlisted answers none), walked by `createTabs().list`; `tabs(sessionId)` is the plugin's own non-asking `tabs.list` method (`selectTabs`; a session with no tab answers no tabs, a failed read answers no tabs and is logged), read by `createTabs` (browser tab ids are the plugin's `tab_<uuid>`, focused first) and the outside refusal's tab title; `delivery` is the follow-up queue driver's `QueueDelivery` over `queue.owed` / `queue.settle`, excluding the session's hub call ids; `undelivered(sessionId, hub)` / `startedBy` / `hubCall` / `hubReplied` / `fromHub` keep the hub side (a hub call id stays hub work while it is in flight, and after its reply while a queue it started is still playing or owed, read back from `queue.startedBy` and `queue.owed`); `cancelSession(sessionId)` is the session's follow-up work cancelled on session delete (`deleteSession`, at the place of opencode's `jobs.cancelSession`, after the session's runs ended): it drops the hub sets and awaits the plugin's `queue.cancelSession`, which drops the session's queue records before the row is tombstoned (no page plugin listed: nothing to cancel; any other failure rejects the delete), and the plugin drops them again when it hears `session.deleted` (a result that lands later is never announced or owed, and waiting on it answers `no queue ... on this tab`); from the row's tombstone on, `makeApp`'s `queue.finished` listener drops a result of a deleted session (no card, no record, no follow-up) and each `startQueueFollowUp` attempt answers `stopped`, not retried (both read the row through `isDeletedRow`), so a result the plugin still keeps between the tombstone and its hearing `session.deleted` starts no turn; `followFinished(listener)` listens on the host bus for `queue.finished`, which `makeApp` turns into the queue card and, for a queue the hub did not start, a follow-up turn. Every `call` first awaits `Plugin.awaitActivation`, so a call that arrives while the plugins are still starting waits for them instead of answering 'unavailable'. The wait ends: `makeApp` builds the supervisor (which takes the registry hold) before it serves, an activation that fails is logged and still releases the hold, and disposing the engine closes the registry, which opens the latch (a call then answers 'unavailable'). Only a plugin activation that never settles keeps it waiting, as it keeps every `Plugin.awaitActivation` caller. `symbolicate(frames)` rejects when the plugin cannot answer; `symbolicateOrNone(frames)` answers null and logs, except for `rpc.unavailable` (`unlisted`: the plugin configured out with `-conciv.page`), which stays quiet
- `QueueDelivery` / `OwedQueue` / `startQueueFollowUp` / `owesFollowUp` / `holdForNextReply` / `pageQueueChunks` (`page-queue.ts`): the follow-up driver reads owed results through a `QueueDelivery` (`owed(sessionId, claim)`, `settle(sessionId, queueIds, delivery)`), which the page plugin's `delivery` gives the engine; `startQueueFollowUp(queues, plane, sessionId, deleted)` asks `deleted(sessionId)` (the engine passes the session row's tombstone) before each attempt and answers `stopped`, not retried, for a deleted session; `makePageQueues({bus, journal})` / `PageQueues` / `QueueRecord` / `QueueStart`, the old bus store (a `QueueDelivery` too), stays only for the old bus path until it is removed; a queue is hub work (`fromHub(record)`, read by the engine's `finished` listener, `undelivered` and `owedTurn`) when its call id is in the session's in-flight hub call ids or its queue id is in the session's hub queue ids, two exact sets with no cap: `hubCall(sessionId, callId)` adds an in-flight id at a hub request's start and for each of its child calls, `hubReplied(sessionId, callIds)` runs at that request's reply on every exit (success, tool error, abort, thrown error) and first moves every not yet delivered queue those call ids started, finished or not, into the hub queue ids, then drops the call ids; a queue id leaves when its result is delivered; `cancelSession(sessionId)` drops the session's records and both sets on session delete (`deleteSession`); `owesFollowUp(queues, sessionId)` reads, without claiming, whether a finished result is owed a follow-up turn, the same check `startQueueFollowUp` starts with; `holdForNextReply(queues, sessionId)` moves the session's owed results to `nextReply` without starting a turn, which the engine does when a run ends `aborted` (a user stop, a steer, a compact or clear ending the run, the startup sweep), so the result arrives with the agent's next reply

## Invariants

- `ask` (`page-bus.ts`): 'no-widget' without a subscriber for the session (with the message `the page is showing another session; switch back to this session to use page tools` when another session has one), 'timeout' on expiry

## Side Effects

- `makeJournal` (`page-bus.ts`): writes page changes to the DB
