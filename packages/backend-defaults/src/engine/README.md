# backend-defaults/src/engine

## Overview

Top-level engine modules. `createBackend` (`start.ts`, the package's `./backend` entry, as Backstage `createBackend`) resolves config, binds a port (persisted, preferred or exact), builds the Hono app with `makeApp` (`app.ts`) and writes the endpoint files. It hands the caller's plugins, harness list, timeouts, staleness check and app version to `makeApp` unchanged, so a test engine starts the same way the dev server does. `makeApp` starts the plugin host and the chat plane and mounts the health, shutdown, oRPC (socket and HTTP), MCP and widget page routes. `engine-login.ts` is the engine gate and login, `event-feed.ts` the public event stream (opencode's `server/src/event-feed.ts` on `Bus.listen`, yielding each encoded event object instead of an SSE frame, since the transport is oRPC), `config.ts` config resolution. Subfolders: `api` (MCP, widget page, the oRPC router), `editor`, `lib`, `pty`, `runtime`, `sessions`, `settings`.

- `makeApp` builds the plugin host's supervisor before it resolves, so activation is under way before any request; `MadeApp.awaitActivation` only waits for the first generation to be active. `MakeAppOpts.eventHeartbeatIntervalMs` (default 15 000 ms) sets how often `event.subscribe` sends its `server.heartbeat` frame; `MakeAppOpts.stopGraceMs` (default `GROUP_EXIT_TIMEOUT_MS`, 5 000 ms) sets how long a stopping CLI's process group and each model listing get before the engine goes on without them; neither is a config-file key.
- `GET /health` answers `{ok, harness, engine: {stale}, id}`, `id` being the per-start `engineId`.

## Invariants

- `assertAccessToken` (`start.ts`): accessToken must be a UUID
- `reservePort` (`start.ts`): up to 4 attempts 300ms apart, retrying only on EADDRINUSE; `exact` binds or throws, `preferred` falls back to port 0 with a warning
- `createBackend` (`start.ts`): the MCP url the engine hands its harnesses and writes to the claude connect file is `<origin>/api/mcp?conciv_auth_token=<token>`; the home-db row and the dev endpoint hold the bare origin and the token apart. Start order: refuse a harness id nothing registers (`requireHarness`, skipped when a `harness` adapter or a simulation is passed), bind the port (and write `server.json`) with a handler that waits for the app, then `makeApp`, then the MCP endpoint file, the dev endpoint and the home-db row, then wait for the first plugin activation; `createBackend` resolves only after it. `makeApp` runs only once the port is known. A request that arrives before the app is made (a CLI reads `server.json` as soon as it exists) waits for it and is then served by it; nothing runs on a half-made app. A failed bind fails start before anything is built; a failed `makeApp` fails every waiting request (hono answers 500), closes the listener and rethrows; a failed endpoint write closes the listener and disposes the app. Every failed start after the bind also puts `server.json` back as it found it (the previous record, or no file), but only while the file still holds this start's record, so an engine already running in the project stays reachable. A plugin whose `setup` throws is listed `failed` and does not stop the engine
- `makeEngineGate` (`engine-login.ts`): only `OPEN_PATHS` (`/health`, the three `/rpc/auth/*` procedures, the widget page `/widget` and `/widget/*`) pass without a token; every other request carries the token as `?conciv_auth_token=<token>` on its own URL and is checked on its own; there is no other way to present it (no header, no path prefix)
- `rpcSocketGate` (`engine-login.ts`): the rpc socket opens untrusted and serves only the three `auth.*` procedures (anything else answers `UNAUTHORIZED`) until a `?conciv_auth_token=` on the upgrade URL (read once when the socket opens; the engine token trusts the socket for its life, a trusted-browser token is held and revocable), a `{type: 'conciv:trust', token}` frame, or a successful `auth.trust` / `auth.exchange` on that socket trusts it; a revoke closes it with 1008
- `makeAuthRouter` (`engine-login.ts`): `auth.exchange` answers `{refused: 'mismatch' | 'expired'}`; five wrong codes retire the printed code
- `auth.issueCode` (`engine-login.ts`): answers `{code, expiresAt}` only when the caller connected with the engine token (`RpcContext.engineCaller`: set from the request URL on HTTP and when the socket opens on the rpc socket), else `FORBIDDEN`, so a logged-in browser cannot invite another; it is not an `OPEN_PATHS` procedure, so the engine gate refuses it without a trusted token. `makeCodeStore.issue()` makes the code without printing it and `request()` prints the banner on top of the same path; one live code at a time, so issuing a link retires a code a human was about to type
- `assertUniqueCapabilityNames` (`app.ts`): throws on tool-name collisions
- harness registry (`start.ts`, `app.ts`): `createBackend` builds `harnessRegistry(configProvider)` from `@conciv/harness` once and hands it to `makeApp` as `harnessRegistry`; `makeApp` called on its own builds it from its own `configProvider`. Harness lookup (`requireHarness`) and harness detection on PATH both read that registry
- `requireHarness(registry, id)` (`lib/require-harness.ts`): `createBackend` calls it before it binds the port, unless the caller passed its own `harness` adapter or a simulation, and `makeApp` calls it for a config with no adapter; a harness id nothing registers throws `conciv: unknown harness "<id>". Known harnesses: <registered ids>.`, with no fallback to claude (the id defaults to 'claude' only when none is given)
- `admitOutside` (`app.ts`): the per-session consent for an outside (hub-origin) call; with `hubAccess` `open` it admits every live session at once, but a missing or deleted session (non-null `deletedAt`) is refused with `session "<id>" does not exist` before anything of the call runs or is recorded in that session's chat; otherwise it runs `assertOutsideAgent` (`runtime/permission-cards.ts`), a plugin host `permission.assert` for action `outside-agent` on the client that waits on the card with no timeout: once admits this call, always saves a project rule, reject refuses it, and a caller abort interrupts the assert, which drops the card
- `onRunEnd` (`app.ts`): publishes how the run ended to the plugin host, then, for a completed run with no session inbox input waiting, the plugin `experimental.idle` trigger as a fiber kept per session (an Effect `FiberMap` keyed by session id) and waits for it to end before the run settles, so `hydrate` still waits for the hook; the session runtime's Stop and Compact and engine `dispose` interrupt that fiber; a hook that fails is recorded as the run's error and published as `conciv.idle-failed`, an interrupted one is not (the run stays completed with no error); inbox input waiting after it wakes the session
- `detectedHarnesses` (`app.ts`): only harnesses whose binary is on `PATH` join the boot harness as switch targets; a config directory alone does not count
- `onError` (`app.ts`): HTTPException keeps its status; anything else is 500 'internal error'
- `/api/shutdown` (`app.ts`): 404 without `onShutdown`
- `resolveConfig` (`config.ts`): session ids must pass `isSessionId` / `isHarnessSessionId`; harness defaults to 'claude'
- `EventFeed` (`event-feed.ts`): only public events pass (`server.connected`, `EventManifest` server events, `rpc.*`), so internal events take no subscriber capacity; a subscriber with `types` gets only those types (filtered on the server); each event is encoded once and the same object goes to every subscriber; a subscriber whose queue holds 4096 undelivered events is removed and its stream fails with `SubscriberOverflowError`, the others go on; an encoding failure is logged and fails every current subscriber with `EncodingError`, later subscribers are served; a subscriber is removed and its queue shut down when its scope closes

## Side Effects

- `createBackend` (`start.ts`): writes the system prompt file, the persisted-port file and the MCP connect endpoint file; binds 127.0.0.1
- `createBackend` (`start.ts`): with `widgetPageDir` writes the dev-endpoint file; `stop` removes it
- `createBackend` (`start.ts`): registers `{id, pid, root, apiBase}` in the home db (`homeDir`, else `CONCIV_HOME`, else the platform folder) after the port is known, checks the other rows once in the background, and `stop` retires the row; every home db failure is logged and never stops the engine
- `stop` (`start.ts`): closes the listener first, then disposes the app; `dispose` (`app.ts`) first aborts the engine's one `AbortController` (the signal every model listing got) and waits for each harness's in-flight listing to settle, for at most `GROUP_EXIT_TIMEOUT_MS` (5 s, the grace `@conciv/harness/local-sandbox` gives a stopping CLI) per harness, so a listing's child (`opencode models --verbose`) that exits on SIGTERM has exited before anything else closes and no later step can start one; a listing that has not settled by then (a `models` function that ignores the signal) is named once through `print` and the close goes on without it; then it closes the plugin RPC (pending calls fail `rpc.unavailable`), closes the plugin registry (cleanups run, later plugins first), interrupts every in-flight `experimental.idle` trigger and waits for it to end (so ending the live runs next finds them settled), closes permissions (pending asks are rejected), ends every live run, shuts the persistent ptys down (`ptys.shutdown`), disposes the session search (`search.dispose`), closes the settings storage (`settings.close`), stops watching the trusted browsers file (`browsers.close`), disposes the plugin host runtime (its file watches close there, one node watch handle per watched directory however many files in it are watched), then closes the database; each step runs even when an earlier one fails and the failures are rethrown as one `AggregateError` (`lib/shutdown.ts:runInOrder`)
- `harnessEnv` (`start.ts`): the child harness env is `childEnv` when given, else the whole env read once at start from the engine's ConfigProvider (`configProvider`, default `ConfigProvider.fromEnv({preserveEmptyStrings: true})`, `lib/default-config-provider.ts`; `lib/engine-env.ts:readProcessEnv`); it adds CONCIV_TOKEN and CONCIV_SESSION_ID
- `makeApp` (`app.ts`): opens the SQLite DB, sweeps empty rows, records usage, titles and native ids; the chat plane spawns harness processes; a run a previous engine left running is marked `aborted` while the chat plane is created, and its turn-end hooks run then
- `resolveConfig` (`config.ts`): reads CONCIV_STATE_ROOT, CONCIV_HARNESS, CONCIV_SESSION_ID, CONCIV_CLAUDE_SESSION_ID as Effect Config from the given ConfigProvider (default `ConfigProvider.fromEnv({preserveEmptyStrings: true})`, `lib/default-config-provider.ts`); an explicit option wins over the env value, the env value over the default
- `makeApp` (`app.ts`): reads PATH, CONCIV_HOME and the whole env (for pty shells and, without `harnessEnv`, harness children) once from `configProvider` (default `ConfigProvider.fromEnv({preserveEmptyStrings: true})`, `lib/default-config-provider.ts`), and provides the same provider to the plugin host runtime; `clock` (a `Layer`, from `createBackend`'s `clock`) is provided under the whole plugin host graph, so every Effect clock read and sleep of the host runs on it (a test clock swaps the scheduler too); without it the real clock
