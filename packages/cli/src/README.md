# cli/src

## Overview

The `conciv` CLI, routed with `@bomb.sh/router`. Five top-level commands: `init`, which sets up a project, `tools`, which inspects and drives a running conciv engine over oRPC, `auth`, which logs browsers in and manages the trusted ones, `mcp`, which connects outside agents to conciv and runs the MCP server they use, and `plugin`, which calls a plugin's RPC methods on the running engine. `run.ts` parses argv with the router and switches on the result: help prints the router's usage, version prints the CLI version, a parse failure becomes one JSON error envelope with a suggested fix, and an execute intent runs the handler attached to the route and prints one JSON envelope (`{ok,data}` or `{ok:false,error}`).

## Interface

- `main` (`main.ts`): root route 'conciv' with `version(package.json version)` and children {tools, init, auth, mcp, plugin}
- `conciv init` (`init.ts`): `initCommand` with toggles --yes, --dry-run, --force, --json (all default false)
- `runInitCommand(options, overrides)` (`init.ts`): runs `runInit`; with --json it uses `silentOutput()` and returns {steps,next} or {dryRun:true,plan}; without --json exits 1 on refused or cancelled
- `conciv mcp` (`mcp.ts`): `mcpRoute`, the group holding `serve`, `connect`, `disconnect` and `list`; `<agent>` is `HubAgentSchema` (`mcp.ts`): an init harness id whose init contribution has a `hub` (claude, codex, gemini-cli, opencode)
- `conciv mcp serve --agent <agent>` (`serveCommand` in `mcp.ts`, which imports `runHub` from `hub.ts` only when it runs, so no other command loads the MCP server stack): an MCP server on stdio for outside agents with exactly three tools: `list_tabs` (empty input; answers one text part holding the `TabsListing` JSON (`hub/page.ts`) from `listTabs(home)` in `engine-read.ts`, the open tabs of every live engine with each failing engine under `unreachable`; its description is the agent guidance for matching the user's words to a tab; an unreadable home db is an `isError` reply naming the folder), and `execute_typescript` and `discover_tools`, each with the engine's input plus an optional `tab` (zod `SessionId`). Every call to an engine goes through the typed oRPC contract (`makeRpcClient(apiBase)` from `@conciv/contract`, the `/rpc/*` fetch link, responses validated against the contract): `execute_typescript` is `code.execute`, `discover_tools` is `code.discover`, the tool descriptions are the runner's `code.describe`, awaited before the hub answers any request so the first `tools/list` already carries them (the describe call is bounded at `ENGINE_READ_MS`, 2 s, from `engine-read.ts`, the bound for an engine answering a cheap read; on a timeout or error, or with no engine, fixed text naming `list_tabs` and the `tab` input). With `tab` the call goes to the engine holding that tab (`askTab` on every live engine in parallel, 300 ms, sent without hub headers so a probe never asks for consent) with `sessionId: <tab>`, `conciv-origin: hub` and `conciv-client: <agent>`, so it runs on that tab's session path; the hub keeps one entry per tab (its owner's rpc client, and whether the tab's instructions were sent) and looks up again only when the owner fails at the transport or answers with an error while it says the tab is not open; the first reply for a tab leads with that session's instructions as a text part (`sessions.instructions({sessionId: <tab>})` on the owner, sent without hub headers, bounded at `ENGINE_READ_MS`; an empty text or a failed read sends none); a tab open nowhere answers `TAB_NOT_OPEN: tab <id> is not open; call list_tabs` only when every engine answered its probe; when no engine has it and a probe failed (an error answer, an engine without a route the probe reads or with an answer outside the contract or outside the page answer's shape, which is named `<root> (engine too old; upgrade its @conciv packages)`, a transport error or timeout, named `<root> did not answer (<error>)` like the CLI) the reply names each failing engine root and why instead, as `cannot tell whether tab <id> is open: no engine that answered has it, and <each>; nothing ran`, while a tab one engine reports open runs there whatever the others answered; one open on two engines names both roots; when no engine that answered holds the tab and some registered engine did not answer its 300 ms `/health` or its 300 ms tab probe, the hub asks them once more in one round with `ENGINE_READ_MS` (`checkEngines` with `roots` for the silent ones, then the probe on the ones that now answer, and again on the ones whose probe failed) before it replies, naming every root still silent as `<root> did not answer (<error>)`. Without `tab` the call goes to its runner with no `sessionId` (the engine's outside run): the live engine registered longest ago in the conciv home db (`checkEngines`, 300 ms), picked at startup and kept, with no probe per call; with no engine registered the reply is `no conciv dev server is running; start one and open its page (conciv home folder read: <home>)`, and when no engine that answered is usable (none live, or each one too old or without code mode), it asks every silent root once more with `ENGINE_READ_MS` and tries the ones that now answer; with still none usable it replies `no conciv dev server answered: <root> did not answer (<error>); ...` when none answered, else `no conciv dev server this hub can use is running: <root> (<why>); <root> did not answer (<error>)`, never that none is running. On either path a call refused at connect (`cause.code === 'ECONNREFUSED'`, so nothing ran, e.g. a restarted dev server) or answered `UNAUTHORIZED` (a dev server restarted on its persisted port with a new agent token, so the kept token is stale and nothing ran) is sent once, silently, after a fresh pick; any other transport failure is never re-sent (the block may already have acted on a page): the reply names the engine that failed and says nothing was retried; an error the engine answers (refusal, too old) becomes an `isError` reply. The hub formats the typed `code.execute` result with `codeExecuteReply` from `@conciv/contract`, the same formatter as the engine's `/api/mcp`, caps included. After a `code.execute` or `code.discover` on a tab the hub asks the page plugin, with the engine token only, `pageCall` `queue.outside` with that run's tool calls (the result's `toolCalls`; none for a discover): it answers the still-playing queues of those calls and every finished queue an outside agent started in that session that no reply carried yet, from any hub on the machine, and marks those delivered; each finished queue leads the reply as one capped text part, the plugin's notice, after the tab's instructions on a first reply. The hub keeps no record of earlier calls: the page plugin holds the delivery. A client that negotiated the MCP tasks extension whose call started queues still playing gets a task (`taskId` the hub's own id for that call's queues, `ttlMs` one hour) holding only those queues, never another call's; a task is dropped once every queue of it was delivered in a later reply (a later `tasks/get` then answers unknown task, so a result is never reported twice), and any task older than its `ttlMs` is dropped unread; `tasks/get` polls `pageCall` `queue.wait({waitMs: 0})` on the tab's engine with the engine token only, one poll per task at a time, and answers `completed` with each queue's notice from `queue.wait` appended once all are final, else `working` (a transport failure keeps the task working); a queue the page plugin no longer knows (PLUGIN_RPC `unavailable`: the engine restarted and lost it) ends the task `failed` with a `statusMessage` naming each lost queue and saying its actions may have partly run; `withTaskName` copies a `tasks/*` request's `params.taskId` into its `Mcp-Name` header (`@tanstack/ai-mcp` 1.1.0 `serveMCPStdio` mirrors `Mcp-Name` only for `tools/call`, `prompts/get` and `resources/read`; delete `withTaskName` once ai-mcp mirrors the task id). This is the command each harness's `hub.add` installs (`serveArgv`, `serve-argv.ts`: `npx -y @conciv/cli@<this version> mcp serve --agent <agent>`)
- `conciv mcp connect <agent>` / `disconnect <agent>` / `list` (`mcp.ts`): `createHubConnections(concivHome)` from `@conciv/harness-init/hub`; connect runs the agent CLI's `hub.add` with `serveArgv` and records the connection, disconnect forgets it then runs `hub.remove` best-effort (opencode has none; the envelope's `note` says what was left behind), list prints `[{harness, name, connectedAt}]`; a failed connect or disconnect is a user error envelope. A CLI disconnect revokes like the widget's: the disconnect time it records in the home db voids every running engine's outside Allow
- `conciv auth revoke [ID] [--all]` (`auth.ts`): `runRevoke` lists, revokes one or revokes every trusted browser
- `conciv auth link <url>` (`auth.ts`): `runLink` asks the engine of the current directory (`discoveredEngine`, never the home db) for a one-time login code on its origin with the engine token as `?conciv_auth_token=<token>` and answers `{link, expiresAt}`, where `link` is the http/https page URL with `conciv_otp=<code>` merged into its fragment, keeping the fragment params already there; opening it logs that browser in
- `conciv plugin call <rpcId> <method> [--data|-d <json>]` (`plugin.ts`): `pluginRoute`; parses `--data` as JSON first (invalid JSON is a user failure and nothing is sent; no `--data` omits `input`), finds the engine with `engineOrigin(cwd, env, null)` and calls `plugin.call({rpcId, method, input?})` through `engineAnswer` with a bare `makeRpcClient(origin)`: no session, `conciv-origin` or `conciv-client` header, also when the engine came from the home db fallback, so the terminal calls as the owner; it takes no `--tab` (a root `--tab` is ignored, as for `init`, `auth` and `mcp`); a PLUGIN_RPC or PLUGIN_RPC_INTERNAL error prints the engine's message with its code, the failure's `type` and its `data`, read the same way for both
- `conciv tools` (`tools.ts`): `toolsRoute`, whose children come from the running engine's registry catalog through `dynamic()`: one group per tool-name prefix (`page_snapshot` is `page snapshot`, `acme_beacon` is `acme beacon`; the `page_*` tools are the page plugin's, from core's catalog), a `react` view of the `page_*` tools in category 'react', and one command per prefix-less tool; beside them one fixed command, `tabs` (`tabsCommand`): `listTabs(concivHome)` from `engine-read.ts`, every open tab of every live engine in the home db, the same listing as the hub's `list_tabs`, never through a session so it never raises a permission card (it still waits for the catalog phase every `conciv tools` route waits for)
- The dev-server methods and `open` are the server plugin's, called with `conciv plugin call server <method>`; there is no `conciv tools server` group
- every other group verb calls `rpc.registry.call({name, input})`
- `envelopeFlag` (`envelope.ts`): the --json toggle accepted on every route that does not declare its own `json`
- `tabFlag` (`tab-flag.ts`): `--tab <id>`, zod-parsed as `SessionId`, declared on the root, the tools routes and every tool command that does not declare its own `tab`; `runCli` refuses route models whose `tab`s differ from the flagged one and hands handlers a `CliTarget`
- `runCli(app, argv)` (`run.ts`): parses, resumes the catalog checkpoint with the live catalog, prints help/version or runs the handler, returns an exit code
- `routeFailure` (`arguments.ts`): turns the router's method-not-allowed / unprocessable-content result into a user error envelope
- `handler` / `readHandler` (`router/handler.ts`): attach a run function to a route definition and read it back from the parsed intent
- `wireToolCommand` (`tool-command.ts`): turns a catalog entry's JSON input schema into a router command (positional `argument`, boolean `toggle`, array `multiple()` option, every other field an `option` with a Standard Schema)
- `toolGroupRoute` (`tools.ts`): noun route with one verb per catalog entry (the verb is the name after the first `_`)
- `runRpc(target, call)` (`request.ts`): oRPC call with the session header; with a `--tab` the session is that tab; with `--tab` or an engine found through the home db fallback the call carries `conciv-origin: hub` and `conciv-client: <agent>`, where the agent is the first init harness whose `hub.shellEnv` is set in the CLI's env (`CLAUDECODE`, `CODEX_THREAD_ID`, `GEMINI_CLI`, `OPENCODE`), else `terminal`, so that engine asks the user for Allow before it runs (unless `hubAccess` is `'open'`) and refuses a disconnected agent; only a `--tab` call adds `conciv-named-tab: 1`, so asking tools run with no per-call permission card only for a caller that named its tab, while a home db fallback call (its session is the user's latest, from `sessions.resolve({})`) still gets the Approve card
- `engineOrigin(cwd, env, tab)` (`engine-origin.ts`, async): `{origin, token, outside}`; origin is http://127.0.0.1:&lt;port&gt; or a live engine's `apiBase`, and token the engine token each client sends as `?conciv_auth_token=`; the home db is checked with 300 ms, and when that answer cannot settle the call (no live engine holds the `--tab`, or without `--tab` no engine is live) while some registered engine did not answer its `/health`, or with `--tab` its tab probe (`askTab`), those are asked once more in one round with `ENGINE_READ_MS` before it reports: nothing registered with `--tab` is `no conciv dev server is running; start one and open its page (conciv home folder read: <home>).`; registered but silent is `cannot find tab <id>: <root> did not answer (<error>).` with `--tab` and `no conciv dev server answered: <root> did not answer (<error>).` without, never a count of 0 running and never a guess at the default port 5173, which stays only for nothing registered; live engines without the tab are `tab <id> is not open in any of the N running conciv dev servers`, followed by `; <root> did not answer (<error>)` for every engine whose tab probe failed or that stayed silent; `runRpc` resolves the engine again for each call (the live catalog and the command are two calls), so each call gets the same second ask; `outside` is true when the engine was found through `--tab` or the home db fallback, and `runRpc` then sends `conciv-origin: hub` and `conciv-client: <agent>`, plus `conciv-named-tab: 1` with `--tab` only (see `runRpc`), so that engine treats the call as an outside agent's
- `engine-read.ts`: what `engineOrigin` and the hub share to ask a slow engine again: `ENGINE_READ_MS` (2 s), `askAgain(home, silent)` (`checkEngines` on the silent roots only), `askTab` / `askTabs` (`pageCall` `tabs.list` for the tab with a timeout, sent with the engine token only: open when it lists a browser tab, not open when it lists none or the engine has no page plugin; each answer or its failure kept), and `silence`, the one wording `<root> did not answer (<error>)`; `liveEngines(home)` (`checkEngines` with `PROBE_MS`, 300 ms) and `homeRead`, which turns an unreadable home db into `cannot read the conciv home folder <home>`; `TOO_OLD`; `listTabs(home)`: per live engine in parallel, each bounded at `ENGINE_READ_MS` and sent with the engine token only: `location.get` (the root), `pageCall` `sessions.attached`, and per attached session `sessions.get` (a missing or hidden session is left out) and `pageCall` `tabs.list` (browser tabs focused first; the row's page is the first; a read that fails for any reason other than a too-old answer is written to stderr and the session is listed with no browser tabs), with the project name and branch from `hub/project.ts`, flattened to `TabsListing` rows; an engine with no page plugin lists no tabs; an engine that fails is listed under `unreachable` with its error, or `engine too old; upgrade its @conciv packages` when it answers outside the contract or outside the page answer's shape, beside every engine `checkEngines` reported silent
- `hub/page.ts`: the page plugin as the cli reads it, by name: `PAGE_NAMESPACE` (`page`), `pageCall(rpc, method, input, signal)` (`plugin.call` to rpc `experimental.page` for `sessions.attached`, `tabs.list`, `queue.outside` or `queue.wait`, the answer zod-parsed; a PLUGIN_RPC `rpc.unavailable` answer, the page plugin not loaded, is null), `pollQueue` (`queue.wait` with `waitMs: 0`; a queue the plugin does not know, or no page plugin, is `gone`), `engineOutdated(error)` (the contract's too-old errors or a failed page answer parse), and the `TabsListing` type
- `hub.ts` holds only the MCP server: the three tools, `tasks/get` and `withTaskName`; each handler runs an Effect (`Effect.runPromise`, with the request's abort signal) on the hub's machines, built once in a scope that closes when stdin ends. Each machine is a state union, an event union and a pure transition, and the Effect that runs it:
  - `hub/engines.ts`: picking the runner (none, picking, asking again, picked, unusable; events listed, answered, asked again); the picked runner is one `Cache` entry, a failed pick is not kept, and it is dropped when a call on it was refused, unauthorized or failed at the transport
  - `hub/tabs.ts`: finding a tab's engine (unknown, finding after the first round, owned, failed; events probed, probed again); owners are a keyed `Cache` (one lookup per tab at a time, a failed lookup not kept), and the greeting is read once per tab
  - `hub/call.ts`: one table for a call on the runner or on a tab (sent, resent once, checking whether the tab is still open, answered, failed; effects drop, resend, check)
  - `hub/tasks.ts`: the queue tasks (working, settled, dropped when delivered or expired; events delivered, created, polled, expired), polls in a `FiberMap` keyed by task id
- `hub/project.ts`: `projectName(root)` (`name` from `<root>/package.json`, null when absent or unparsable) and `currentBranch(root)` (the nearest `.git/HEAD` at or above the root, a worktree `gitdir:` file included), re-read on every listing
- `writeOutcome` / `writeFailure` / `CliOutcome` (`envelope.ts`); `userFailure` / `readFailure` (`failure.ts`); `closest` (`arguments.ts`)
- Subdirectories:
  - init: [./init/README.md](./init/README.md) - the `conciv init` pipeline

## Invariants

- `routeFailure` (`arguments.ts`): a route without a command is 'No command given', an unknown word under a route with children is 'Unknown command' with a `closest` suggestion, an unknown flag is 'Unknown flag' with 'Did you mean --x?', a positional passed as a flag says how to pass it, an extra word is 'Unexpected argument', and a schema issue is prefixed with the flag or `<ARG>` it belongs to
- option flags accept both the camelCase and the kebab-case spelling of the field name; toggles accept `--x` and `--no-x`; arguments after `--` are not bound
- `-h`/`--help` and `-v`/`--version` are claimed by the router anywhere in argv; only the root supports version
- `settle` (`run.ts`): every `dynamic()` increment is resumed with the live catalog of the target engine before help, version or execute is decided; with no engine running, `conciv tools ...` (help included) fails with the 'No conciv dev server' envelope; the catalog target is the first `--tab` in argv before `--` (root, tools route, group route or after the verb), and the handler runs on that same tab; a parsed `--tab` that differs from it fails as a user error
- the CLI carries no tool declarations of its own: no `@conciv/extension*` or `@conciv/tools` import, guarded by the dependency-closure and prod-closure tests
- `readFailure` (`failure.ts`): tagged errors become user errors; anything else is 'unexpected' with a bug-report hint
- `declaredSessionId` (`request.ts`): an invalid CONCIV_SESSION_ID throws a user failure
- `engineAnswer` (`request.ts`): oRPC-defined errors, 4xx responses and an `APPROVAL_DENIED` refusal (the user declined, or the agent is disconnected) become user failures, printed with the message and no stack or bug hint; network failures are offline and throw 'No conciv dev server on &lt;host&gt;'; `runRpc` and `runLink` both go through it
- `runLink` (`auth.ts`): no engine state, or a state file without an engine token, is a user failure
- `ServerStateSchema` (`engine-origin.ts`): port must be an integer 1-65535; lookup order: with `--tab` the live engine whose tab probe says open (else a user failure naming the tab); otherwise CONCIV_PORT, .conciv/server.json in cwd or an ancestor, the most recently registered live engine in the home db (`CONCIV_HOME`), then 5173

## Side Effects

- `hub.ts`: reads the conciv home db and checks each engine (`checkEngines`, process alive, root present, `/health` id); talks to an engine only through its typed oRPC client (`makeRpcClient(apiBase)`), keeping the picked runner and one client per open tab, dropped when a call is refused or unauthorized (nothing ran) or when the runner changes, the calls whose queues it still owes per tab and the queue tasks in memory; with no live engine a call answers an MCP error naming the home folder; serves until stdin ends

- `bin.ts`: sets NO_COLOR=1 when stdout is not a TTY and FORCE_COLOR is unset; runs only when invoked directly; sets process.exitCode
- `writeOutcome` / `writeFailure` (`envelope.ts`): write JSON to stdout
- `runCli` (`run.ts`): prints usage (the router's plain `printHelp`) or the version with console.log
- `runRpc` (`request.ts`): network oRPC calls to the engine; read CONCIV_SESSION_ID and cache the resolved session id
- `runLink` (`auth.ts`): reads .conciv/server.json walking up from cwd and calls `auth.issueCode` on that engine; sends no session, `conciv-origin` or `conciv-client` header
- `engineOrigin` (`engine-origin.ts`): reads CONCIV_PORT and .conciv/server.json walking up from cwd, then the home db and each live engine's tab probe (`askTab`)
- `liveCatalog` (`run.ts`): calls rpc.registry.catalog on the target engine when argv reaches `conciv tools`
- `existingPath` (`tool-command.ts`): resolves a path-format argument to its absolute path when `access` finds it, else keeps it as given
- `runInitCommand` (`init.ts`): runs the init pipeline, which writes files and installs packages
