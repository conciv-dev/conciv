# frontend-defaults/src

## Overview

The one entry of `@internal/frontend-defaults` (`ConcivApp` over a `Platform` a host builds, `frontend-defaults.tsx`), the router factory (`router.tsx`), the dev-server entry (`entry-standalone.tsx`, browser history and the engine named by `?core`), drive mode (`drive/`), the generated TanStack route tree and module declarations for `?inline` css/woff2 imports.

`ConcivApp` owns the rpc client, login and trust, the active-session stamp and teardown, so a host only builds the platform and renders. The router's QueryClient never lets queries go stale on their own (`staleTime: Infinity`): data changes through a server push, an invalidation after our own action, or a window refocus (`refetchOnWindowFocus: 'always'`).

Subdirectories: [app](./app/README.md), [composer](./composer/README.md), [data](./data/README.md), [lib](./lib/README.md), [pane](./pane/README.md), [routes](./routes/README.md), [runtime/persistence](./runtime/persistence/README.md), [settings](./settings/README.md), [shell](./shell/README.md)

## Invariants

- `frontend-defaults.tsx:tabHistory`: only the last screen of the tab is restored, never a back stack (one last URL per window); a fresh tab starts at `/`; a reload restores before the first render, with no wait for trust.
- `frontend-defaults.tsx:ConcivApp`: the api base starts as the one `platform.engine()` gives at mount; a rebind is the `conciv:rebind` window event, and its handler is the only writer of the base: both the first base and a rebound one enter normalized (`normalizeApiBase` from `@conciv/client`: origin and path with no trailing slash; the empty same-origin base stays empty), so the rpc socket and the plugin bundles join onto a clean base and a rebind to an equivalent spelling of the current base is ignored; it sets the base, then resets the cached queries, then asks for trust; an empty base or the current one is ignored, and servers mode does not listen. The rest is derived from the base: the rpc client reads it on every call, the connection generation counts the distinct bases, and the engine-stored navigation lives only while the first base holds
- `router.tsx:createConcivRouter`: the dispose function runs at most once (`once`)
- `router.tsx:wireEngine`: reachability and the trust subscription are re-set up only when the connection changes, and the previous setup is cleaned up first
- `router.tsx:createConcivRouter` (`engine.watch`): when trust flips from untrusted or revoked to trusted, it invalidates the queries that ended in error
- `router.tsx:watchTrust`: whenever the connection's trust is or becomes revoked (`engineLock` answers `revoked`: a token this browser held was refused), it calls `AppData.forgetLocalDrafts`; every way a held trust is lost ends in that status: the rpc socket or another engine socket closed with 1008, a 401 on a call made with a token, and a stored token the trust check refuses. An untrusted connection (no token held, as on a first load before the code exchange, or on an engine port this browser has no token for) clears nothing, because the draft database is shared by every tab of the page origin. `wireEngine`'s `locked()` reads `engineLocked` (untrusted or revoked) for `makeAppData`'s `lockedOut` and the draft store's `writable`
- `router.tsx:createConcivRouter`: `defaultPendingMs` 300, `defaultPendingMinMs` 500, scroll restoration off; defaults `connected=()=>true`, `connectionGeneration=()=>0`, `plugins=[]`, `servers=false`
- `routeTree.gen.ts`: generated by `tsr generate`; do not edit
- `runtime/browser-tab/open-browser-tab.ts:openBrowserTab`: the widget is one browser tab with one id and connection id for its life (`runtime/plugin/host-apis.tsx`); it holds `tabs.open` for the routed session while the engine is connected and compatible, and lets it go when either changes. The tab's `url` is redacted (user info, secret query and hash values, then every `BrowserTabUrl` a plugin contributes) and cut to the schema's limits. Focus, blur, visibility, route (Navigation API, when there is one) and title changes are sent with `tabs.state`, retried while the engine answers UNAVAILABLE. A session the engine does not have yet (NOT_FOUND) is opened once its `session.created` arrives; a session of another project (UNAVAILABLE) shows the danger notice `This page couldn’t open in this session. Reload the page or start a new session.`
- `runtime/plugin/plugin-boundary.tsx:createTabCrash`: a crashed plugin panel tab offers Retry, and after a retry, focus goes to the new Retry button when the content crashes again, else to the tab's content

## Side Effects

- `frontend-defaults.tsx:ConcivApp`: listens for the `conciv:rebind` window event while a bound app is mounted
- `frontend-defaults.tsx:tabHistory`: reads this tab's last screen from sessionStorage `conciv-last-screen` at boot and writes the href there on every navigation
- `entry-standalone.tsx`: reads `window.location.search` and renders into `#app`
- `router.tsx:wireEngine`: calls `setupEngineReachability(connection)` from `@conciv/client` on the engine connection the host passed in `Platform.engine` and subscribes to its trust, stopping when the connection changes or the router is disposed; the shell never opens a connection itself: a rebind or a picked server asks the host through `Platform.connect`
