# src

## Overview

The one entry of `@conciv/app` (`ConcivApp` over a `Platform` a host builds), the app-internal router factory, the dev-server entry, the generated TanStack route tree and module declarations for `?inline` css/woff2 imports.

## Interface

- `createConcivRouter(config)` (`router.tsx`): builds the Solid router with a QueryClient whose queries never go stale on their own (`staleTime: Infinity`; data changes through a server push, an invalidation after our own action, or a window refocus, `refetchOnWindowFocus: 'always'`), AppData, engine reachability and router context
- `disposeConcivRouter(router)` (`router.tsx`): calls `router.options.context.dispose()`, which stops the engine watch and disposes the AppData once
- `ConcivRouterContext`, `ConcivRouterConfig`, `ConcivEnvironment`, `ConcivTimings` types (`router.tsx`)
- `routeTree` (`routeTree.gen.ts`): generated; full paths `/`, `/panel`, `/quick`, `/panel/$sessionId`, `/panel/connect`, `/panel/latest`, `/pip/$sessionId`, `/panel/$sessionId/`, `/panel/$sessionId/$view`, `/panel/$sessionId/settings` and its tab routes
- `index.tsx`: `ConcivApp` renders the whole app from a `Platform` (the engine to talk to, how navigation is stored (`'tab'`, `'browser'`, or `{history}`, any TanStack `RouterHistory`, used as the router's history as given), the root to render into, settings, plugins, and optional `timings`: engine connection timings for every connection the app holds, the chat run reconnect, the query retry delay, and the session picker's search and preview waits); it owns the rpc client, login and trust, the active-session stamp and teardown, so a host only builds the platform and renders
- `entry-standalone.tsx`: the dev-server host; renders `ConcivApp` into `#app` with browser history and the engine named by `?core`
- `css.d.ts`: `*.css?inline` and `*.woff2?inline` string module declarations
- Subdirectories: [app](./app/README.md), [composer](./composer/README.md), [data](./data/README.md), [lib](./lib/README.md), [pane](./pane/README.md), [routes](./routes/README.md), [settings](./settings/README.md), [shell](./shell/README.md)

## Invariants

- `index.tsx:tabHistory`: only the last screen of the tab is restored, never a back stack (as opencode's per-window last URL); a fresh tab starts at `/`; a reload restores before the first render, with no wait for trust.
- `index.tsx:ConcivApp`: the api base starts as the one `platform.engine()` gives at mount; a rebind is the `conciv:rebind` window event, and its handler is the only writer of the base: both the first base and a rebound one enter normalized (`normalizeApiBase` from `@conciv/contract`: origin and path with no trailing slash; the empty same-origin base stays empty), so `/health`, the rpc socket and the plugin bundles join onto a clean base and a rebind to an equivalent spelling of the current base is ignored; it sets the base, then resets the cached queries, then asks for trust; an empty base or the current one is ignored, and servers mode does not listen. The rest is derived from the base: the rpc client reads it on every call, the connection generation counts the distinct bases, and the engine-stored navigation lives only while the first base holds
- `router.tsx:makeGuardedDisposer`: the dispose function runs at most once
- `router.tsx:wireEngine`: reachability and the trust subscription are re-set up only when `apiBase()` changes, and the previous setup is cleaned up first
- `router.tsx:watchEngine`: when trust flips from untrusted or revoked to trusted, it refetches the queries that ended in error
- `router.tsx:watchEngine`: whenever the connection's trust is or becomes revoked (`engineLock` answers `revoked`: a token this browser held was refused), it calls `AppData.forgetLocalDrafts`; every way a held trust is lost ends in that status: the rpc socket or another engine socket closed with 1008, a 401 on a call made with a token, and a stored token the trust check refuses. An untrusted connection (no token held, as on a first load before the code exchange, or on an engine port this browser has no token for) clears nothing, because the draft database is shared by every tab of the page origin. `wireEngine`'s `locked()` reads `engineLocked` (untrusted or revoked) for `makeAppData`'s `lockedOut` and the draft store's `writable`
- `router.tsx:createConcivRouter`: `defaultPendingMs` 300, `defaultPendingMinMs` 500, scroll restoration off; defaults `connected=()=>true`, `apiBase=()=>''`, `connectionGeneration=()=>0`, `plugins=[]`, `servers=false`
- `routeTree.gen.ts`: generated by `tsr generate`; do not edit
- `runtime/plugin/plugin-boundary.tsx:PluginBoundary`: a crash in one plugin renders only its fallback and never unmounts the host; a crashed plugin panel tab (`createTabCrash`) offers Retry, and after a retry, focus goes to the new Retry button when the content crashes again, else to the tab's content

## Side Effects

- `index.tsx:ConcivApp`: listens for the `conciv:rebind` window event while a bound app is mounted
- `index.tsx:tabHistory`: reads this tab's last screen from sessionStorage `conciv-last-screen` at boot and writes the href there on every navigation
- `entry-standalone.tsx`: reads `window.location.search` and renders into `#app`
- `router.tsx:wireEngine`: calls `setupEngineReachability(connection)` from `@conciv/client` on the engine connection the host passed in `Platform.engine` and subscribes to its trust, stopping when the connection changes or the router is disposed; the shell never opens a connection itself: a rebind or a picked server asks the host through `Platform.connect`
- `runtime/plugin/plugin-boundary.tsx:reportCrash`: `console.error` with the crashed plugin's name and the error
