# composer

## Overview

Composer toolbar: element grab, new session, compact and the Connect agents menu, the connected agents row above the composer, the composer prompt's model menu (which also switches the harness), a session combobox.

## Interface

- `ComposerActions` (`actions.tsx`): grab element, new session, compact, `ConnectAgentsMenu`
- `ConnectAgentsMenu` (`connect-agents-menu.tsx`): "Connect agents" menu (and the same items in the composer overflow menu) with one "Connect <name>" item per `meta.hubAgents` `installs` entry; hidden while that list is empty; an item is disabled while a connect or disconnect of that agent is pending
- `ConnectedAgents({onDisconnected})` (`connected-agents.tsx`): the `Connected agents` group (`display: contents`, so each chip is its own item in the strip's row and wraps only when the row overflows) leading the strip above the composer, before the extension `status` slot: one chip per `meta.hubAgents` `connections` entry (Clawd for Claude, the plug icon otherwise, the name, and a `Disconnect <name>` icon button on every chip), a `Connecting <name>…` / `Disconnecting <name>…` spinner chip (`role="status"`, polite) per pending change, taken from the pending mutations' own variables so it survives a `meta.hubAgents` refresh that already dropped the row; hidden when nothing is connected, connecting or disconnecting; `onDisconnected` runs when a disconnect settles (the pane returns focus to the composer)
- `useHubConnections()` (`hub-connections.ts`): polls `meta.hubAgents` every 3 s and on window focus, so a connect or disconnect made outside the widget shows up; `installs`, `connections`, `connecting`, `disconnecting`, `connect(install)`, `disconnect(connection, onSettled)`; pending changes come from `useMutationState` over the oRPC `meta.connectHub` / `meta.disconnectHub` mutation keys, so the menu and the row (separate components) see the same pending set
- `Clawd({class})` (`clawd/clawd.tsx`): static Claude mascot SVG, MIT, see `clawd/README.md`
- `useModelMenu(onClose)` → `ModelMenu` (`{popover, state, search, expand, confirm, ask, settle}`), `SessionModelPrompt({sessionId, menu, running})` (`model-selector.tsx`): the model menu, owned by the pane so `/model` can open it (`popover().setOpen(true)`): a ui-kit-system `usePopover` machine plus one store of its search text, unfolded `Older versions` sections and pending harness-switch confirm; `onClose` runs whenever the popover closes (unless the confirm is open) and when the confirm settles. The composer prompt is a mono trigger (lowercase model name sliding in on change, the harness in parentheses when more than one harness is available, then signal bars for the effort that fill and drain one bar at a time) followed by a separate `❯` caret; it renders the picker through `Popover.RootProvider` (`lazyMount`, `unmountOnExit`), a `Model` dialog holding one ui-kit `Listbox` built from `meta.harnesses` with a `Search models` field (`Listbox.Input`, `autoHighlight`): one option group per harness, the session's own first (labelled with its name, visible only when more than one harness is available); each group lists its first model group (name and description, check on the selected one), capped at 4 rows when longer (the default, the selected one and the newest others) with a `N more models, type to search` line, since a harness like OpenCode lists hundreds and rendering them all stalls every model switch and each later group as a `Collapsible` section (`Older versions`, folded unless it holds the current model); a search lists every model of every harness, folded sections included, whose name, id or harness name contains it (`useFilter` `contains`, case and accent insensitive); a harness that listed no models says `<harness> has no usable models`; below a separator an `Effort` section: a `SegmentGroup` of the current model's `efforts` in order (`xhigh` reads `High+`) and a fixed-height note for the chosen level
- `SessionSelector` (`session-selector.tsx`): session combobox (`pill` | `bar`) over a virtual list with Today/Yesterday/Earlier header rows, server-side search, a clear-search button, new session (renaming lives in the panel header title)
- `SessionPreview` (`session-preview.tsx`): the read-only preview beside the session picker; a kit `Popover` (controlled, `modal={false}`, `autoFocus={false}`, `lazyMount`, `unmountOnExit`) anchored to the picker content (`right-start`, flipping to `left-start` then `bottom-start`), titled `Preview of <title>` with the project beside it (another project's hit names its own project, reads its transcript from that project's `cwd`, and adds a kit `ClipboardCopyButton` `Copy resume command` over its own `createResumeCopy`, so it shows `Copied` on itself and never opens the row's tooltip; the button keeps its 28px look with a 44px hit area from an `after:-inset-2` pseudo-element), rendering the session through the real ui-kit-chat `Thread` over a read-only `Chat`

## Invariants

- `actions.tsx:ComposerActions`: the grab button is disabled when `grab.grabbable()` is false
- `model-selector.tsx:SessionModelPrompt`: the current harness is the session row's `harnessKind`, else `defaultHarness`; shown model falls back session model, then that harness's `defaultModel`, then null; a current harness with no models still shows the prompt, labelled with the harness name, so the menu opens and another harness can be picked; rows and the prompt name the harness in parentheses (`Opus 5.5 (Claude)`) only when more than one harness is available; the trigger shows effort bars only when the session effort is one the current model lists; the Effort section is hidden when the current model has no `efforts`; picking an effort keeps the popover open, picking a model (click or Enter, even the current one) closes it; a null effort leaves no segment checked and the note reads the model default; the popover opens on the search field, arrows move from the current model (or, while searching, from the first match), Enter picks; Escape clears a non-empty search and otherwise closes; closing clears the search and refolds the sections; every close returns focus to the composer; nothing matching shows `No models match “<search>”`
- `model-selector.tsx:SessionModelPrompt`: picking another harness's model switches the harness with that model (`sessions.switchHarness` with `model`); those rows are disabled while a run is in progress or a switch is pending; an empty chat switches at once, a chat with messages first confirms with the history size estimated from the messages' text length / 4 (never the session's context usage, which counts the old harness's system prompt and tools); picking it closes the popover first and the confirm mounts only once the popover finished exiting (`onExitComplete`), so the two never overlap; the popover never restores focus itself (`restoreFocus: false`), the composer gets it once the confirm is cancelled or confirmed; another harness whose model list failed shows a retry button; a failed catalog shows `Couldn’t load the other harnesses: Retry loading models` and keeps the session's own models; a current harness whose list failed names the prompt `Couldn’t load models` and offers `Couldn’t load models: Retry loading models`; the composer never waits on another harness's model list
- `session-selector.tsx:SessionSelector`: rows name their harness only when more than one harness is available
- `session-selector.tsx:SessionSelector`: the preview opens 600 ms after (Ark HoverCard's default `openDelay`) a row is highlighted (`@tanstack/solid-pacer` `createDebouncer`), then follows the highlight at once; a highlight cleared by the pointer leaving only cancels a pending open; typing or clearing the search closes the preview (zag clears the highlight on every input change), so the next highlight waits again; closing the picker closes the preview
- `session-preview.tsx:SessionPreview`: Escape closes the preview first and the picker second through zag's layer stack (the picker content and input are `persistentElements`, focus returns to the input); `Alt+ArrowRight` focuses the thread scroller and `Alt+ArrowLeft` returns to the input (Ark `useHotkeys`, only while the preview is mounted), the footer names both keys and Escape through `useFormatHotkey` in ui-kit-system `Kbd`; the search's `matched` words reach every message through ui-kit-chat `MarkdownHighlightProvider`; the thread lands on the newest message and loads earlier pages when scrolled near the top; loading shows `ConversationSkeleton`, a failed load shows a `role=alert` row with Retry
- `session-selector.tsx:select`: every pick of a this-project row (Ark `onSelect`, pointer or Enter, the active session included) reaches `onActivate`; only a pick of another session announces `Switched to <title>`; a row from another project goes to `openElsewhere` instead and never activates; an empty id does nothing
- `session-selector.tsx:openElsewhere`: a hit from another project (`cwd` set) is never opened here: selecting it (click or Enter) copies its `resume` command through that row's `createResumeCopy`, a kit `Tooltip` controlled by the copy status and anchored to the row says "Copied" or "Copy failed", and the app announce says the same; the picker stays open for those rows (`closeOnSelect` is off while such a row is highlighted); a hit with no command announces that it lives in that project; its meta line ends with the project folder name (`TruncatedText`)
- `createResumeCopy` (`resume-copy.ts`): one kit `createClipboardCopy` per resume command, labelled "Copied" / "Copy failed", announcing each outcome

## Side Effects

- `hub-connections.ts:useHubConnections`: `meta.connectHub` mutation; success posts `<name> connected. Ask any <name> session for your conciv tab.` and invalidates `meta.hubAgents`; `meta.disconnectHub` mutation; success posts `<name> disconnected.` followed by the outcome's `note` when there is one (opencode: its leftover `opencode.json` entry; a harness whose remove failed: why) and invalidates `meta.hubAgents`; a refusal posts the CLI's message as a warning; a thrown call posts `Couldn’t connect <name>. Try again.` / `Couldn’t disconnect <name>. Try again.`
- `model-selector.tsx:SessionModelPrompt`: `rpc.sessions.model` and `rpc.sessions.effort` mutations, each invalidates sessions and announces a failure
- `model-selector.tsx:SessionModelPrompt`: `rpc.sessions.switchHarness` mutation, refetches the session's `meta.models`, `meta.commands`, `sessions.list` and `sessions.get`, re-hydrates the chat, announces `Switched to <model> (<harness>).`, failures go to the notice surface
- `session-selector.tsx:SessionSelector`: `sessions.list` infinite query, or `sessions.search` while the search is non-empty (the input is Ark-controlled through `inputValue`: the picker store keeps the text typed in this picker, and a memo folds it with the root route's `sessionSearch` term, showing the typed text until the term changes to something other than that text, which is another pane's picker on `/quick` writing it, and then the term itself; `selectionBehavior="preserve"` so closing and reopening keeps it; `onInputValueChange` for the reasons `input-change` and `clear-trigger` stores the text and feeds one `@tanstack/solid-pacer` `createDebouncer` (`SEARCH_WAIT_MS`) that writes the trimmed term to `sessionSearch` with `replace: true`, flushed at once when the input empties, and the search query reads the term from that param, so a reload restores it; the visually hidden `Combobox.Label` "Search sessions", the input, the loader, the clear button and the kit `Switch` "All projects" sit in a `<search>` landmark; the switch writes the `allProjects` param at once and the search sends it as `everywhere`; 30 per page, the previous page kept as placeholder data, a "Loading more" row at the end of the virtual list fetches the next page, sessions de-duplicated by id across pages), `sessions.get` for the active session, a `sessions.changes` live query (`experimental_liveOptions`) whose index version is part of the search query key (`infiniteKey` plus the version, passed as `queryKey`) so a new version refetches the search; the plain list never reads the index, so its key stays stable and it refreshes through `invalidateSessions` (opening the picker) without dropping the pages already loaded; rows are bucketed into Today / Yesterday / Earlier against a minute clock (`createDateNow`); each row reads `Edited <time> · <size>` with the time through ui-kit-system `RelativeTime` (Ark `Format.RelativeTime`, formatted when the row renders; opening the picker invalidates the session queries, so rows re-render with fresh times) and the transcript size through ui-kit-system `ByteSize` (no size slot when the meta carries none), and its accessible name comes from a visually hidden label (`aria-labelledby`); a search hit (`SessionHit`) marks its `matched` words in the title (Ark `Highlight`, `ignoreCase matchAll exactMatch`, the same zag `highlightWord` engine the excerpt's Streamdown uses) and, when it carries an `excerpt`, renders it under the title through ui-kit-chat `Markdown compact highlight={matched}`, clipped at 3 lines (`h-12`, a bottom `mask-image` fade) and wired as the row's description (`aria-describedby`); rows keep fixed sizes (`EXCERPT_ROW_SIZE` for a hit with an excerpt, `SESSION_ROW_SIZE` otherwise), and only the marks animate (`anim-mark` on `--chat-highlight` with a hairline accent underline, `motion-reduce` off)
- `session-preview.tsx:SessionPreview`: `sessions.preview` infinite query of the transcript the hit matched in (a `SessionHit`'s `preview` reference, a plain `SessionMeta`'s `native`; 40 messages per page, `before` is the oldest message id loaded, `staleTime` 60 s, `gcTime` 5 min, no retry), mounted only while the preview is open, no prefetch
