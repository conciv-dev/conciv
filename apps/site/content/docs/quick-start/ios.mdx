title: iOS
description: Attach conciv to a native iOS app running in the simulator.
---

<Callout type="warn">
  Early alpha: the bridge protocol and the Swift API can change without notice. The iOS simulator is the only supported
  target. Use the SwiftPM version that matches your `@conciv/*` npm version.
</Callout>

conciv drives a native iOS app the way it drives a web page. The Swift SDK floats a transparent overlay and the
conciv button over your own UI, and loads the widget from the engine your dev server runs. The package needs iOS 17.

<Steps>
<Step>

### Add the package

Add the SwiftPM mirror to your app. In `Package.swift`:

```swift title="Package.swift"
.package(url: "https://github.com/conciv-dev/conciv-swift.git", from: "0.0.1"),
```

Then add the product to the target that shows your UI:

```swift title="Package.swift"
.product(name: "ConcivWidget", package: "conciv-swift"),
```

In an Xcode project, use File > Add Package Dependencies and paste the same URL.

</Step>
<Step>

### Attach

Call `ConcivWidget.attach()` once, from your scene delegate or your SwiftUI `App` init. It finds the key window
itself, reads the engine address from the `CONCIV_URL` environment variable, and finds the engine on its own when
the variable is unset.

```swift
ConcivWidget.attach()
```

The button is the animated mascot by default (`launcher: .mascot`). Pass `.native` for a round native button instead:

```swift
ConcivWidget.attach(launcher: .native)
```

<Callout type="warn">
  `attach()` does nothing in a Release build: no overlay, no web view, no engine address. Run a Debug build to see the
  widget.
</Callout>

</Step>
<Step>

### Run

Start your dev server with conciv in its config, then launch the app in the simulator. The overlay and the button
appear over your UI.

</Step>
</Steps>

## Let the agent build and run the app

Add `@conciv/plugin-ios` (`pnpm add -D @conciv/plugin-ios`) and the agent can build, launch, screenshot and read the
logs of the app for you. This is the config of the demo app in the conciv repo:

```ts title="vite.config.ts"
import {fileURLToPath} from 'node:url'
import {defineConfig} from 'vite'
import conciv from '@conciv/it/plugin/vite'

export default defineConfig({
  server: {watch: {ignored: ['**/ConcivDemo/**', '**/ConcivWidget/**']}},
  plugins: [
    conciv({
      port: 4599,
      plugins: [
        [
          '@conciv/plugin-ios',
          {
            projectRoot: fileURLToPath(new URL('./ConcivDemo', import.meta.url)),
            bundleId: 'dev.conciv.ConcivDemo',
            simulator: 'iPhone 17 Pro',
            buildMode: 'swiftc',
            extraSourceDirs: ['../ConcivWidget/Sources/ConcivWidget'],
          },
        ],
      ],
    }),
  ],
})
```

`port` is optional. The app finds an engine on any port through the pairing file below; a fixed port keeps the address
the same across restarts, which helps when you launch the app by hand with `CONCIV_URL`.

The agent gets four tools: `ios_build`, `ios_run`, `ios_screenshot` and `ios_logs`. `ios_build` and `ios_run` ask
first: see [Approvals](/docs/usage/approvals). `ios_run` passes the engine address to the app as
`SIMCTL_CHILD_CONCIV_URL`, which the app reads as `CONCIV_URL`. With the plugin configured, the agent's system prompt
also tells it that it is working on a native app: there is no hot reload, and a Swift edit reaches the screen only
after `ios_build` and `ios_run`.

## How the app finds the engine

`CONCIV_URL` is the engine's address with no `/widget` at the end, for example `http://127.0.0.1:4599`. The SDK adds
`/widget` itself. Without `CONCIV_URL`, the SDK:

<Steps>
  <Step>
    Reads `~/.conciv/dev-endpoint.json`, which the engine writes when it starts and removes when it stops, and uses it
    if its address answers `GET /health`.
  </Step>
  <Step>
    Otherwise tries `http://127.0.0.1` on ports 4599, 8787 and 3000, and takes the first that answers as a conciv
    engine.
  </Step>
</Steps>

<Callout>
  The SDK reads only `~/.conciv/dev-endpoint.json`. If your config sets `devEndpointDir`, the engine writes the file
  elsewhere and the app falls back to the port probe. Set `CONCIV_URL` to be sure which engine the app uses.
</Callout>
