title: iOS
description: Attach conciv to a native iOS app running in the simulator.
---

<Callout type="warn">
  Early alpha. The iOS SDK is on the `0.0.x` line, so the bridge protocol and public API can change
  without notice. The iOS simulator is the only supported target today. Match the SwiftPM version to
  the `@conciv/*` npm version you run.
</Callout>

conciv drives a native iOS app the same way it drives a web app: a transparent overlay and launcher
sit above your own UI, and the agent reads and acts through them. The Swift SDK loads the widget from
your dev core, so the native side stays thin and everything routes through the same engine.

<Steps>
<Step>

### Add the package

Add the SwiftPM mirror to your app. In `Package.swift`:

```swift title="Package.swift"
dependencies: [
  .package(url: "https://github.com/conciv-dev/conciv-swift.git", from: "0.0.1"),
],
```

Then add the product to the target that shows your UI:

```swift title="Package.swift"
.product(name: "ConcivWidget", package: "conciv-swift"),
```

In an Xcode project, use File > Add Package Dependencies and paste the same URL.

</Step>
<Step>

### Attach

Call `ConcivWidget.attach()` once, from your scene delegate or your SwiftUI `App` init. It finds the
key window itself, reads the core endpoint from the `CONCIV_URL` environment variable, and falls back
to auto-discovery when the variable is unset. That one line is the whole integration.

```swift title="SceneDelegate.swift"
import ConcivWidget

// inside scene(_:willConnectTo:options:)
ConcivWidget.attach()
```

```swift title="App.swift"
import ConcivWidget

@main
struct MyApp: App {
  init() {
    ConcivWidget.attach()
  }
  // ...
}
```

Then run your dev server (a vite host with the conciv plugin) and launch the app in the simulator. The
transparent overlay and launcher appear over your own UI.

<Callout type="warn">
  `attach()` compiles to a no-op in a Release build: no overlay, no WebView, no dev-core URL. Nothing
  conciv ships to TestFlight or the App Store, so a Release build shows nothing. Run a Debug build to
  see the widget.
</Callout>

</Step>
</Steps>

## Let the agent build and run the app

Everything above is all you need to see the widget. Optionally, give the agent the `ios` extension so
it can build, launch, and screenshot the app for you (via the `ios.build` and `ios.run` tools) instead
of you rebuilding by hand.

<Accordions type="single">
<Accordion title="Configure the ios extension">

Point the extension at your native project in the vite config:

```ts title="vite.config.ts"
import {fileURLToPath} from 'node:url'
import {defineConfig} from 'vite'
import conciv from '@conciv/it/plugin/vite'

export default defineConfig({
  plugins: [
    conciv({
      port: 4599,
      extensions: {
        ios: {
          projectRoot: fileURLToPath(new URL('./ios', import.meta.url)),
          bundleId: 'dev.conciv.YourApp',
          simulator: 'iPhone 17 Pro',
        },
      },
    }),
  ],
})
```

Pin `port` so the simulator always loads the same URL across restarts. From the agent panel you then
run `ios.build` and `ios.run` to build and launch the app. Without this block the widget still works;
only the `ios.*` build tools are unavailable.

</Accordion>
</Accordions>

## How the app finds the core

`attach()` needs the core's API base, the origin with no `/native` suffix (for example
`http://127.0.0.1:4599`). The SDK appends `/native` itself. It resolves the base in this order:

- `CONCIV_URL` if set. `ios.run` injects it for you as `SIMCTL_CHILD_CONCIV_URL`, which the app reads
  as `CONCIV_URL`; to launch by hand pass `SIMCTL_CHILD_CONCIV_URL=http://127.0.0.1:4599 xcrun simctl
  launch booted dev.conciv.YourApp`.
- Otherwise the pairing file a freshly started dev core writes at `~/.conciv/dev-endpoint.json`. The
  simulator shares the host filesystem, so this is the zero-config path. The file only exists while a
  dev core is running, so restart the core if discovery finds nothing.

## Next

The agent works the native app the same way it works a web page: grab a view, ask about it, and let it
find and edit the Swift. See [Usage](/docs/usage) for what the agent can do, and
[`@conciv/extension-ios`](https://github.com/conciv-dev/conciv/tree/main/packages/extensions/ios) for
the transport tiers, pairing, and re-pair behavior behind the native path.
