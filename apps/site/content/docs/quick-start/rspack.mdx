---
title: Rspack
description: Add conciv to an Rspack app.
---

In a development build the Rspack plugin puts the widget on every page of your app, and in watch mode (the dev server
or `--watch`) it also starts the engine. A one-off development build only adds the widget, so run the dev server or
turn on watch mode. A config with `mode: 'production'` or no `mode` counts as production and gets neither;
`mode: 'development'` and `mode: 'none'` get both.

<Tabs items={['init', 'By hand']}>

<Tab value="init">

```bash
npx @conciv/cli@latest init
```

init finds Rspack in your `package.json`, installs `@conciv/it`, and adds conciv to the `plugins` of your Rspack
config: `require` and `conciv.default()` in a CommonJS config, `import` and `conciv()` in an ES module config. If it
cannot read the shape of your config, it prints the snippet to paste instead. See [Quick start](/docs/quick-start) for
what it asks.

</Tab>

<Tab value="By hand">

<Steps>
<Step>

### Install

```bash
npm install -D @conciv/it
```

</Step>
<Step>

### Add the plugin

```js title="rspack.config.js"
const conciv = require('@conciv/it/plugin/rspack')

module.exports = {
  plugins: [conciv.default()],
}
```

Set `mode: 'development'` in the config, or pass `--mode development`, for the widget and the engine.

</Step>
</Steps>

</Tab>

</Tabs>

<Callout>
  Rspack is less complete than [Vite](/docs/quick-start/vite): the agent cannot read your dev server's config or module
  graph, and its `server_*` tools answer `no dev server is attached to conciv`. The chat and the page tools work in the
  widget your dev build serves.
</Callout>

The plugin picks the engine port before the first watch build and builds the widget with it. See
[Configuration](/docs/configuration#port) for how the port is chosen. If the engine cannot start, the build fails with
`conciv: the engine failed to start` and the reason. Stopping the watch, or closing the compiler, stops the engine.
