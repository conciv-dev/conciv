---
title: Rspack
description: Add conciv to an Rspack app.
---

In a development build the Rspack plugin puts the widget on every page of your app, and in watch mode
(the dev server or `--watch`) it also starts the engine. A one-shot development build only adds the
widget, so run the dev server or turn on watch mode. A config with `mode: 'production'` or no `mode` counts as
production and gets neither; `mode: 'development'` and `mode: 'none'` get both.

<Tabs items={['init', 'Manual']}>

<Tab value="init">

```bash
npx @conciv/cli@latest init
```

init detects Rspack from your package.json, installs `@conciv/it` with your package manager, and
adds the `@conciv/it/plugin/rspack` plugin to your Rspack config.

init prints the whole plan and asks once before it writes anything; `--yes` approves it up front and
`--dry-run` prints it and exits. It refuses a dirty git tree; commit first or pass `--force`.

</Tab>

<Tab value="Manual">

<Steps>
<Step>

### Install

```bash
npm install -D @conciv/it
```

</Step>
<Step>

### Add the plugin

```js title="rspack.config.js"
const conciv = require('@conciv/it/plugin/rspack')

module.exports = {
  mode: 'development',
  plugins: [conciv.default()],
}
```

</Step>
</Steps>

</Tab>

</Tabs>

<Callout>
  Rspack is less complete than [Vite](/docs/quick-start/vite). The live page bridge is Vite only. Chat, tests, and
  approvals work in the widget your dev build serves.
</Callout>

The engine listens on the `port` you pass when it is free. With no `port`, it prefers the port it
used last time in this project, else a port picked for the project (from 24170 up), so two projects
started together never ask for the same one. When the port is taken, the plugin picks a free port before the first watch build and builds the widget with it, so
two projects can run side by side. If the engine still cannot start, the build fails with the reason.
