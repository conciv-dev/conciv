<Callout type="warn">
  With conciv in your Rspack config, `rspack serve` starts the engine, but the widget is not on your page, and conciv
  has no supported way to add it yet. For the widget, use [Vite](/docs/quick-start/vite) or
  [Next.js](/docs/quick-start/nextjs).
</Callout>

## Add it

<Tabs items={['init', 'By hand']}>

<Tab value="init">

```bash
npx @conciv/cli@latest init
```

init finds Rspack in your `package.json`, installs `@conciv/it`, and adds conciv to the `plugins` of your Rspack
config. It then prints an "Inject the widget" card: the `@conciv/widget/global` bundle and the `widgetUrl` option it
names do not add the widget.

</Tab>

<Tab value="By hand">

```bash
npm install -D @conciv/it
```

```js title="rspack.config.mjs"
import {rspack} from '@rspack/core'
import conciv from '@conciv/it/plugin/rspack'

export default {
  entry: './src/index.js',
  plugins: [new rspack.HtmlRspackPlugin({title: 'rspack probe'}), conciv()],
  devServer: {port: 5302},
}
```

</Tab>

</Tabs>

## What runs

<TypeTable
  type={{
    'rspack serve': {
      required: true,
      type: 'dev',
      description: 'Starts the engine on 127.0.0.1 and writes .conciv/server.json. Your page gets no conciv button.',
    },
    'rspack build': {
      required: true,
      type: 'build',
      description: 'Also starts the engine, and the build process keeps running until you stop it.',
    },
  }}
/>

Without `port`, the engine takes the port it used last time, or a free one. With `port`, it listens on exactly that
port; if the port is in use, the process exits with `EADDRINUSE`.
