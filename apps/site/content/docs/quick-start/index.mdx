Pick your framework, copy the prompt, and paste it into your coding agent:

<SetupPrompt />

What you get:

- `@conciv/it` in your dev dependencies, and conciv in your build config.
- A conciv section in `AGENTS.md`, so your agent knows the conciv commands.
- Your dev server running, with a conciv button in the corner of your app.
- A login link, or a 6-digit code to type in the panel.

## Give it a first task

Ask your agent, in your terminal or in the conciv panel:

<CopyPrompt text="Look at the page I have open in conciv. Change the main heading to say Hello from conciv. Edit the source file, then check that the page shows the new text." />

The agent reads the live page, finds the heading in your source, and edits it. Your dev server reloads the page.

<Callout>
  The chat runs an agent CLI on your machine, `claude` by default. It must be on the `PATH` of the shell that starts
  your dev server, and logged in. See [Harnesses](/docs/harnesses) for the others.
</Callout>

## Set up by hand

<Accordions>
<Accordion id="by-hand" title="Run conciv init yourself">

<Steps>
<Step>

### Run init

Run it in your app folder, the one with `package.json`:

```bash
npx @conciv/cli@latest init
```

</Step>
<Step>

### Answer its questions

init asks four things:

- Teach these agent harnesses about conciv? Every agent CLI it found is checked.
- Connect these agents to conciv, so they can find and drive your open conciv tabs?
- Wire the detected config for conciv? It names your framework.
- Add the `@conciv/skills` docs pack? This one is off by default.

Then it shows the plan and asks "Run this plan?".

</Step>
<Step>

### Read what it did

For each step it prints a line, and the diff of every config it edits. A step it cannot do ends as a card with a
snippet to paste.

</Step>
<Step>

### Start your app and log in

Start your dev server, then open your app. Click the conciv button and type the 6-digit code your dev server prints.
See [Logging in](/docs/usage/logging-in).

</Step>
</Steps>

To skip init, wire the config yourself: see your framework's page.

</Accordion>
</Accordions>

## Edge cases

<Accordions>
<Accordion id="flags" title="init flags">

- `--yes` takes every default and asks nothing. Use it in CI or from an agent.
- `--dry-run` prints the plan and changes nothing.
- `--force` runs even with uncommitted git changes.
- `--json` prints one JSON result. Pair it with `--yes` or `--dry-run`.

</Accordion>
<Accordion id="stops" title="When init stops before it writes anything">

- No `package.json` in the folder: `no package.json here — run init from your app directory`.
- Uncommitted changes, without `--force`: `uncommitted changes — commit first or pass --force`.
- No terminal to ask in, without `--yes` or `--dry-run`: `Non-interactive terminal — re-run with --yes or --dry-run`.

</Accordion>
<Accordion id="undo" title="Stopping init halfway">

Press Ctrl-C while it runs. init puts your config back as it was.

</Accordion>
<Accordion id="production" title="Production builds">

conciv runs in your dev server only. `vite build` leaves it out. A Next.js production server does not start it.

</Accordion>
</Accordions>
