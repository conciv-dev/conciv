---
title: webpack
description: Add conciv to a webpack app.
---

In a development build the webpack plugin puts the widget on every page of your app, and in watch mode
(the dev server or `--watch`) it also starts the engine. A one-shot development build only adds the
widget, so run the dev server or turn on watch mode. A config with `mode: 'production'` or no `mode` counts as
production and gets neither; `mode: 'development'` and `mode: 'none'` get both.

<Tabs items={['init', 'Manual']}>

<Tab value="init">

```bash
npx @conciv/cli@latest init
```

init detects webpack from your package.json, installs `@conciv/it` with your package manager, and
adds the `@conciv/it/plugin/webpack` plugin to your webpack config.

init prints the whole plan and asks once before it writes anything; `--yes` approves it up front and
`--dry-run` prints it and exits. It refuses a dirty git tree; commit first or pass `--force`.

</Tab>

<Tab value="Manual">

<Steps>
<Step>

### Install

```bash
npm install -D @conciv/it
```

</Step>
<Step>

### Add the plugin

```js title="webpack.config.js"
const conciv = require('@conciv/it/plugin/webpack')

module.exports = {
  mode: 'development',
  plugins: [conciv.default()],
}
```

</Step>
</Steps>

</Tab>

</Tabs>

<Callout>
  webpack is less complete than [Vite](/docs/quick-start/vite). The live page bridge is Vite only. Chat, tests, and
  approvals work in the widget your dev build serves.
</Callout>

The engine listens on port 24170, or on the `port` you pass, when that port is free. When it is
taken, the plugin picks a free port before the first watch build and builds the widget with it, so
two projects can run side by side. If the engine still cannot start, the build fails with the reason.
