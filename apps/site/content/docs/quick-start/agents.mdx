Agents use the conciv CLI directly. `conciv tools` is self-describing: agents run
`conciv tools --help` to discover every command, and the CLI finds your running dev server itself.
No MCP config, no addresses, nothing to maintain.

<Tabs items={['init', 'Manual']}>

<Tab value="init">

```bash
npx @conciv/cli@latest init
```

init scans for installed harnesses (claude, codex, gemini-cli, opencode, pi) and lists what it found in the plan
it prints before doing anything - `● claude` for a harness it will teach, `○ codex (not found)` for
one that is not installed. Pick `Adjust` at the prompt to choose the harnesses in a multiselect.

Approving the plan writes a marked conciv section into AGENTS.md (and CLAUDE.md if you keep one),
whether or not any harness was found; the section names the harnesses you picked in a
`Set up for:` line. Re-running init updates that section in place and reports it as
`already wired` when it is current.

claude is the one harness with a deeper integration: init generates the plugin files under
`.conciv/claude-connect` and installs them through claude's native plugin manager, scoped to the
project. If the claude CLI is not selected the step resolves as `skipped: not selected`, and if the
plugin manager fails init prints the two commands to run yourself.

init writes the marketplace, the plugin manifest, the MCP bridge, and a `conciv` skill that tells
claude to reach for the conciv CLI before any browser MCP tool, but no `.mcp.json`: the conciv
dev server writes that manifest when it connects to a claude session, so the plugin always points at
the address that is actually serving.

init prints the whole plan and asks once before it writes anything; `--yes` approves it up front and
`--dry-run` prints it and exits. It refuses a dirty git tree; commit first or pass `--force`.

</Tab>

### Teach your agents the conciv CLI

Paste this section into AGENTS.md (and CLAUDE.md if you keep one):

```md
<!-- conciv:start -->

## conciv

This project has conciv installed. For everything in the running browser, use the conciv CLI through Bash (`conciv tools page ...`, `conciv tools react ...`, `conciv tools server ...`). Use browser MCP tools only when a conciv command cannot do what you need.

### When to use conciv instead of the browser MCP

Use the browser MCP for plain navigation, clicks and screenshots. For anything about why the page
looks or behaves the way it does, use conciv first. Every command prints JSON. Start with
`conciv tools page snapshot` to get a ref or a selector for the element you care about.

- Which component rendered an element, and the source file and line: `conciv tools react locate <selector>`
- Props, state, hooks and context of a live component: `conciv tools react inspect <selector>`
- Every mounted instance of a component by name: `conciv tools react find <ComponentName>`
- A value that stays stale, a list that does not refresh, cached data: `conciv tools react inspect` on the component, then `conciv tools page eval` to read the store or query cache on `window`
- An element that cannot be clicked or is not visible: `conciv tools page query <selector>` for its box and styles, `conciv tools page eval` with `getComputedStyle` and `elementFromPoint`
- Browser console errors and warnings: `conciv tools page console`
- Unexpected re-renders or a memo that never updates: `conciv tools react track <selector>`
- Module graph, transformed source, a forced hot update: `conciv tools server graph|transform|reload`

Run `conciv tools --help` for every command. Every command needs the project's conciv dev server running.

### MCP sandbox

conciv is also connected via MCP. Capabilities are discovered inside the sandbox with `await external_catalog({})`, never a static list.

<!-- conciv:end -->
```

### Install the conciv claude plugin

The plugin files are generated, not hand-written, so this one piece goes through init:

```bash
npx @conciv/cli@latest init
```

Pick claude at the prompt. init writes `.conciv/claude-connect`, including the `conciv` skill, and installs the
plugin for you.
Run the two commands yourself only if init reports the step as manual:

```bash
claude plugin marketplace add .conciv/claude-connect
claude plugin install conciv-connect@conciv --scope local
```

init writes no `.mcp.json` under the plugin. The conciv dev server writes that manifest when it
connects to a claude session, so the plugin points at the address that is actually serving.
