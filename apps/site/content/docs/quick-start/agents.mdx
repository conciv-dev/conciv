Connect the agent in your terminal to conciv. It can then find your open conciv tabs and use the same tools the chat
in the panel uses. `conciv init` does this for every agent it finds. To connect one yourself, pick your agent:

<Tabs groupId="agent" persist items={['Claude Code', 'Codex', 'Gemini CLI', 'opencode']}>

<Tab value="Claude Code">

```bash
npx @conciv/cli@latest mcp connect claude
```

This adds the `conciv-hub` MCP server to Claude Code for your user. It runs `claude mcp add -s user conciv-hub ...`.

</Tab>

<Tab value="Codex">

```bash
npx @conciv/cli@latest mcp connect codex
```

This adds the `conciv-hub` MCP server to Codex. It runs `codex mcp add conciv-hub ...`.

</Tab>

<Tab value="Gemini CLI">

```bash
npx @conciv/cli@latest mcp connect gemini-cli
```

This adds the `conciv-hub` MCP server to Gemini CLI for your user. It runs `gemini mcp add -s user conciv-hub ...`.

</Tab>

<Tab value="opencode">

```bash
npx @conciv/cli@latest mcp connect opencode
```

This adds the `conciv-hub` MCP server to opencode. It runs `opencode mcp add conciv-hub ...`.

</Tab>

</Tabs>

On success it prints:

```text
{"ok":true,"data":{"connected":"claude"}}
```

## Try it

With your dev server running and your app open, ask your agent:

<CopyPrompt text="List my open conciv tabs. Then read the page in the first one and tell me what is on it." />

The agent gets three tools:

- `list_tabs` lists the open conciv tabs of every running dev server on this machine.
- `discover_tools` lists the tools it can call on a tab.
- `execute_typescript` runs those tools on the tab you name.

The panel shows the same connections. A **Connected agents** row sits above the composer. A **Connect agents** menu
sits in the composer toolbar.

## What init sets up

- A conciv section in `AGENTS.md`, between `<!-- conciv:start -->` and `<!-- conciv:end -->`. It tells the agent to
  use `conciv tools page ...` for the browser, and `conciv tools --help` for the rest.
- The same section in `CLAUDE.md`, when yours does not import `AGENTS.md`. With Claude Code and no `CLAUDE.md`, init
  creates one that holds `@AGENTS.md`.
- For Claude Code, the `conciv-connect` plugin in `.conciv/claude-connect`. It holds a conciv skill and an MCP bridge,
  for this project only.
- The `conciv-hub` MCP server in each agent you picked.

Re-running init updates the section in place.

## Edge cases

<Accordions>
<Accordion id="commands" title="The other mcp commands">

- `conciv mcp disconnect <agent>` stops conciv answering that agent, and removes it from the agent's config.
- `conciv mcp list` lists the connected agents.
- `conciv mcp serve --agent <agent>` is the server the agent runs. connect registers it for you. You do not run it
  yourself.

</Accordion>
<Accordion id="opencode-disconnect" title="Disconnecting opencode">

The `conciv-hub` entry stays in `opencode.json`. conciv refuses it until you connect again.

</Accordion>
<Accordion id="claude-plugin" title="The Claude Code plugin failed to install">

init prints the commands to run yourself:

```bash
claude plugin marketplace add .conciv/claude-connect
claude plugin install conciv-connect@conciv --scope local
claude plugin update conciv-connect@conciv --scope local
```

The plugin's bridge reads the engine address from `.conciv/mcp-endpoint.json`. The engine writes it when it starts.

</Accordion>
<Accordion id="agents-md" title="init could not write AGENTS.md">

When the file has a start marker with no end marker, init does not edit it. It prints the section as a card to paste.

</Accordion>
<Accordion id="jobs" title="Long running work">

Work a call leaves running, such as a queue of page actions, is a job on the engine. Its result comes back once, at
the top of the next `execute_typescript` reply on that tab. An agent whose MCP client supports tasks gets a task
instead. The task completes when the job ends.

</Accordion>
<Accordion id="access" title="Asking before an agent uses a tab">

A connected agent can use any open tab with no question. Set `hubAccess: 'project'` to have the tab ask first. See
[Configuration](/docs/configuration) and [Approvals](/docs/usage/approvals).

</Accordion>
</Accordions>
