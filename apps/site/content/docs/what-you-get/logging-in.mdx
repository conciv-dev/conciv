---
title: Logging in
description: The first time a browser opens conciv, it asks for a code from your dev server's terminal.
---

The engine only answers browsers it trusts. The first time a browser opens the panel, conciv asks for a
6-digit code, and the engine prints that code in the terminal running your dev server.

## Log in with the code

<Steps>
<Step>

### Open the panel

A browser that has not logged in shows the conciv button with a warning mark, labelled "Authorize conciv". Click
it. The **Authorize conciv** dialog opens instead of the chat: "Enter the 6-digit code printed in the terminal running your dev server."

</Step>
<Step>

### Read the code in your terminal

Opening the dialog asks the engine for a code. The engine prints it in a box:

```text title="dev server terminal"
╭──────────────────────────────────────────────────────╮
│ conciv: a browser asks to connect to this engine     │
│ From:    Chrome 156 | macOS at http://localhost:5199 │
│ Code:    541045                                      │
│ Link:    http://localhost:5199/#conciv_otp=541045    │
│ Expires: 13:48:32                                    │
╰──────────────────────────────────────────────────────╯
```

</Step>
<Step>

### Type the code

Type the six digits. conciv sends them when the last digit is in, and the chat opens. The browser keeps its
login, so the next visit goes straight to the chat.

</Step>
</Steps>

<Callout title="The code">
  A code works once and lives 5 minutes. Opening the dialog again while a code is live reuses it. After 5 wrong tries
  the code is dropped: click **Send a new code** and the engine prints a fresh one.
</Callout>

## Log in with the link

The `Link:` line in the box is your page with the code in its address: `#conciv_otp=<code>`. Open it in the
browser you want to log in. conciv reads the code on load, logs the browser in, then removes the code from the
address bar.

To get a link without opening the dialog first, run `conciv auth link` with the page's address, from your
project folder:

```bash
.conciv/bin/conciv auth link http://localhost:5199/
```

```text title="output"
{"ok":true,"data":{"link":"http://localhost:5199/#conciv_otp=449191","expiresAt":1794743322685}}
```

The dev server creates `.conciv/bin/conciv` when it starts. The command reads `.conciv/server.json` to find the
engine, so the dev server has to be running.

## See and revoke logged-in browsers

Each logged-in browser is a row in `.conciv/trusted-browsers.json`. List them:

```bash
.conciv/bin/conciv auth revoke
```

```text title="output"
{"ok":true,"data":{"revoked":[],"trusted":[{"id":"80effeb3","hash":"80effeb3d7327283fb553964dd26a1917b4c373a5b1582dda463d5fe179a0a5e","browser":"Chrome 156 | macOS","origin":"http://localhost:5199","grantedAt":1794743013798}]}}
```

Revoke one by its `id`, or all of them with `--all`:

```bash
.conciv/bin/conciv auth revoke 80effeb3
.conciv/bin/conciv auth revoke --all
```

A revoked browser is cut off at once: the panel shows "This browser is no longer authorized to use conciv."
with a **Log in** button that opens the code dialog again.

## What the panel says

<Accordions type="single">
  <Accordion title="Log in to use conciv on this page.">
    This browser has no login for this engine. Click **Log in** and enter the code from your terminal.
  </Accordion>
  <Accordion title="This browser is no longer authorized to use conciv.">
    Someone ran `conciv auth revoke` for this browser, or with `--all`. Click **Log in** to log in again.
  </Accordion>
  <Accordion title="That code didn't match. Check your terminal and try again.">
    The digits differ from the code in the newest box in your terminal. After 5 misses the code is dropped; click **Send
    a new code**.
  </Accordion>
  <Accordion title="That code expired. Send a new code and use the one your terminal prints.">
    The code is older than 5 minutes, or it was dropped after 5 misses. Click **Send a new code**.
  </Accordion>
  <Accordion title="conciv lost connection to the engine.">
    The engine stopped answering, usually because the dev server stopped. Start it again and click **Retry**.
  </Accordion>
  <Accordion title="conciv couldn't reach the engine. Check that the dev server is still running.">
    The panel could not load from the engine. Start the dev server again and click **Retry**.
  </Accordion>
</Accordions>

## Vite DevTools

With Vite DevTools in your Vite plugins, conciv opens as a panel in the DevTools dock, and the DevTools page logs
itself in. No code is asked for. It shows in `conciv auth revoke` as `via Vite DevTools`.
