A plugin adds tools, skills and RPC methods to the engine, and panels and buttons to the widget. conciv's own
features are plugins too, written with the same SDK, `@conciv/plugin`.

## The two halves

<Cards>
  <Card
    title="Engine half"
    description="Runs inside the engine. Adds tools for the agent, skills, hooks and RPC methods. Every plugin has one."
  />
  <Card
    title="Browser half"
    description="Runs in the widget. Adds panels, slots, composer pills and settings pages. Optional."
  />
</Cards>

The two halves talk through the plugin's RPC contract, a file both import. The same contract is what you call from
the terminal with [`conciv plugin call`](/docs/build-a-plugin/terminal).

```ts title="rpc.ts"
import {z} from 'zod'
import {Rpc} from '@conciv/plugin/rpc'

export const Hello = Rpc.define({
  id: 'hello',
  methods: {
    greet: {input: z.object({name: z.string()}), output: z.object({message: z.string(), count: z.number()})},
  },
  events: {},
})
```

A project plugin is one `.ts` or `.js` file (engine half only) or a folder. In a folder, `index.ts` is the engine half,
`rpc.ts` the contract and `plugin-experimental.cjs` the prebuilt browser half.

## See your plugins

Open **Settings > Plugins** in the widget. It lists your installed and project plugins by id. A plugin with a browser
half also gets a **Server** badge (it has an engine half too), **Reload**, which loads it again, and a switch that
turns it off and on. A plugin with only an engine half shows its id alone; turn it off with a [`-id`
entry](/docs/plugins/install#turn-a-plugin-off) instead. A plugin that failed to load shows its error, with **Show
details** for the full text. Built-in plugins are listed only when one fails, with a **Built-in** badge.
