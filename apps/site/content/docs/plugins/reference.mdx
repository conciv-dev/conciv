Look up an import or a field here. Each table is generated from the published packages' types. The list under it says
what each row is for. The [guides](/docs/plugins) show each one in use.

## What to import

| Import                                     | You import it when you                                       |
| ------------------------------------------ | ------------------------------------------------------------ |
| `@conciv/backend-plugin-api`               | write an engine part with async and await                    |
| `@conciv/backend-plugin-api/effect`        | write an engine part with Effect                             |
| `@conciv/backend-plugin-api/effect/plugin` | type a helper function that takes the Effect `ctx`           |
| `@conciv/backend-plugin-api/effect/rpc`    | type the registration your RPC handlers belong to, in Effect |
| `@conciv/protocol/schema/rpc`              | declare an RPC contract that both parts import               |
| `@conciv/protocol/schema/tool`             | fail a tool call with a `Tool.Error` in Effect               |
| `@conciv/frontend-plugin-api`              | write a browser part: panels, slots, pills, cards, settings  |
| `@conciv/frontend-plugin-api/vite`         | build a browser part into the bundle the engine serves       |
| `@conciv/react`                            | draw a browser part's UI with React components, in your app  |
| `@conciv/preact`                           | draw a browser part's UI with Preact components, in your app |
| `@conciv/client`                           | read data in a browser part through the widget's query cache |
| `@conciv/backend-test-utils`               | start a real engine in a test and script the agent           |

What the browser part's `Plugin.define` takes:

<auto-type-table path="@conciv/frontend-plugin-api" name="Plugin.Definition" />

- `stores`: values the widget keeps for the plugin. See [Add settings](/docs/plugins/guides/settings).
- `icons`: SVG icons of your own, named for `ctx.ui.Icon`.
- `beforeRegister`: runs once with the options, before any plugin's setup, for hooks the page needs early.
- `enforce`: orders `beforeRegister` calls: every `pre`, then the rest, then every `post`.
- `setup`: runs once when the widget loads the browser part. It has no `id`. It takes the engine part's.

## Engine ctx

What `setup` or `effect` gets as `ctx`. In the Promise style each domain returns a `Promise`. In the Effect style the
same fields return an `Effect`.

<Tabs groupId="plugin-api" persist items={['Promise', 'Effect']}>
<Tab value="Promise">

<auto-type-table path="@conciv/backend-plugin-api" name="Plugin.Context" />

</Tab>
<Tab value="Effect">

<auto-type-table path="@conciv/backend-plugin-api/effect/plugin" name="Context" />

</Tab>
</Tabs>

- `app`: the running conciv, with its version, release channel and platform.
- `location`: where the engine runs. Its `directory` is your project folder.
- `options`: the options from the plugin's config entry, as JSON.
- `agent`: change the agent profiles, such as their permission rules.
- `event`: follow the engine's events.
- `model`: list the models, and add or change them.
- `permission`: ask the user before an action. See [Ask for permission](/docs/plugins/guides/permission).
- `plugin`: list the plugins the engine loaded.
- `rpc`: answer an RPC contract, or call another plugin's. See [Share an RPC method](/docs/plugins/guides/rpc).
- `browserTabs`: list the browser tabs a session's page plugin sees.
- `job`: start, wait on and cancel background jobs.
- `session`: list, create and drive sessions.
- `skill`: add, change and remove skills. See [Add a skill](/docs/plugins/guides/skill).
- `storage`: a key-value store kept for your plugin, and a folder for its files.
- `tool`: add, change and remove tools, and hook into their calls. See [Add a tool](/docs/plugins/guides/tool).
- `servers`: the dev servers the engine knows about.
- `bundler`: hook into your app's bundler, with `resolveId`, `load` and `transform`.
- `experimental`: APIs that can still change. Its `generate` asks a model for text, decisions or an image. It is
  `undefined` in the Effect style.

- `name`: what the agent calls. Use letters, digits and `_`.
- `description`: how the agent decides when to call it.
- `input`: the schema the agent's input must match. The engine checks it before your code runs.
- `output`: the schema of the result's `output`.
- `options`: `codemode`, `namespace`, `permission` and `pinned`. See
  [Tools and code mode](/docs/tools-and-code-mode).
- `execute`: runs one call. It returns a `Promise` or an `Effect` of the result.

What `execute` gets as its second argument:

- `sessionId`: the chat the call runs in.
- `agent`: the agent profile running the call.
- `messageId`: the agent message that holds the call, when there is one.
- `id`: the call's own id.
- `origin`: where the call came from: `chat` for the widget, `hub` for an agent outside it.
- `progress`: sends an update the card can show while the call runs.
- `signal` (Promise): aborts when the user stops the turn.
- `cancel` (Effect): set when the call can be cancelled.

What `execute` returns:

<auto-type-table path="@conciv/protocol/schema/tool" name="Result" />

- `output`: the result the agent reads, matching the `output` schema.
- `content`: text or files for the agent, in place of or beside `output`.
- `metadata`: data for the card. The agent does not read it.

## An RPC method

One entry of a contract's `methods`:

<auto-type-table path="@conciv/protocol/schema/rpc" name="Method" />

## Browser ctx

What the browser part's `setup` gets as `ctx`:

<auto-type-table path="@conciv/frontend-plugin-api" name="Context" />

- `id`: the plugin's id, from its engine part.
- `options`: the options from the plugin's config entry.
- `signal`: aborts when the plugin reloads or stops.
- `client`: calls the engine: `client.rpc(contract)` and `client.event.subscribe`.
- `add`: adds an entry to a registry, such as `Panel` or `ToolRegistry`. `list` reads a registry.
- `provide` and `use`: share an in-process contract with another plugin.
- `layout`: panel tabs, scroll offsets and the settings page.
- `sessions`: the sessions of open tabs, and the mounted one.
- `screen`: the mounted session's screen and its composer.
- `storage`: stores for keys known only at run time.
- `system`: the clipboard, saving files and opening URLs.
- `desktop`: opens a file in the user's editor, when the engine can.
- `dialogs`: opens dialogs that close with their owner.
- `toast`: short messages in a corner of the window.
- `tabs`: the open session tabs, across engines.
- `links`: routes local links to the plugins that handle them.
- `ui`: the widget's own Solid components, such as `Icon`, `Button`, `Switch` and `SettingsRow`.
- `app`: the widget's version, release channel and platform.
- `appearance`: the user's appearance settings.
- `overlay`: a layer over the page, under the widget.
- `router`: the widget's route.
- `keybinds`: the keybinds of published commands.
- `servers`: the dev servers the engine knows about.
- `attention` and `commands`: not implemented yet, always `undefined`.

## Browser registries

### Panel

<auto-type-table path="@conciv/frontend-plugin-api" name="Panel" />

- `id`: the panel's name, unique in your plugin.
- `region`: where the tabs go. It is required, and `'pane'` is the only value.
- `list`: the tabs to show. It runs again when what it reads changes.
- `render`: draws a tab's content once.
- `close`, `closed` and `restore`: run as the user closes a tab, and bring it back.
- `focus`: runs when one of your tabs is selected.
- `normalize`, `mobile` and `transient`: how stored tabs are matched, shown on a phone, and kept.

One tab that `list` returns:

<auto-type-table path="@conciv/frontend-plugin-api" name="PanelTab" />

- `id`: the tab's id, stored in the user's open tabs.
- `title`: the tab's name, shown when it has no `label`.
- `label`: what the tab strip draws.
- `pinned`: always in the strip.
- `closable`, `draggable` and `tabbable`: how the user can close, move and reach the tab.
- `transient`, `fallback`, `group`, `missing`, `hidden` and `file`: how the strip treats the tab.

### Slot

<auto-type-table path="@conciv/frontend-plugin-api" name="Slot" />

- `at`: the place: `session.header`, `session.status`, `window.bottom` or `page.overlay`.
- `order`: sorts the slot among others at the same place.
- `render`: draws the content once. A `page.overlay` slot also takes `hides`.

### ComposerPill

<auto-type-table path="@conciv/frontend-plugin-api" name="ComposerPill" />

- `id`: the pill's name.
- `order`: sorts it among the other pills.
- `show`: what the pill looks like for one composer, or `undefined` to hide it.
- `menu`: your own content for the popover the pill opens.

What `show` returns:

<auto-type-table path="@conciv/frontend-plugin-api" name="ComposerPillView" />

- `label`: the pill's text, and `title` the popover's heading.
- `icon` and `tone`: the pill's icon, and its colour for success, warning or danger.
- `run`: what a click does.
- `rows`: a menu of rows, each with its own `run`, in place of `run`.

### SettingsPage

<auto-type-table path="@conciv/frontend-plugin-api" name="SettingsPage" />

- `id`: the entry's name.
- `page` and `section`: put it on the General page, or in its General section.
- `title` and `icon`: how the entry reads.
- `entries`: what the settings search finds.
- `render`: draws the page, section or row.

### ToolRegistry

<auto-type-table path="@conciv/frontend-plugin-api" name="ToolRegistry" />

- `name`: the tool whose calls this card draws.
- `render`: draws one call.
- `errorComponent`: draws a failed call.

What `render` gets:

<auto-type-table path="@conciv/frontend-plugin-api" name="ToolProps" />

- `tool`, `input` and `status`: the tool's name, the agent's input, and where the call is.
- `output`: the result as JSON text, once the call ends.
- `error`: the message of a failed call.
- `metadata`: the call's metadata, such as progress updates.
- The other props are how the widget opens, locks and lays out the card.

## Render in any framework

Every `render` above takes a Solid component. Three helpers turn your own UI into one, so a browser part can draw in
another framework:

| Helper         | Import                        | Draws with                                        |
| -------------- | ----------------------------- | ------------------------------------------------- |
| `mountRender`  | `@conciv/frontend-plugin-api` | plain DOM, or any framework you mount by hand     |
| `reactRender`  | `@conciv/react`               | a React component, inside your app's React tree   |
| `preactRender` | `@conciv/preact`              | a Preact component, inside your app's Preact tree |

Each one fits every render a registry takes: a panel, a slot, a settings page, a pill's menu, a code block and a
tool card.

- `mountRender` calls your mount function with an element and the props, once the element is in the page. The
  mount returns a cleanup, which runs when the widget removes the contribution.
- `props.current()` gives the props as they are now. `props.subscribe(listener)` calls the listener at once and on
  every change, and returns a stop function.
- The React and Preact helpers draw through a portal into your app's tree, so your providers reach the component.
  They need a `<ConcivWidget>` from the same package above them, and throw without one.
- `<ConcivWidget>` mounts the widget itself. Set `widget: false` on the conciv bundler plugin, so the page does not
  get a second one.
- A plugin folder's browser part is built with `experimental()`, which compiles Solid. React and Preact UI lives in
  your app as a `Plugin.Setup`. You give it to `<ConcivWidget>` in its plugins.
- The widget's reactive values, such as `run.status()`, are Solid signals. So is a store's value. Outside Solid, read
  them in the function you pass to `ctx.add`, which runs again when they change.
