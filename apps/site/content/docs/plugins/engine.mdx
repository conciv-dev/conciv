The engine part runs inside the conciv engine. Write it with [Effect](https://effect.website) from
`@conciv/plugin/effect`. The promise entry, `@conciv/plugin`, does the same without Effect: see
[The promise entry](#the-promise-entry).

A plugin in your project's `conciv/plugins` folder imports the SDK from the project's own dependencies:

```bash
pnpm add -D @conciv/plugin effect zod
```

A published plugin lists `@conciv/plugin` as a peer dependency and a dev dependency, and `effect` and `zod` as
dependencies. See [Publishing](/docs/plugins/publishing).

## Define the plugin

`Plugin.define({id, effect})` is the default export of the engine part. The engine runs `effect(ctx)` when it loads
the plugin. Each `ctx` domain returns an `Effect`.

```ts title="packages/plugins/test-runner/src/index.ts"
export default Plugin.define({
  id: 'test-runner',
  effect: (ctx) =>
    Effect.gen(function* () {
      const manager = yield* Effect.sync(() => {
        const config = testRunnerConfig.parse(ctx.options)
        const adapter = getRunner(config.runner) ?? vitest
        return adapter.create(ctx.location.directory)
      })
      yield* register(ctx, manager)
      yield* ctx.skill.transform((editor) => editor.add(info))
      const registration = yield* registerRpc(ctx.rpc, manager).pipe(Effect.orDie)
      const events = yield* Queue.unbounded<TestEvent>()
      yield* Stream.fromQueue(events).pipe(
        Stream.runForEach((event) =>
          registration.events
            .emit('event', event)
            .pipe(Effect.catch(reportUndelivered), Effect.catchDefect(reportUndelivered)),
        ),
        Effect.forkScoped({startImmediately: true}),
      )
      const unsubscribe = manager.subscribeRaw((event) => {
        Queue.offerUnsafe(events, event)
      })
      yield* Effect.addFinalizer(() =>
        Effect.sync(unsubscribe).pipe(Effect.andThen(Effect.promise(() => manager.stop()))),
      )
    }),
})
```

The effect runs in a scope that closes when the plugin stops or reloads. Every tool, skill and RPC handler it
registers is removed then, every fiber it forked with `forkScoped` is interrupted, and every finalizer runs.

`Plugin.define<R, E>` takes the services the effect needs and the error it may fail with. `Plugin.Services` is the
scope plus the platform services the engine provides: `FileSystem`, `Path` and `ChildProcessSpawner`. A failure must
be a tagged value: the plugin shows as failed, with the tag and message.

```ts title="packages/plugins/recorder/src/index.ts"
const ConfigInvalid = Schema.TaggedStruct('RecorderConfigInvalid', {message: Schema.String})
type ConfigInvalid = typeof ConfigInvalid.Type
```

```ts title="packages/plugins/recorder/src/index.ts"
export default Plugin.define<Plugin.Services, ConfigInvalid>({
  id: 'recorder',
  effect: (ctx) =>
    Effect.gen(function* () {
      const parsed = recorderConfig.safeParse(ctx.options)
      if (!parsed.success) return yield* Effect.fail(ConfigInvalid.make({message: z.prettifyError(parsed.error)}))
      const config = parsed.data
      const path = yield* Path.Path
```

## Tools

Add tools inside `ctx.tool.transform`. `editor.namespace` describes a group, and `editor.add` adds one tool. `execute`
returns an `Effect` of the result:

```ts title="packages/plugins/recorder/src/tools.ts"
export const register = Effect.fn('RecorderTools.register')(function* (ctx: Pick<Context, 'tool'>) {
  const services = yield* Effect.context<ClientRingsInterface | RendererCacheInterface>()
  const control = yield* CaptureControl
  const pull = (fromTs: number, toTs: number, keyframes: number) =>
    pullWindow(fromTs, toTs, keyframes).pipe(Effect.provideContext(services))
  yield* ctx.tool.transform((editor) => {
    editor.namespace({
      name: 'recording',
      description:
        "Marked recordings of the user's app page: start one, act, stop it, or pull the last seconds. Each answers a semantic action log plus keyframe screenshots.",
    })
    editor.add({
      name: 'start',
      description:
        "Start a marked recording of the user's app page. Waits for the page to attach and begin streaming, then returns a captureId, so acting right after it returns is safe. Use before performing page actions you want to review, then call recording_stop.",
      input: z.object({}),
      output: z.object({captureId: z.string(), startedAt: z.number()}),
      options,
      execute: () =>
        Effect.gen(function* () {
          const {captureId, startTs, appendCursor} = yield* control.startCapture
          const covered = yield* control.awaitAppendAfter(appendCursor, START_WAIT_MS)
          if (covered) return {output: {captureId, startedAt: startTs}}
          yield* control.stopCapture(captureId).pipe(Effect.ignore)
          return yield* Effect.fail(
            Tool.makeError({
              message: 'no page client attached within 5s; the app page with the widget must be open to record',
            }),
          )
        }),
    })
```

Here `options` is `{namespace: 'recording', codemode: true}`, so the tool is `recording_start`.

A schema is a zod schema, any Standard Schema (Valibot, ArkType ...), an Effect Schema, or a raw JSON Schema object.

`execute` gets a context with `sessionId`, `agent`, `messageId`, the call `id`, `progress(update)`, and an optional
`cancel` effect.

### Tool.Error

Fail the effect with a `Tool.Error` to fail the call with a message the agent reads. Import `Tool` from
`@conciv/plugin/schema/tool` (or from `@conciv/plugin`), and make one with `Tool.makeError` or `Tool.toolError`.
`metadata` travels with it:

```ts title="packages/plugins/tanstack/src/tools.ts"
function bundlerFailure(failure: BundlerUnavailable) {
  return Tool.toolError({message: failure.message, metadata: {code: 'BUNDLER_UNAVAILABLE'}})
}
```

```ts title="packages/plugins/tanstack/src/tools.ts"
execute: () =>
  tanstack.buildErrors().pipe(
    Effect.map((output) => ({output})),
    Effect.mapError(bundlerFailure),
  ),
```

A typed failure becomes a `Tool.Error` once, at the edge, with `catchTag`:

```ts title="packages/plugins/recorder/src/tools.ts"
execute: ({captureId, keyframes}) =>
  Effect.gen(function* () {
    const range = yield* control.stopCapture(captureId)
    yield* control.awaitAppendAfter(range.appendCursor, FLUSH_WAIT_MS)
    return yield* pull(range.startTs, range.stopTs, keyframes)
  }).pipe(
    Effect.catchTag('RecorderCaptureNotFound', (missing) =>
      Effect.fail(Tool.makeError({message: `no active capture ${missing.captureId}`})),
    ),
  ),
```

### Ask before a tool runs

A tool that changes something real asks the user first. Add an `ask` rule for its action to every agent, then call
`ctx.permission.assert` inside `execute`. It succeeds once the user allows the action, and fails with a `Tool.Error`
when they deny it:

```ts title="packages/plugins/ios/src/tools.ts"
const ASKING_RULES: Permission.Rule[] = ['ios_build', 'ios_run'].map((action) => ({
  action,
  resource: '*',
  effect: 'ask',
}))
```

```ts title="packages/plugins/ios/src/tools.ts"
function confirmed(permission: Context['permission'], action: string, tool: Tool.Context) {
  return permission.assert({
    action,
    resources: ['*'],
    save: ['*'],
    metadata: {},
    sessionId: tool.sessionId,
    agent: tool.agent,
    source: {type: 'tool', messageId: tool.messageId, id: tool.id},
  })
}
```

```ts title="packages/plugins/ios/src/tools.ts"
  const asking = <Output>(
    action: string,
    tool: Tool.Context,
    work: (runtime: IosRuntime) => Effect.Effect<Output, Tool.Error, Services>,
  ) => configured((runtime) => confirmed(ctx.permission, action, tool).pipe(Effect.flatMap(() => work(runtime))))

  yield* ctx.agent.transform((editor) => editor.list().forEach((agent) => agent.permissions.push(...ASKING_RULES)))
  yield* ctx.tool.transform((editor) => {
    editor.namespace({
      name: 'ios',
      description: 'The native iOS app on the simulator: build it, run it, capture its screen and read its logs.',
    })
    editor.add({
      name: 'build',
      description: 'Compile the native iOS project for the simulator and report build diagnostics.',
      input: z.object({clean: z.boolean().optional()}),
      output: BuildOutputSchema,
      options: direct,
      execute: (input, tool) => asking('ios_build', tool, (runtime) => built(build, runtime, input)),
    })
```

The ask shows as an Approve or Deny card in the chat. See [Approvals](/docs/usage/approvals).

## Skills

Add a skill inside `ctx.skill.transform`. The agent sees its `description` and loads its `content` when it needs it.

```ts title="packages/plugins/recorder/src/skill.ts"
import {Skill} from '@conciv/plugin'
import {AbsolutePath} from '@conciv/plugin/schema/schema'

export const info: Skill.Info = {
  id: Skill.Id.make('recorder'),
  name: Skill.Name.make('Recorder'),
  description:
    "Record what happens on the user's app page and read it back as an action log with keyframe screenshots. Load it before your first recording tool call.",
  path: AbsolutePath.make('skill://recorder/SKILL.md'),
  content: [
    '# Recorder',
    '',
    "The recorder keeps a short recording of the user's app page while a recording is live. Nothing is recorded unless a recording was requested. Call its three tools from code mode; `discover_tools` shows their exact signatures.",
  ].join('\n'),
}
```

The test runner adds its skill the same way, in [Define the plugin](#define-the-plugin):
`yield* ctx.skill.transform((editor) => editor.add(info))`. `@conciv/plugin/effect` exports the same `Skill`. For
skills written as files in the project, see [Skills](/docs/skills).

## Add to the system prompt

A session `context` hook runs before every model request and can add text to the system prompt. The iOS plugin adds
its rules this way:

```ts title="packages/plugins/ios/src/tools.ts"
  if (configuredRuntime === undefined) return
  const rules = iosSystemPrompt(configuredRuntime.config, {cwd: configuredRuntime.cwd})
  yield* ctx.session.hook('context', (event) => Effect.sync(() => event.system.push({type: 'text', text: rules})))
})
```

This is the end of the plugin's `register` generator.

## RPC

An RPC contract lets the browser part, another plugin or a terminal call the engine part. Put it in its own module,
so both parts import it.

### Rpc.define

`Rpc.define({id, methods, events})` declares the contract. Each method has an `input` and `output` schema, and
optional named `errors`. Each event has a `schema`.

```ts title="packages/plugins/test-runner/src/rpc.ts"
import {Rpc} from '@conciv/plugin/rpc'
import {z} from 'zod'
import {TestEventSchema, TestRunResultSchema} from './shared/events.js'

export const ListResultSchema = z.object({
  files: z.array(z.object({file: z.string(), relPath: z.string(), lastState: z.string().optional()})),
})

const UiServerInfoSchema = z.object({available: z.boolean(), url: z.string().optional()})

const RunArgsSchema = z.object({
  patterns: z.array(z.string()).optional(),
  testNamePattern: z.string().optional(),
  failedOnly: z.boolean().default(false),
})

const ListInputSchema = z.object({failedOnly: z.boolean().default(false)})

const NoInputSchema = z.unknown()

const CurrentRunSchema = z.object({events: z.array(TestEventSchema).nullable(), unavailable: z.string().nullable()})

const unavailable = {UNAVAILABLE: z.object({available: z.literal(false), error: z.string()})}

export const TestRunner = Rpc.define({
  id: 'test-runner',
  methods: {
    status: {input: NoInputSchema, output: TestRunResultSchema},
    current: {input: NoInputSchema, output: CurrentRunSchema},
    list: {input: ListInputSchema, output: ListResultSchema, errors: unavailable},
    ui: {input: NoInputSchema, output: UiServerInfoSchema, errors: unavailable},
    run: {input: RunArgsSchema, output: TestRunResultSchema, errors: unavailable},
    stop: {input: NoInputSchema, output: z.object({ok: z.boolean()})},
  },
  events: {event: {schema: TestEventSchema}},
})
```

An error name that starts with `rpc.` is reserved: `Rpc.define` throws on it.

### Register the handlers

`ctx.rpc.register(contract, handlers)` answers the methods. A handler gets the parsed input and a context with
`error(name, message, data)`, which makes one of the method's declared errors, and returns an `Effect`:

```ts title="packages/plugins/test-runner/src/index.ts"
function registerRpc(rpc: Context['rpc'], manager: TestRunnerManager) {
  return rpc.register(TestRunner, {
    status: () => Effect.sync(() => manager.status()),
    current: () => Effect.sync(() => manager.current()),
    list: (input, call) =>
      guarded(
        () => manager.list(input.failedOnly),
        (reason) => call.error('UNAVAILABLE', UNAVAILABLE_MESSAGE, {available: false, error: reason}),
      ),
```

Each typed failure maps to a declared error once, at the edge:

```ts title="packages/plugins/recorder/src/index.ts"
'recordings.exportVideo': (input, call) =>
  Effect.gen(function* () {
    const file = yield* recordings.videoFile(input.id)
    const events = yield* recordings.get(input.id)
    yield* renderVideoFile(file, events)
    const piece = yield* readVideoPiece(file, input.offset, MAX_FILE_BYTES)
    return {...piece, ...VIDEO}
  }).pipe(
    Effect.catchTags({
      RecorderRecordingNotFound: () => Effect.fail(call.error('expired', `The recording ${input.id} has expired`)),
      RecorderVideoUnrendered: () =>
        Effect.fail(call.error('render-failed', `The recording ${input.id} could not be rendered to video`)),
      RecorderVideoUnreadable: () =>
        Effect.fail(call.error('unreadable', `The video of the recording ${input.id} could not be read`)),
    }),
    Effect.provideContext(services),
  ),
```

The registration has `dispose` and `events.emit(name, data)`, which sends an event to every subscriber. The test
runner emits each live test event, in [Define the plugin](#define-the-plugin).

RPC methods never ask the user. An operation that must ask is a tool.

### Call another plugin

`ctx.rpc(Contract)` returns a typed client for another plugin's contract. The TanStack plugin calls the page plugin
this way:

```ts title="packages/plugins/tanstack/src/tools.ts"
import {Definition as PageDefinition, State, TabId} from '@conciv/plugin-page/rpc'
```

```ts title="packages/plugins/tanstack/src/tools.ts"
const page = ctx.rpc(PageDefinition)
```

To call these methods from the widget, see [Call the engine part](/docs/plugins/browser#call-the-engine-part). From
a terminal, see [`conciv plugin call`](/docs/plugins/terminal).

## The promise entry

`@conciv/plugin` is the same engine part without Effect. `Plugin.define` takes `setup(ctx)` instead of `effect`, and
each `ctx` domain returns a `Promise`. `setup` may be async, and may return a cleanup that runs when the plugin stops
or reloads.

```ts title="packages/plugins/whiteboard/src/index.ts"
export default Plugin.define({
  id: 'whiteboard',
  async setup(ctx) {
    const directory = ctx.location.directory
    const store = await createStore(databaseDirectory(ctx.location))
    const closeStore = () => store.close()
    const registration = await releaseOnFailure([closeStore], () =>
      ctx.rpc.register(Whiteboard, whiteboardHandlers(store)),
    )
    const stopAnnouncing = store.onEvent((event) => {
      if (event.table === 'cursor') return
      const {room, table, key, type, cursor} = event
      registration.events.emit('changed', {room, table, key, type, cursor}).catch((error: unknown) => {
        console.error(`[whiteboard] change ${table} ${key} was not announced: ${String(error)}`)
      })
    })
    const stopEnrichment = startCommentEnrichment(store, directory)
    const stops = [closeStore, stopAnnouncing, stopEnrichment]
    await releaseOnFailure(stops, async () => {
      await ctx.agent.transform((editor) =>
        editor.list().forEach((agent) => agent.permissions.push(...CONFIRMATION_RULES)),
      )
      await register(ctx.tool, store, directory, ctx.permission)
      await ctx.skill.transform((editor) => editor.add(info))
      await ctx.session.hook('experimental.idle', async ({sessionId}) => {
        await autoCommitDraft(store, sessionId)
      })
    })
    return () => stops.toReversed().forEach((stop) => stop())
  },
})
```

A tool's `execute` and an RPC handler return a `Promise`. A tool fails a call by throwing `Tool.toolError`:

```ts title="packages/plugins/whiteboard/src/tool/refusal.ts"
export function fail({code, ...failure}: Failure): never {
  throw Tool.toolError(code === undefined ? failure : {...failure, metadata: {code}})
}
```
