title: Add settings

A plugin has two kinds of settings:

- **Options** are set in code, in the project's conciv config. The team shares them through the repo.
- **A setting in the widget** is changed by the user, in the widget's settings. It stays on their machine.

## Read options from the config

The user passes options with the plugin's entry:

```ts twoslash title="vite.config.ts"
import {defineConfig} from 'vite'
import conciv from '@conciv/it/plugin/vite'

export default defineConfig({
  plugins: [conciv({plugins: [['./tools/tickets', {project: 'OPS', closeAfterDays: 30}]]})],
})
```

Your engine part reads them as `ctx.options`. Check them with a schema first, since the user can write anything:

<Tabs groupId="plugin-api" persist items={['Promise', 'Effect']}>
<Tab value="Promise">

```ts twoslash title="tools/tickets/server.ts"
import {z} from 'zod'
import {Plugin} from '@conciv/backend-plugin-api'

const Options = z.object({
  project: z.string(),
  closeAfterDays: z.number().int().positive().default(14),
})

export default Plugin.define({
  id: 'tickets',
  async setup(ctx) {
    const options = Options.parse(ctx.options)
    await ctx.tool.transform((tools) => {
      tools.add({
        name: 'ticket_project',
        description: 'Name the tracker project this repo files tickets in.',
        input: z.object({}),
        execute: async () => ({content: `Tickets go in ${options.project}.`}),
      })
    })
  },
})
```

</Tab>
<Tab value="Effect">

```ts twoslash title="tools/tickets/server.ts"
import {Effect} from 'effect'
import {z} from 'zod'
import {Plugin} from '@conciv/backend-plugin-api/effect'

const Options = z.object({
  project: z.string(),
  closeAfterDays: z.number().int().positive().default(14),
})

export default Plugin.define({
  id: 'tickets',
  effect: (ctx) =>
    Effect.gen(function* () {
      const options = yield* Effect.try(() => Options.parse(ctx.options)).pipe(Effect.orDie)
      yield* ctx.tool.transform((tools) => {
        tools.add({
          name: 'ticket_project',
          description: 'Name the tracker project this repo files tickets in.',
          input: z.object({}),
          execute: () => Effect.succeed({content: `Tickets go in ${options.project}.`}),
        })
      })
    }),
})
```

</Tab>
</Tabs>

- `ctx.options` is the object from the config entry. Every value in it is JSON.
- `Options.parse` checks it and fills in defaults. Here `closeAfterDays` is 14 unless the user sets it.
- A parse that fails stops the plugin from loading, with zod's message in the log. That tells the user what to fix.

The browser part gets the same object as `ctx.options`.

## Add a setting to the widget

Declare a store for the value, then add a row to the widget's settings. The browser part is written with Solid
components and plain async functions:

```tsx twoslash title="plugin-experimental.tsx"
// @jsx: preserve
// @jsxImportSource: solid-js
// ---cut---
import {Plugin, SettingsPage, Store, usePlugin} from '@conciv/frontend-plugin-api'
import {z} from 'zod'

const stores = {
  prefs: Store.global(z.object({showClosed: z.boolean()}), {showClosed: false}),
}

function ShowClosedRow() {
  const ctx = usePlugin<{stores: typeof stores}>()
  const prefs = ctx.stores.prefs
  return (
    <ctx.ui.SettingsRow title="Show closed tickets">
      <ctx.ui.Switch
        label="Show closed tickets"
        hideLabel
        checked={prefs.value.showClosed}
        onChange={(checked) => prefs.set({showClosed: checked})}
      />
    </ctx.ui.SettingsRow>
  )
}

export default Plugin.define({
  stores,
  setup(ctx) {
    ctx.add(SettingsPage, {
      id: 'tickets',
      page: 'general',
      section: 'general',
      title: 'Tickets',
      entries: [{id: 'show-closed', title: 'Show closed tickets', keywords: 'tickets closed'}],
      render: () => <ShowClosedRow />,
    })
  },
})
```

- `Store.global` declares a value with a schema and a starting value. `global` means one value for every project.
- The `stores` field of the definition hands the declared stores to the widget. It loads them before your setup runs.
- `usePlugin` gives a component your plugin's context. `ctx.stores.prefs` is the store, typed from the declaration.
- `prefs.value` is the stored value.
- `prefs.set` replaces it. The widget saves it for you.
- `ctx.ui` holds the widget's own components. The row and its switch look like the widget's own settings.
- With page and section both set to `'general'`, the entry is one row in the General section.
- `entries` is what the settings search finds.

Where a settings page goes:

- No `page`: a page of its own.
- `page: 'general'`: a section on the General page.
- `section: 'general'` as well: a row in the General section.

<Accordions>
<Accordion title="Other store scopes">

- `Store.project` keeps one value for the project the engine runs in.
- `Store.session` keeps one value per session. Call it with the session: `ctx.stores.view(session)`.
