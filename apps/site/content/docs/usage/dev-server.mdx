title: Dev server

The dev server tools let the agent ask your running Vite dev server about your code, instead of guessing from config
files. They are built in, with nothing to install.

## Basic

Ask about your dev server when a build question comes up:

```text title="Prompt"
Why does @/components/Header resolve to the wrong file from src/routes/index.tsx?
```

The agent asks the server how the import resolves from that file, and answers from what the server says.

<Callout type="info" title="Vite only">
  The tools need a Vite dev server, which includes TanStack Start and Astro. On Next.js, webpack and Rspack they answer
  that no dev server is attached.
</Callout>

## Ask how the server is set up

The agent reads the resolved config: the root, the base path, the mode, the aliases and the plugins. It also knows
where the server listens, on this machine and on your network:

```text title="Prompt"
What URL do I open on my phone to see this app?
```

## Ask what a file pulls in

The agent reads a file's place in the module graph: what it imports, and what imports it.

```text title="Prompt"
Which modules import src/lib/store.ts? I want to know what a change there touches.
```

## See the code the server serves

The agent reads the code the dev server sends to the browser for a URL, after every plugin ran:

```text title="Prompt"
Show me what /src/main.ts looks like after the transform. Is the env variable inlined?
```

## Open a file or restart the server

```text title="Prompt"
Open src/routes/index.tsx at line 12 in my editor. Then restart the dev server and check the page loads.
```

A restart asks you first, with a [Permission card](/docs/usage/approvals). Allow it, and the server restarts and
bundles its dependencies again.

## Ask from your terminal

The same questions work from a terminal, with the question's name after `server`:

```bash title="Terminal"
npx @conciv/cli plugin call server urls
```

It prints the answer as JSON:

```json title="Output"
{"ok": true, "data": {"local": ["http://localhost:5173/"], "network": ["http://192.168.1.20:5173/"]}}
```

The other questions take their input as JSON after `--data`:

```bash title="Terminal"
npx @conciv/cli plugin call server config
npx @conciv/cli plugin call server resolve --data '{"spec":"@/lib/auth","importer":"src/routes/login.tsx"}'
npx @conciv/cli plugin call server graph --data '{"file":"src/lib/store.ts"}'
npx @conciv/cli plugin call server transform --data '{"url":"/src/main.ts"}'
npx @conciv/cli plugin call server open --data '{"file":"src/routes/index.tsx","line":12,"column":4}'
```

- `resolve` takes the import, and optionally the file it is imported from. Its `id` is `null` when nothing matches.
- `graph` takes a file. `transform` takes the URL the browser asks for.
- `open` takes a file, and optionally a line and a column.

A restart is not on this list. It always goes through the agent, so you get the card first.

<Accordions type="single">
  <Accordion title="The answer says no dev server is attached to conciv?">
    The engine has no Vite dev server to ask. It runs on another bundler, or on its own. Opening a file in your editor
    still works.
  </Accordion>
  <Accordion title="The dev server failed the request?">
    The dev server itself refused the question, for example a transform that throws. From the terminal, the error's
    `data.message` holds the dev server's own message.
  </Accordion>
  <Accordion title="Why do the cards say external_server_resolve?">
    That is the tool's name in code mode, where the agent calls tools from a short program. Learn more in the [Tools and
    code mode documentation](/docs/tools-and-code-mode).
  </Accordion>
</Accordions>
