Page control lets the agent read and change the page you have open, in your own browser tab. It is built in, with
nothing to install.

## Point at an element

Click **Select an element from the page**, the crosshair beside the composer. Then click an element in your app.
conciv pins it to your next message, with its source file and line when it can find them:

```text title="Prompt"
Give this card more padding, and round its corners.
```

The agent reads the page, finds the element, changes it, and checks the result.

## Try a change live

The agent can restyle the page on the spot. You see an idea at once:

```text title="Prompt"
Try the header in dark blue, without saving it.
```

A live change lives only in the page. The next hot reload wipes it, because it is not in your source.

## Keep the change

When you like it, ask the agent to keep it. It edits the source file, so the change survives a reload:

```text title="Prompt"
Keep that. Save it to the component.
```

The agent can also open the file in your editor:

```text title="Prompt"
Open the file that renders this card in my editor.
```

## Have it use the page

The agent can click, type and scroll like a user. Use it to reproduce a bug or walk through a flow:

```text title="Prompt"
Fill the signup form with a test user, submit it, and tell me what the console says.
```

What the agent can do on the page:

- **Read** the page: its controls, its text, a field's value, a screenshot, the console and the current route.
- **Act** on it: click, fill, select, check, press a key, hover, scroll and submit.
- **Restyle** it: change styles, classes and text, live.
- **Inspect React**: the component tree, and the file and line that rendered an element.
- **Wait** for an element to show or hide, or for a hot update to land after a file edit.
- **Run code** in the page. This asks you first, every time.

Learn more about the ask in the [Approvals documentation](/docs/usage/approvals).
