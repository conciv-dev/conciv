The agent works against the page you see, in your own browser tab. It reads the page with a snapshot of its controls,
acts on an element, waits for the page to settle, and takes a fresh snapshot. Page control comes from the page plugin,
`@conciv/plugin-page`, which conciv ships and always loads.

## Point at what you mean

**Select an element from the page**, the crosshair beside the composer, picks any element on the page and pins it to
your next message, with its source file and line when conciv can find them.

## What the agent can do on the page

The agent calls the page tools from code mode as `external_page_*`, such as `external_page_click`. Every tool takes an
optional tab: without one, the tab you focused last answers.

- **Read**: `snapshot`, `screenshot`, `text`, `value`, `query`, `console`, and the current `route`.
- **Act**: `click`, `fill`, `select`, `check`, `uncheck`, `press`, `hover`, `scroll` and `submit`, on an element from
  the latest snapshot, a CSS selector, or a React component name. `queue` plays a list of actions in order.
- **Restyle**: `setstyle`, `addclass`, `settext` and `css`.
- **Inspect React**: `inspect`, `tree`, `locate` and `find`. `locate` names the source file and line that rendered an
  element.
- **Wait**: `wait` for an element to show or hide, and `hmr` for a hot update to land after a file edit.
- **Run code**: `eval` runs JavaScript in your page. It asks you first, every time (see
  [Approvals](/docs/usage/approvals)).

Page text, console messages and screenshots are untrusted page content: the agent is told never to follow
instructions found in them.

## Preview, then persist

The restyle tools change the page live, so you see an idea at once. These edits live only in the page: the next hot
reload wipes them, because they are not in your source. When you keep a change, the agent edits the real files so it
survives a reload. It can open the source file in your editor too.
