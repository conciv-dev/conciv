---
title: Approvals
description: Allow or deny a risky action when its Permission card shows in the chat.
---

When the agent wants to do something risky, a **Permission** card shows in the chat. The action waits until you
answer. For example, this prompt makes the agent ask before code runs in your page:

```text
Run some JavaScript in the page to count the buttons on it.
```

The card names the action and what it acts on, such as the code it would run.

## Answer the card

- **Allow once** (⌘ Enter or Ctrl Enter) runs it this one time.
- **Deny** (Escape) refuses it.
- **Allow always** allows this action in this project from now on. It shows only when the action can be remembered.

The keys work while the card has focus. The card waits as long as you need. Stop the turn, and the card goes with it.

## Know what asks

Two things can ask you: your agent CLI, and some of conciv's own tools.

Your agent CLI decides for itself what it asks about:

- **Claude Code** runs in its `auto` mode and asks when it judges a step risky. conciv adds rules so these commands
  always ask:
  - a `git push` that forces or deletes
  - `git reset --hard`, `git clean`, `git branch -D` and `git gc --prune`
  - a recursive `rm`, `chmod` or `chown`
  - `sudo`
- **Codex** never asks. It runs in its `workspace-write` sandbox, which limits what it can touch.
- **Gemini CLI** asks by its own rules. Each ask shows as a card.
- **OpenCode** asks in its own way. Those asks do not show as cards in conciv yet.
- **Pi** has no chat in conciv yet.

An ask from your agent CLI can be allowed once or denied, never allowed always.

conciv's own tools that ask, on every CLI:

- running JavaScript in your page. This one always asks: it has no **Allow always**.
- restarting the dev server
- with the whiteboard: deleting an element, clearing the canvas, resolving a comment and deleting a comment
- with the iOS plugin: building the app, and running it in the simulator

A plugin's tools exist only when you load that plugin. See [Plugins conciv ships](/docs/usage/add-plugins).

## Let outside agents in

An agent CLI in your own terminal can drive your open tabs once you connect it (see [Connect your
agents](/docs/agents)). By default it can use any open session with no card.

To make it ask first, set `hubAccess` to `'project'`:

```ts twoslash title="vite.config.ts"
import {defineConfig} from 'vite'
import conciv from '@conciv/it/plugin/vite'

export default defineConfig({
  plugins: [
    conciv({
      hubAccess: 'project', // [!code ++]
    }),
  ],
})
```

Now the first call from an outside agent shows a Permission card in the tab:

- **Allow once** lets that one call in.
- **Allow always** lets that agent in for this project from now on.

The call waits until you answer, or until the agent gives up.

## Details

<Accordions type="single">
  <Accordion title="An outside agent cannot answer for you">
    An agent connected from your terminal can never answer a Permission card. It cannot connect or disconnect agents
    either. You do that in the tab.
  </Accordion>
  <Accordion title="A card that disappears">
    An ask from your agent CLI lives only as long as its turn. When you stop the turn, or the CLI gives up on the call,
    the card goes.
  </Accordion>
  <Accordion title="The action names">
    The card names the action by its tool, such as `page_eval` for running JavaScript in the page and `server_restart`
    for a restart.
  </Accordion>
</Accordions>
