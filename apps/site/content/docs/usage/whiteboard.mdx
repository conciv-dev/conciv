The whiteboard is a shared [Excalidraw](https://excalidraw.com) canvas that opens over your dev app. You and the agent
draw on the same surface: sketch a rough layout and ask the agent to build it, or ask it to diagram the thing you are
both looking at.

<Callout type="warn">
  The whiteboard comes from the whiteboard plugin, `@internal/plugin-whiteboard`. conciv does not ship it, and the
  package is not published to npm yet. Inside the conciv repo, the example apps load it from its folder (see
  [Examples](/docs/examples)).
</Callout>

## Open it

The **Whiteboard** button above the composer ("Open the whiteboard canvas") opens the canvas over the page, with the chat
still usable above it. Escape closes it. Once opened, the canvas stays mounted while hidden, so the agent keeps drawing
into it. The canvas is transparent so the page shows through; **Canvas background** in the general settings turns that
off for a solid canvas.

## The agent draws real elements

When the agent draws, it writes real, editable Excalidraw elements onto the canvas, not an image. You can move,
restyle and delete anything it drew. It can draw shapes, convert SVG, turn a mermaid diagram into native shapes and
connect elements with arrows. It draws into a draft first and commits it to the shared canvas; a draft left when a
turn ends is committed for it.

The agent calls the whiteboard tools from code mode as `external_whiteboard_*`, such as
`external_whiteboard_canvas_diagram`.

## Comments anchored to your source

Comments and pins attach to your source, not only to canvas coordinates. The agent can leave a comment on the
component it is talking about, reply, resolve a thread when it is addressed, and pick up threads you started. The
**Comment** button above the composer ("Comment on an element") lets you pick an element on the page and comment on it.

These agent actions ask you first, with a [Permission card](/docs/usage/approvals): deleting an element, clearing the
canvas, resolving a comment and deleting a comment.

## Where the board lives

Each chat session has its own board. The engine keeps it in the plugin's storage under your project's state root, so
it stays on your machine and a second engine on the same state root reads it back. Every open tab follows the board as
it changes.
