## Before any message

<Accordions type="single">

<Accordion title="The conciv button never appears">

conciv mounts in dev builds only. Check that:

- the dev server is running, not a production build
- `enabled` is not set to `false` in your conciv config, and `widget` is not `false`

</Accordion>

<Accordion title="The chat does not answer">

The default harness runs the `claude` CLI. Install Claude Code, log in to it, and make sure `claude` is on the `PATH`
of the process that starts your dev server. See [Harnesses](/docs/harnesses).

</Accordion>

</Accordions>

## In the panel

<Accordions type="single">

<Accordion title="Log in to use conciv on this page.">

This browser has not logged in to this engine. Click **Log in** and type the 6-digit code your dev server printed in its
terminal. See [Logging in](/docs/usage/logging-in).

</Accordion>

<Accordion title="This browser is no longer authorized to use conciv.">

Someone ran `conciv auth revoke` for this browser, or `conciv auth revoke --all`. Click **Log in** to log in again.

</Accordion>

<Accordion title="That code didn't match. Check your terminal and try again.">

The digits differ from the code in the newest box your dev server printed. After 5 wrong tries the code is dropped:
click **Send a new code**.

</Accordion>

<Accordion title="That code expired. Send a new code and use the one your terminal prints.">

A code lives 5 minutes, and is dropped after 5 wrong tries. Click **Send a new code** and use the code in the new box.

</Accordion>

<Accordion title="Could not ask the dev server for a code. Please try again.">

The engine did not answer the login dialog. Check that the dev server is running, then click **Send a new code**.

</Accordion>

<Accordion title="conciv lost connection to the engine.">

The engine stopped answering, usually because the dev server stopped or restarted. Start it and click **Retry**. A
message you try to send meanwhile stays in the composer.

<ImageZoom
  src="/screenshots/lost-connection.png"

  width={1920}

/>

</Accordion>

<Accordion title="conciv couldn't reach the engine. Check that the dev server is still running.">

The panel could not load from the engine. Start the dev server and click **Retry**.

</Accordion>

<Accordion title="This widget is version <version> but the conciv engine is older.">

Your `@conciv/*` packages are on different versions. Update them all to the version the message names, then restart
your dev server.

</Accordion>

<Accordion title="Engine is running outdated code: the server code on disk is newer than the running engine. Restart the dev server.">

conciv's code on disk changed after the engine started, for example after an install. Restart the dev server.

</Accordion>

<Accordion title="pi is not installed or not yet supported">

The session runs the Pi harness, which has no chat in conciv yet. Pick another harness's model in the model menu. See
[Harnesses](/docs/harnesses).

</Accordion>

<Accordion title='claudeExecutable: --plugin-dir path "<path>" contains whitespace.'>

conciv cannot pass a path with a space to Claude Code. The error names the path (or `--settings`): move it to a path
without spaces.

</Accordion>

</Accordions>

## In the terminal

<Accordions type="single">

<Accordion title="conciv: port <port> is already in use, the engine is listening on http://127.0.0.1:<other> instead">

On Vite, the `port` you set is a preference: when it is taken, the engine takes a free one, logs this line, and the
widget follows it. To keep the port, stop what holds it. With no `port` set, the Vite engine reuses the port it had last
time (from `.conciv/server.json`) when it is free, and otherwise takes any free port.

Next.js, webpack and Rspack check the port before the engine starts, take a free one when yours is taken, and build that
port into the widget, without this line.

</Accordion>

<Accordion title='the configured conciv session id "<id>" is not a conciv session id (ses_...)'>

`sessionId` (or `CONCIV_SESSION_ID`) is not a conciv session id, so the engine does not start. Use an id that starts
with `ses_`, or remove the option. See [Configuration](/docs/configuration).

</Accordion>

<Accordion title='conciv: unknown harness "<id>". Known harnesses: claude, codex, gemini-cli, opencode, pi.'>

`harness` (or `CONCIV_HARNESS`) names a harness conciv does not have. Use one of the ids the message lists. See
[Harnesses](/docs/harnesses).

</Accordion>

</Accordions>

## From the conciv CLI

<Accordions type="single">

<Accordion title="No conciv dev server on 127.0.0.1:<port>.">

The CLI found no engine at that port. It takes the port from `CONCIV_PORT`, else from `.conciv/server.json` in this
folder or a parent, else the newest running engine on this machine, else `5173`. Start your dev server, or set
`CONCIV_PORT` to the engine's port (not the dev server's).

</Accordion>

<Accordion title="no conciv engine state found here or in any parent directory">

`conciv auth` needs `.conciv/server.json`, which the dev server writes when it starts. Run the command from your
project folder, after the dev server has started once.

</Accordion>

<Accordion title='no trusted browser has the id "<id>"'>

Run `conciv auth revoke` with no id to list the logged-in browsers and their ids.

</Accordion>

<Accordion title="Non-interactive terminal">

`conciv init` had no terminal to ask its questions in. Run it again with `--yes` to take the defaults, or `--dry-run`
to only print the plan.

</Accordion>

<Accordion title="uncommitted changes">

`conciv init` refuses a git tree with uncommitted changes. Commit first, or pass `--force`.

</Accordion>

<Accordion title="no package.json here">

`conciv init` runs in your app's folder, the one that holds `package.json`.

</Accordion>

</Accordions>
