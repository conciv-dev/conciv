Pass options where you add conciv. Every option is optional.

```ts title="vite.config.ts"
conciv({widget: {quickTerminal: {hotkey: 'Alt+k'}}})
```

Next.js takes them as the second argument, `withConciv(nextConfig, options)`. webpack and Rspack take them as the
plugin's argument, `conciv.default(options)` in a CommonJS config.

### port

<Tabs items={['Vite', 'Next.js, webpack and Rspack']}>
  <Tab value="Vite">
    Without `port`, the engine takes the port it used last time in this project, or a free one. With `port`, the engine
    tries it and takes a free port when it is in use, with the warning `conciv: port <port> is already in use, the
    engine is listening on http://127.0.0.1:<other> instead`.
  </Tab>
  <Tab value="Next.js, webpack and Rspack">
    The port is picked before the widget is built, so the widget and the engine use the same one. It is `port` if you
    set it, else the port the engine used last time in this project, else a port picked from the project folder (one
    of 1000 from 24170 up), so two projects rarely ask for the same one. When that port is in use, a free port is taken
    instead.
  </Tab>
</Tabs>

The engine listens on `127.0.0.1` only, and writes the port it took to `.conciv/server.json`.

### widget

`modal` is the corner panel and its button. `quickTerminal` is the sheet that drops from the top of the page. Both are
on unless you set them to `false`.

```ts
conciv({widget: {modal: {position: 'top-left'}}})
conciv({widget: {quickTerminal: {hotkey: ['Mod+`', 'Control+k']}}})
conciv({widget: {quickTerminal: false}})
conciv({widget: {modal: false}})
```

`modal.position` is one of `top-left`, `top-right`, `middle-left`, `middle-right`, `bottom-left` or `bottom-right`
(the default). The quick terminal hotkey is ``Mod+` `` by default, and a `hotkey` set here replaces it. See
[Quick terminal](/docs/usage/quick-terminal).

`widget: false` keeps the engine and adds nothing to the page. Use it when you render the widget yourself with
`<ConcivWidget />` from `@conciv/react`, `@conciv/preact` or `@conciv/solid`, so the page does not get two:

```ts title="vite.config.ts"
import {defineConfig} from 'vite'
import react from '@vitejs/plugin-react'
import conciv from '@conciv/it/plugin/vite'

export default defineConfig({
  plugins: [react(), conciv({widget: false})],
})
```

### plugins

Each entry is a package name, a path (relative paths start at the project folder), or `[name, options]`. A name with a
leading `-` removes that plugin. See [Plugins](/docs/plugins).

```ts
conciv({
  plugins: [
    [
      '@conciv/plugin-ios',
      {
        projectRoot: fileURLToPath(new URL('./ConcivDemo', import.meta.url)),
        bundleId: 'dev.conciv.ConcivDemo',
        simulator: 'iPhone 17 Pro',
        buildMode: 'swiftc',
        extraSourceDirs: ['../ConcivWidget/Sources/ConcivWidget'],
      },
    ],
  ],
})
```

The engine writes the prompt to `.conciv/chat-system-prompt.txt` when it starts and gives it to the harness. Claude
gets it appended to Claude Code's own system prompt.

### permission and permissions

With nobody at the tab to answer a permission card, decide ahead of time:

```ts
conciv({permission: {page_eval: 'allow'}})
```

`permission` takes three short forms: one effect for every action (`permission: 'allow'`), one effect per action
(`permission: {page_eval: 'deny'}`), or one effect per action and resource
(`permission: {page_eval: {'document.title': 'allow'}}`). `permissions` takes the full rules,
`[{action, resource, effect}]`, with `allow`, `deny` or `ask` as the effect. The short forms come first and
`permissions` after them. See [Approvals](/docs/usage/approvals).

### policies

```ts
conciv({policies: [{action: 'plugin.use', resource: '*/greeter-promise', effect: 'deny'}]})
```

The actions are `provider.use`, `tool.use`, `integration.connect`, `integration.use`, `mcp.use`, `skill.use`,
`plugin.use` and `websearch.use`.
