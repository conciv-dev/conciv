Copy this prompt into your coding agent. It sets conciv up in your webpack app:

<SetupPrompt framework="webpack" />

What you get:

- The dev server, or a watch build, adds a conciv button to every page and starts the engine.
- A one-off development build adds the button only. The engine does not start.
- A production build leaves conciv out.

<Callout title="Set the mode">
  conciv runs only when your config is not a production build:

- `mode: 'development'`: conciv is on.
- `mode: 'none'`: conciv is on.
- `mode: 'production'`: conciv is off.
- No `mode`: webpack builds for production, so conciv is off.

</Callout>

## Set up by hand

<Accordions>
<Accordion id="by-hand" title="Install and wire conciv yourself">

<Steps>
<Step>

### Install

```package-install
npm install -D @conciv/it
```

</Step>
<Step>

### Add the plugin

Add the `require`, the plugin call and a development mode:

```js title="webpack.config.js"
const HtmlWebpackPlugin = require('html-webpack-plugin')
const conciv = require('@conciv/it/plugin/webpack') // [!code ++]

module.exports = {
  mode: 'development', // [!code ++]
  plugins: [
    new HtmlWebpackPlugin(),
    conciv.default(), // [!code ++]
  ],
}
```

- `@conciv/it/plugin/webpack` is the webpack plugin. A CommonJS `require` gets it as `.default`.
- `mode: 'development'` turns conciv on. Skip it if you pass `--mode development` on the command line.
- Your other plugins stay as they are.

</Step>
<Step>

### Start your dev server

```bash
npx webpack serve
```

Or run a build in watch mode with `--watch`.

</Step>
<Step>

### Open your app and log in

Click the conciv button in the corner. Type the 6-digit code your dev server prints in its terminal. See
[Logging in](/docs/usage/logging-in).

</Step>
</Steps>

</Accordion>
</Accordions>

## What works

<Callout>
  webpack gives the agent less than [Vite](/docs/bundlers/vite) does. The chat and the page tools work. The agent
  cannot read your dev server's config or module graph. Its `server_*` tools answer that no dev server is attached.
</Callout>

## Edge cases

<Accordions>
<Accordion id="esm" title="An ES module config">

In an ES module config, import the plugin and call it directly. init writes this form when your config uses `import`:

```js title="webpack.config.js"
import HtmlWebpackPlugin from 'html-webpack-plugin'
import conciv from '@conciv/it/plugin/webpack' // [!code ++]

export default {
  mode: 'development', // [!code ++]
  plugins: [
    new HtmlWebpackPlugin(),
    conciv(), // [!code ++]
  ],
}
```

</Accordion>
<Accordion id="card" title="init printed a snippet instead of editing the config">

init edits only a config it can read as CommonJS or as an ES module. Otherwise it prints the CommonJS snippet. Add it
as in the manual steps above.

</Accordion>
<Accordion id="port" title="The engine port">

The plugin picks the engine port before the first watch build. It builds the widget with that port. See
[Configuration](/docs/reference/configuration#port) for how the port is chosen.

</Accordion>
<Accordion id="fails" title="The build fails with: conciv: the engine failed to start">

The engine could not start. The reason follows the message in the build output. Stopping the watch, or closing the
compiler, stops the engine.

</Accordion>
</Accordions>
