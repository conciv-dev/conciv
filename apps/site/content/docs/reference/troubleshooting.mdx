---
title: Troubleshooting
description: Find the message conciv shows you, then read its cause and its fix.
---

Find the message you see on this page, by where it shows: in the panel, in your dev server's terminal, or from the
`conciv` command. Each entry gives the cause, then the fix.

When nothing shows at all, start with the first section.

## When nothing shows

<Accordions type="single">

<Accordion title="The conciv button never appears">

**Cause.** conciv adds the widget in development only, and only when it is turned on.

**Fix.** Check each of these:

- You run the dev server, not a production build.
- Your conciv options do not set `enabled` to `false`.
- Your conciv options do not set `widget` to `false`.

</Accordion>

<Accordion title="The chat never answers">

**Cause.** The default harness runs the `claude` CLI, and the dev server cannot find it or it is not logged in.

**Fix.** Install Claude Code and log in to it. Make sure `claude` is on the `PATH` of the shell that starts your dev
server. See [Harnesses](/docs/harnesses) to use another CLI.

</Accordion>

</Accordions>

## In the panel

<Accordions type="single">

<Accordion title="Log in to use conciv on this page.">

**Cause.** This browser has not logged in to this engine.

**Fix.** Click **Log in** and type the 6-digit code from your dev server's terminal. See [Logging
in](/docs/usage/logging-in).

</Accordion>

<Accordion title="This browser is no longer authorized to use conciv.">

**Cause.** Someone logged this browser out with `conciv auth revoke`.

**Fix.** Click **Log in** and log in again.

</Accordion>

<Accordion title="That code didn't match. Check your terminal and try again.">

**Cause.** The digits differ from the newest code in your terminal.

**Fix.** Type the code from the newest box. After 5 wrong tries the code is dropped: click **Send a new code**.

</Accordion>

<Accordion title="That code expired. Send a new code and use the one your terminal prints.">

**Cause.** A code lives 5 minutes. It is also dropped after 5 wrong tries.

**Fix.** Click **Send a new code**, and type the code from the new box.

</Accordion>

<Accordion title="Could not ask the dev server for a code. Please try again.">

**Cause.** The engine did not answer the login dialog.

**Fix.** Check that the dev server is running, then click **Send a new code**.

</Accordion>

<Accordion title="conciv lost connection to the engine.">

**Cause.** The engine stopped answering, usually because the dev server stopped or restarted.

**Fix.** Start the dev server and click **Retry**. A message you tried to send meanwhile stays in the composer.

/>

</Accordion>

<Accordion title="conciv couldn't reach the engine. Check that the dev server is still running.">

**Cause.** The panel could not load from the engine.

**Fix.** Start the dev server and click **Retry**.

</Accordion>

<Accordion title="This widget is version <version> but the conciv engine is older.">

**Cause.** Your `@conciv/*` packages are on different versions.

**Fix.** Update them all to the version the message names. Then restart your dev server.

</Accordion>

<Accordion title="Engine is running outdated code: the server code on disk is newer than the running engine. Restart the dev server.">

**Cause.** conciv's code on disk changed after the engine started, for example after an install.

**Fix.** Restart the dev server.

</Accordion>

<Accordion title="pi is not installed or not yet supported">

**Cause.** The session runs the Pi harness, which has no chat in conciv yet.

**Fix.** Pick a model of another harness in the model menu. See [Harnesses](/docs/harnesses).

</Accordion>

<Accordion title='claudeExecutable: --plugin-dir path "<path>" contains whitespace.'>

**Cause.** conciv cannot pass a path with a space in it to Claude Code. The message names the path, or `--settings`.

**Fix.** Move that folder to a path without spaces.

</Accordion>

</Accordions>

## In your dev server's terminal

<Accordions type="single">

<Accordion title="conciv: port <port> is already in use, the engine is listening on http://127.0.0.1:<other> instead">

**Cause.** On Vite, the `port` you set is taken. The engine took a free port instead, and the widget follows it.

**Fix.** Nothing breaks, so you can leave it. To keep your port, stop what holds it and restart the dev server.

Without a `port` option, the engine reuses its port from last time when it is free.

</Accordion>

<Accordion title='the configured conciv session id "<id>" is not a conciv session id (ses_...)'>

**Cause.** The `sessionId` option is not a conciv session id, so the engine does not start.

**Fix.** Use an id that starts with `ses_`, or remove the option. See [Configuration](/docs/reference/configuration).

</Accordion>

<Accordion title='conciv: unknown harness "<id>". Known harnesses: claude, codex, gemini-cli, opencode, pi.'>

**Cause.** The `harness` option names a harness conciv does not have.

**Fix.** Use one of the ids the message lists. See [Harnesses](/docs/harnesses).

</Accordion>

</Accordions>

## From the conciv command

<Accordions type="single">

<Accordion title="No conciv dev server on 127.0.0.1:<port>.">

**Cause.** The command found no engine on that port.

**Fix.** Start your dev server. If it runs, set `CONCIV_PORT` to the engine's port, which is not the dev server's.

The command looks for the port in this order: `CONCIV_PORT`, then `.conciv/server.json` in this folder or a parent,
then the newest engine running on this machine, then 5173.

</Accordion>

<Accordion title="no conciv engine state found here or in any parent directory">

**Cause.** `conciv auth` needs `.conciv/server.json`, which the dev server writes when it starts.

**Fix.** Run the command in your project folder, after the dev server has started there once.

</Accordion>

<Accordion title='no trusted browser has the id "<id>"'>

**Cause.** No logged-in browser has that id.

**Fix.** Run `conciv auth revoke` with no id to list the browsers and their ids.

</Accordion>

<Accordion title="Non-interactive terminal">

**Cause.** `conciv init` had no terminal to ask its questions in.

**Fix.** Run it again with `--yes` to take the defaults. Or use `--dry-run` to print the plan only.

</Accordion>

<Accordion title="uncommitted changes">

**Cause.** `conciv init` refuses a git tree with uncommitted changes.

**Fix.** Commit first, or pass `--force`.

</Accordion>

<Accordion title="no package.json here">

**Cause.** `conciv init` runs in your app's folder, the one that holds `package.json`.

**Fix.** Change to that folder and run it again.

</Accordion>

</Accordions>
