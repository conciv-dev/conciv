conciv has four parts. Your dev server starts the engine and adds the widget to your page. The widget talks to the
engine. The engine runs the harness.

What the agent can do comes from plugins: page control and the dev server methods are built in, and you can add
more. See [Plugins](/docs/plugins).

## How they talk

The engine serves these routes on its port:

<TypeTable
  type={{
    '/rpc and /rpc-ws': {required: true, type: 'oRPC', description: "The widget's calls: sessions, settings, tools."},
    '/chat-ws or /chat-sse': {required: true, type: 'stream', description: 'The chat stream of a running turn.'},
    '/push-ws': {
      required: true,
      type: 'websocket',
      description: 'What the engine pushes to the page, such as page queries.',
    },
    '/api/mcp': {required: true, type: 'MCP', description: 'The MCP endpoint for agents.'},
    '/health': {required: true, type: 'HTTP', description: 'Open to anyone. Reports the engine version.'},
  }}
/>

Every route except `/health`, the login calls and the iOS page needs a token. A browser gets one by
[logging in](/docs/what-you-get/logging-in) with the code the engine prints.

## A turn

<Steps>
  <Step>You ask something in the chat. The engine starts the harness in your project folder with conciv's prompt.</Step>
  <Step>
    The harness reads and drives your live page through the tools plugins give it, and edits your source files. Its
    output streams into the panel.
  </Step>
  <Step>Anything that asks first shows a permission card. See [Approvals](/docs/what-you-get/approvals).</Step>
</Steps>

The harness the engine starts finds the `conciv` command first on its `PATH`: the engine links it at
`.conciv/bin/conciv`.
