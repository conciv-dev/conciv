A coding agent in your terminal cannot see your running app. So you leave the app to ask it something. Then you paste
the error, the markup or a screenshot back by hand. conciv removes that trip. The agent runs inside your app. It reads
the page you are on and edits the source that renders it.

This guide takes the shortest path:

1. Install conciv with one command.
2. Start your dev server.
3. Log in with the code your dev server prints.
4. Ask the agent about the page you are on.

## Installation

Run init in your app folder, the one with `package.json`:

```package-install
npx @conciv/cli@latest init
```

init asks what to set up and shows the plan. It writes nothing until you say yes. What init changes:

- It adds `@conciv/it` to your dev dependencies.
- It wires conciv into your bundler config.
- It adds a conciv section to `AGENTS.md`, so your agent knows the conciv commands. With Claude Code, `CLAUDE.md`
  gets it too.
- It installs the conciv plugin for Claude Code, when Claude Code is on your machine.
- It connects Claude Code, Codex, Gemini CLI and opencode, when it finds them, so the agent in your terminal can
  drive your open tabs.
- It adds the `@conciv/skills` docs pack, only if you check that box.

<Callout type="warn" title="Next.js with a src folder">
  init writes the two instrumentation files to the project root. Next.js reads them from the folder that holds your
  routes. If your routes live in `src/`, move both files there.
</Callout>

This is the config init writes. Your other plugins stay as they are:

```ts twoslash title="vite.config.ts" tab="Vite" tab-group="bundler"
import {defineConfig} from 'vite'
import react from '@vitejs/plugin-react'
import conciv from '@conciv/it/plugin/vite' // [!code ++]

export default defineConfig({
  plugins: [
    react(),
    conciv(), // [!code ++]
  ],
})
```

```ts twoslash title="next.config.ts" tab="Next.js" tab-group="bundler"
import type {NextConfig} from 'next'
import {withConciv} from '@conciv/it/plugin/nextjs' // [!code ++]

const nextConfig: NextConfig = {}

export default withConciv(nextConfig) // [!code ++]
```

```ts twoslash title="instrumentation.ts" tab="Next.js" tab-group="bundler"
export {register} from '@conciv/it/plugin/nextjs' // [!code ++]
```

```ts twoslash title="instrumentation-client.ts" tab="Next.js" tab-group="bundler"
import '@conciv/it/plugin/nextjs/widget' // [!code ++]
```

```js title="webpack.config.js" tab="webpack" tab-group="bundler"
const HtmlWebpackPlugin = require('html-webpack-plugin')
const conciv = require('@conciv/it/plugin/webpack') // [!code ++]

module.exports = {
  mode: 'development', // <- conciv runs only when the build is not for production
  plugins: [
    new HtmlWebpackPlugin(),
    conciv.default(), // [!code ++]
  ],
}
```

```js title="rspack.config.js" tab="Rspack" tab-group="bundler"
const {rspack} = require('@rspack/core')
const conciv = require('@conciv/it/plugin/rspack') // [!code ++]

module.exports = {
  mode: 'development', // <- conciv runs only when the build is not for production
  plugins: [
    new rspack.HtmlRspackPlugin(),
    conciv.default(), // [!code ++]
  ],
}
```

```ts twoslash title="vite.config.ts" tab="TanStack Start" tab-group="bundler"
import {defineConfig} from 'vite'
import {tanstackStart} from '@tanstack/react-start/plugin/vite'
import react from '@vitejs/plugin-react'
import conciv from '@conciv/it/plugin/vite' // [!code ++]

export default defineConfig({
  plugins: [
    tanstackStart(),
    react(),
    conciv(), // [!code ++]
  ],
})
```

Each bundler has its own page with the manual setup and its edge cases: [Vite](/docs/bundlers/vite),
[Next.js](/docs/bundlers/nextjs), [webpack](/docs/bundlers/webpack), [Rspack](/docs/bundlers/rspack) and
[TanStack Start](/docs/bundlers/tanstack-start).

<Accordions>
<Accordion id="stops" title="If init stops before it writes anything">

init checks your project first, and stops with one of these messages:

- `no package.json here: run init from your app directory`
- `uncommitted changes: commit first or pass --force`
- `Non-interactive terminal: re-run with --yes or --dry-run`

Pressing Ctrl-C while init runs puts your config back as it was. Every flag is in the
[CLI reference](/docs/reference/cli).

## Start your dev server

Start your dev server the way you always do. conciv starts with it. It adds a conciv button to the corner of every
page.

```bash title="Terminal"
npm run dev
```

A few things to notice:

- conciv runs in dev builds only. A production build leaves it out.
- The chat runs an agent CLI on your machine, `claude` by default. It must be on the `PATH` of the shell that starts
  your dev server, and logged in. See [Connect your agents](/docs/agents) for the others.

## Log in

The engine can read your project and run commands, so it answers only browsers you let in. Click the conciv button.
Your dev server prints a box with a 6-digit code:

```text title="Dev server terminal"
╭──────────────────────────────────────────────────────╮
│ conciv: a browser asks to connect to this engine     │
│ From:    Chrome 142 | macOS at http://localhost:5173 │
│ Code:    482913                                      │
│ Link:    http://localhost:5173/#conciv_otp=482913    │
│ Expires: 10:42:07                                    │
╰──────────────────────────────────────────────────────╯
```

Type the code in the panel, or open the link. You log in once per browser. Learn more in
[Logging in](/docs/usage/logging-in).

## Ask about the page

Open the panel and ask about the page you have open. The agent reads the rendered page first, then finds the file
that renders it.

```text title="Prompt"
What is on this page, and which file renders it?
```

A few things to notice:

- The crosshair beside the composer pins an element to your message, with its source file when conciv finds it.
- When the agent edits your source, your dev server reloads the page.
- A risky action shows a card first: Allow once, Allow always or Deny.
