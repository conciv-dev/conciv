A harness is the agent CLI that answers in the chat. conciv runs it on your machine, in your project folder, with your
own login, models and settings.

## Pick a harness

```ts twoslash title="vite.config.ts"
import {defineConfig} from 'vite'
import conciv from '@conciv/it/plugin/vite'

export default defineConfig({
  plugins: [
    conciv({
      harness: 'codex', // <- a new session starts with Codex; the default is claude
    }),
  ],
})
```

`harness` is one of `claude`, `codex`, `opencode`, `gemini-cli` or `pi`. The full comparison is at the [end of the
page](#what-each-one-can-do).

<Callout type="success" title="Use the CLI you already have">
  Each harness keeps its own login and settings, and conciv reuses them. Pick the one you already work with.
</Callout>

## Install and log in

conciv does not install the CLI or log you in. Do both first, in your own terminal. For Claude Code, run `claude`, log
in when it asks, then quit. conciv finds the CLI on the `PATH` of the process that started your dev server.

## Switch in a session

The model menu in the panel lists the harness you set. It also lists every other harness whose CLI is on your `PATH`.
Pick a model there to switch the session. Learn more in the [Sessions documentation](/docs/sessions#switching-harness).

## Set it for one run

`CONCIV_HARNESS` picks a harness without a config edit:

```bash title="Terminal"
CONCIV_HARNESS=opencode pnpm dev
```

`harness` in the config wins over the variable.

## Claude

conciv runs Claude Code in its `auto` permission mode. It adds ask rules for risky Bash commands, and those asks
become permission cards. conciv's instructions come after Claude Code's own system prompt. Claude gives you the most:
`/` commands, image attachments, permission cards and a **Terminal** tab.

## Codex

conciv runs Codex in the `workspace-write` sandbox, with `approvalPolicy: 'never'`. It never shows a permission card.
Its sandbox limits what it can touch instead.

## Gemini CLI

conciv runs Gemini CLI over ACP, as `gemini --acp -m <model>`. The default model is `gemini-3-pro-preview`. Its asks
show as permission cards.

## OpenCode

OpenCode chats in the panel. It can ask for permission, but its asks do not reach conciv yet. No card shows.

## Pi

Pi has no chat in conciv yet. Its past sessions still show in the session list. A turn with it ends with "pi is not
installed or not yet supported".
