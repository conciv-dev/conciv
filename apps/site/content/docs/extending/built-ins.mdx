Two built-ins show the public contracts at work: the whiteboard and test-runner plugins. Neither uses anything private, so they double as reference implementations.

## Whiteboard

[`@conciv/plugin-whiteboard`](https://github.com/conciv-dev/conciv/tree/main/packages/plugins/whiteboard)
is the [shared Excalidraw canvas](/docs/usage/whiteboard), a plugin like the test runner. It
demonstrates the heavyweight end of the contract:

- **Four tool groups** (`canvas`, `comment`, `anchor`, `element`) under the `whiteboard` namespace.
- **Plugin storage**: the board, its comments and pins live in the storage the engine keeps for
  the plugin, with a change feed every open canvas follows over the plugin's RPC.
- **Composer UI**: a "Whiteboard" pill above the composer opens the canvas over the page.
- **Session scoping**: every chat session gets its own room.

## Test runner

[`@conciv/plugin-test-runner`](https://github.com/conciv-dev/conciv/tree/main/packages/plugins/test-runner)
powers [live tests](/docs/usage/live-tests). Load it with
`plugins: [['@conciv/plugin-test-runner', {runner: 'playwright'}]]`. It shows the plugin patterns:

- **Options**: the `runner` option (vitest, jest, node-test, playwright) is parsed with zod in
  `setup`. Vitest is the default.
- **A runner registry**: adapters (Vitest, Playwright) behind one interface, picked from the option.
- **Tools**: `test_runner_run` and `test_runner_status` are direct tools the agent calls by name.
  `external_test_runner_list` stays in code mode.
- **Plugin RPC**: the Tests tab starts and stops runs over the plugin's RPC, and reads one `event`
  per live run step to stream rows.
- **The card**: the finished result renders in the thread as a test card.
- **A skill**: teaches the agent to list tests before it runs a vague request.

## Reading order

Start with the test runner's `src/index.ts` (about eighty lines end to end), then the whiteboard's
tool groups in `src/tools.ts` and `src/canvas-tools.ts`.
