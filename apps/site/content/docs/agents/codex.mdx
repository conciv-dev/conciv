[Codex](https://developers.openai.com/codex/cli) connects to conciv as an MCP server, and chats in the panel
inside its own sandbox.

## Basic

Run this once, in any folder:

```bash title="Terminal"
npx @conciv/cli mcp connect codex
```

It adds conciv's MCP server, named conciv-hub, to Codex. Under the hood it runs `codex mcp add`. On success it
prints:

```json title="Output"
{"ok": true, "data": {"connected": "codex"}}
```

With your dev server running and your app open, ask Codex in your terminal:

```text title="Prompt"
List my open conciv tabs. Then read the page in the first one and tell me what is on it.
```

Learn what it can call in the [Agents documentation](/docs/agents#what-a-connected-agent-gets).

## What conciv runs in the chat

When Codex is the session's harness, conciv runs the Codex CLI on your machine, in your project, with your own login:

```text title="What conciv passes Codex"
sandbox          workspace-write    <- Codex can write only inside your project
approval policy  never              <- Codex never asks, so no Permission card shows
model            your default       <- the model in your Codex config.toml, unless you pick one
```

The model menu lists the models in Codex's own model cache. A picked effort level reaches Codex as its reasoning
effort. Past Codex sessions in this project show in the session list.

## Disconnect

```bash title="Terminal"
npx @conciv/cli mcp disconnect codex
```

This stops conciv answering Codex, and removes `conciv-hub` from its config.

<Accordions type="single">
  <Accordion title="The chat says Codex is not logged in?">
    conciv checks the Codex login before a turn. Log in to Codex in a terminal, then send the message again.
  </Accordion>
  <Accordion title="Why does Codex never ask before it acts?">
    conciv runs it with the never approval policy. Its sandbox limits what it can touch instead. Pick Claude Code or
    Gemini CLI for a harness that asks with cards.
  </Accordion>
</Accordions>
