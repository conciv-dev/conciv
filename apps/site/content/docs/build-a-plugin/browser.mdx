title: Browser side
description: What a plugin's browser half can add to the widget, the stores it keeps, and the host APIs and ui kit on its context.

The browser half is the default export of `plugin-experimental.tsx`, made with `Plugin.define` from
`@conciv/plugin/experimental` and built with the [Vite preset](/docs/plugins/your-first-plugin#the-browser-half). It
has no id: the widget gives it the engine half's id as `ctx.id`. `setup` is synchronous and runs in a Solid owner.
Everything it adds goes away when the plugin reloads or stops.

```tsx
import {z} from 'zod'
import {createLatest, Panel, Plugin, Slot, Store} from '@conciv/plugin/experimental'
import {Tanstack} from './rpc.js'

export default Plugin.define({
  stores: {prefs: Store.global(z.object({open: z.boolean()}), {open: false})},
  setup(ctx) {
    const routes = createLatest(
      () => ctx.id,
      (_id, signal) => ctx.client.rpc(Tanstack).routes({}, {signal}),
    )
    ctx.add(Slot, {at: 'session.status', render: () => <span>{routes.latest?.routes.length ?? 0} routes</span>})
    ctx.add(Panel, {id: 'routes', region: 'pane', list: () => [{id: 'routes', title: 'Routes'}], render: () => <p />})
  },
})
```

`ctx.client.rpc(Contract)` calls the plugin's own engine half. `createLatest(key, load)` keeps the latest answer of a
load that reruns when `key` changes.

### Composer pills

`show` runs for each open composer and returns the pill, or `undefined` for none. With `run` the pill is a button;
with `rows` it opens a menu; with `menu` it opens a popover you render. `order` sorts pills, lowest first.

```ts
ctx.add(ComposerPill, {
  id: 'checks',
  order: 1,
  show: () => ({
    label: 'Checks',
    title: 'Checks pill',
    icon: 'list-checks',
    tone: 'success',
    rows: [
      {
        label: 'Run the checks',
        detail: '3 left',
        icon: 'terminal',
        run: () => ctx.toast.show({title: 'Checks started'}),
      },
      {label: 'Locked check', icon: 'lock'},
    ],
  }),
})
```

A row without `run` is shown disabled. `tone` is `success`, `warning` or `danger`.

### Settings pages

```ts
ctx.add(SettingsPage, {id: 'prefs', title: 'Alpha prefs', render: () => <p>Alpha prefs body</p>})
ctx.add(SettingsPage, {id: 'block', page: 'general', title: 'Block', render: () => <p>Alpha section on general</p>})
```

The first is a tab under **Settings** of its own. The second joins the General page as a section.

## Stores

Declare stores in `stores`; read and write them on `ctx.stores`. A store's schema is any Standard Schema with an object
output, and its second argument is the initial value.

<TypeTable
  type={{
    'Store.global(schema, initial)': {
      required: true,
      type: 'store',
      description: 'One value, not tied to a project or a session.',
    },
    'Store.project(schema, initial)': {
      required: true,
      type: 'store',
      description: 'One value for the project, kept with its project settings.',
    },
    'Store.session(schema, initial)': {required: true, type: 'store', description: 'One value per session.'},
  }}
/>

```ts
ctx.stores.note.set({text: 'saved note'})
ctx.stores.visits.update((draft) => {
  draft.count += 1
})
```

`value` reads the current value. A stored value that fails the schema keeps its valid fields; each failing field
takes the initial value.

```ts
ctx.dialogs.open(() => <ctx.ui.Dialog title="Fixture dialog">The dialog body</ctx.ui.Dialog>)
ctx.layout.open('fixture:opened', props.session)
ctx.system.save({name: 'fixture-note.txt', content: 'saved through the host'})
```

Use `ctx.ui` for every button, menu and dialog: a plugin never imports conciv's UI kit, and the build refuses it.
