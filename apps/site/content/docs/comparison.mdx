A coding agent in your terminal, such as Claude Code or Codex, edits your source but cannot see your app. MCP browser
tools, such as Playwright MCP or Chrome DevTools MCP, give an agent a browser to drive. A browser-extension agent, such
as Claude in Chrome, reads and clicks web pages from an extension you install in your browser. conciv puts the agent
inside your running app, in the tab you already have open, and ties what it sees to your source. It needs no browser
extension: your dev server adds the widget to your pages, and the agent reaches the tab through it.

The four are not rivals. conciv runs your terminal agent's own CLI. It can also connect that agent to your open tabs.

MCP browser tools reach your open tab only if you start them attached to your own browser. conciv names an element's
source file when it can find it. It reads the dev server's module graph on Vite only. The widget is tested in Chromium
and Firefox. Playwright MCP also drives Firefox and WebKit. Claude in Chrome runs in Google Chrome only.
Playwright MCP can save a trace of the steps the agent takes, not of yours. Claude in Chrome can record a workflow you click through, in its classic side panel, so it can repeat it.

### Changing the code

| Feature                                                   | conciv  | Terminal agent | MCP browser tools | Browser extension |
| --------------------------------------------------------- | :-----: | :------------: | :---------------: | :---------------: |
| Edits your source                                         | <Yes /> |    <Yes />     |      <No />       |      <No />       |
| [Checks its change in the page](/docs/usage/page-control) | <Yes /> |     <No />     |    <Partly />     |    <Partly />     |

| [Asks before risky actions](/docs/usage/approvals)        | <Yes /> |    <Yes />     |    <Partly />     |      <Yes />      |

conciv edits your source through your own agent CLI. MCP browser tools edit nothing themselves: the agent that calls
them does, and that agent can check its change in a page when it pairs them. A browser-extension agent works on the
page, not your files; paired with a terminal agent, it tests what that agent built. conciv runs your tests with the
test runner plugin, and asks as a card in the page. A terminal agent asks in the terminal. Claude in Chrome asks
before each action, per site, or checks each action itself, by the mode you pick.

MCP browser tools are not an agent, so they have no CLI or login of their own. A browser-extension agent brings its
own model and account: Claude in Chrome needs a paid Claude plan. conciv works with Vite, Next.js, webpack and Rspack.
It takes your own tools as plugins; a terminal agent takes them through MCP. conciv gives your terminal agent your
open tabs through MCP. MCP browser tools give it a browser of their own to drive, and Claude in Chrome can work with
Claude Code.

## Where each one fits

- **A terminal agent** is the right tool for work away from the page: refactors, scripts, backend code.
- **MCP browser tools** fit a page you do not build, a production site, or deep browser data. Chrome DevTools MCP
  centres on performance traces, network requests and the console. Playwright MCP drives pages through accessibility
  snapshots.
- **A browser-extension agent** fits tasks on sites you do not build, with your logins: internal tools, admin
  consoles, forms.
- **conciv** fits work on your own app while it runs: point at it, change it, see it.

## Honest limits

- conciv runs in development builds only. It is not for production sites.
- It needs a supported bundler. Rollup and esbuild do nothing yet.
- On webpack and Rspack, the agent cannot read the dev server's module graph.
- It needs Node 26 or newer, and an agent CLI you install and log in to yourself.
- The Pi CLI has no chat in conciv yet.
- The iOS setup is an early alpha, for the simulator only.
