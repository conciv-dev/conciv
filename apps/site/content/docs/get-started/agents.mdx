---
title: Connect your agent
description: Let the coding agent in your own terminal see and drive your open conciv tabs.
---

The chat in the panel runs its own harness. Your own terminal agent, such as Claude Code or Codex in another window,
is separate. Connect it to conciv and it can find your open conciv tabs and use the same tools the chat uses.

`conciv init` does this for you. You can also do it by hand.

`.conciv/bin/conciv` is put in place by the dev server when it starts, so the agent's commands work while your dev
server runs.

The Claude Code plugin's bridge reads the engine's address from `.conciv/mcp-endpoint.json`, which the engine writes
when it starts. If the plugin install fails, init prints the commands to run yourself:

```bash
claude plugin marketplace add .conciv/claude-connect
claude plugin install conciv-connect@conciv --scope local
claude plugin update conciv-connect@conciv --scope local
```

## Connect by hand

`conciv mcp connect` adds `conciv-hub` to that agent's MCP config. It takes `claude`, `codex`, `gemini-cli` or
`opencode`.

```bash
npx @conciv/cli@latest mcp connect claude
```

```text title="output"
{"ok":true,"data":{"connected":"claude"}}
```


## In the panel

The panel shows the same connections: a **Connected agents** row above the composer with one chip per agent, each
with a **Disconnect** button. The composer's **Connect agents** button has a **Connect** entry for each agent CLI you
have that is not connected yet, such as **Connect Codex**. On a narrow composer the same entries are in **More composer
actions**.

## Letting an agent in

By default a connected agent can use any open tab with no question. Set `hubAccess` to have each tab, or the project,
ask first. See [Approvals](/docs/what-you-get/approvals#outside-agents).
