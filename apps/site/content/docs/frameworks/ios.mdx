<Callout type="warn">
  Early alpha: the bridge protocol and the Swift API can change without notice. The iOS simulator is the only supported
  target. Use the SwiftPM version that matches your `@conciv/*` npm version.
</Callout>

conciv drives a native iOS app the way it drives a web page. The Swift SDK floats a transparent overlay and the
conciv button over your own UI, and loads the widget from the engine your dev server runs. Your web dev server needs
conciv in its config, as on the [Vite](/docs/frameworks/vite) page.

## Install

Add the SwiftPM mirror to your app. In `Package.swift`:

```swift title="Package.swift"
.package(url: "https://github.com/conciv-dev/conciv-swift.git", from: "0.0.1")
```

Then add the product to the target that shows your UI:

```swift title="Package.swift"
.product(name: "ConcivWidget", package: "conciv-swift")
```

In an Xcode project, use File > Add Package Dependencies and paste the same URL. The package needs iOS 17.

## Add it

Call `ConcivWidget.attach()` once, from your scene delegate or your SwiftUI `App` init. It finds the key window itself.

```swift title="App.swift"
import ConcivWidget

ConcivWidget.attach()
```

## Run it

Start your dev server, then launch a Debug build of the app in the simulator. The overlay and the conciv button
appear over your UI.

The app finds the engine in this order:

<Steps>
  <Step>
    `CONCIV_URL` in the app's environment: the engine's address with no `/native` at the end, for example
    `http://127.0.0.1:4599`. The SDK adds `/native` itself.
  </Step>
  <Step>
    `~/.conciv/dev-endpoint.json`, which the engine writes when it starts, if its address answers `GET /health`.
  </Step>
  <Step>`http://127.0.0.1` on ports 4599, 8787 and 3000, the first that answers as a conciv engine.</Step>
</Steps>

The demo app lives in [`native/swift`](https://github.com/conciv-dev/conciv/tree/main/native/swift).

## If it does not show up

- **You ran a Release build.** `attach()` does nothing in a Release build: no overlay, no web view, no engine address.
- **The app cannot find the engine.** Set `CONCIV_URL` in the scheme's environment, or give the engine a fixed
  `port: 4599` in your dev server's conciv options.
- **Your config sets `devEndpointDir`.** The engine writes `dev-endpoint.json` elsewhere, and the SDK reads only
  `~/.conciv/dev-endpoint.json`. Set `CONCIV_URL`.
- **The panel says it couldn't reach the engine.** See [Troubleshooting](/docs/reference/troubleshooting#in-the-panel).
